## 1. 本次目标

把“八层同一套探索、终端、扣血和传送流程”改造成八种能够被玩家描述出来的冒险章节：

> 八层共享同一套 SQL 学习内核，但每层拥有不同的核心动词、地图结构、世界反应、Boss 规则和情绪节奏。

需要解决：

1. 玩家不再把新楼层理解成换色迷宫；
2. SQL 不再永远等同于攻击；
3. 地图内容不依赖扩大尺寸和增加赶路；
4. 捷径连接值得返回的事件，而不只是缩短距离；
5. 抄写员通过行动推进关系，不再只是篝火菜单中的复盘文案；
6. 每层回答一个剧情问题，同时自然提出下一层的问题；
7. 第八层停止重复普通探索，转入真正的终局事故。

## 4. 当前基线与体验缺口

### 4.1 `CURRENT`

- 八层 47 组课程可从第一层运行至唯一 `MIGRATE` 结局；
- 新 Run 使用 `48×36 / generator-v5`；
- 每层有三个前、中、后区域；
- 出生区是安全与兜底复活锚点，中段和后段各有一处实体篝火；
- 每层当前有一条确定钥匙控制的永久双向捷径；
- 每层有五个短叙事拍和两条必然证据；
- 抄写员当前在每个篝火旁出现，并在篝火菜单中复盘；
- 地图、人物和装饰主要由程序化几何图元表现；
- 音乐当前由 Web Audio 程序化合成。

### 4.2 已被玩家实测否决的表现

- 八层主要循环仍是“走路 → 遇怪 → 写 SQL → 扣血 → 下一处”；
- 区域差异主要依赖颜色、少量图标和文字标签；
- 剧情以短暂卡片和菜单文本为主，地图与人物没有足够行动和后果；
- 捷径技术上可用，但旧区域缺少值得返回的目标；
- 抄写员与篝火职责重叠，人物存在感不足；
- 当前合成音乐的音色、响度和连续性未通过主观验收。

因此后续不能以“已有八层参数、叙事文本或音频调度”为质量完成证据。

### 4.3 本轮不处理的课程漂移

当前可玩顺序保持：

| 层 | 当前运行课程 |
|---:|---|
| 1 | `SELECT / WHERE / IS NULL / GROUP BY / HAVING` |
| 2 | `ORDER BY / LIMIT / DISTINCT / INNER JOIN / LEFT JOIN / 综合 JOIN` |
| 3 | JOIN 深化、自连接、三表连接、`UNION`、连接审计 |
| 4 | 标量、`IN`、`EXISTS`、相关子查询、CTE、递归 CTE |
| 5 | `OVER`、排名、前后行、Frame、分组 Top-N |
| 6 | 写操作、约束、事务、保存点 |
| 7 | B+ 树、联合 / 覆盖索引、索引失效、执行计划、优化 |
| 8 | MVCC、锁、隔离、建模、复制、分片、安全与五阶段事故 |

“第一层纯单表、第二层聚合、第三层连接”的长期蓝图标记为
`DEFERRED_CURRICULUM_MIGRATION`，不得在本次体验实现中暗中调整。

## 5. 八层反重复原则

### 5.1 一套内核，八种章节

代码层目标：

- 约 70% 共用：移动、交互、SQL 编辑器、SQLite、判题、战斗、存档、图鉴、背包和篝火；
- 约 20% 楼层专用：交通、环境状态、非战斗结果与 Boss 阶段；
- 约 10% 一次性惊喜：回访事件、场景演出或特殊调查。

玩家感知目标：

- 每层至少 40% 的行动或反馈与上一层不同；
- 隐藏 HUD 后仍能通过地貌、交通、场景行为和地标认出楼层；
- 玩家能用一个动词概括本层，而不是只能说“题目更难”。

### 5.2 共享操作，不共享结果

继续只使用现有核心操作：

```text
移动
E 交互
Q + S 打开 SQL
B 背包
ESC 返回
```

不为每层增加新按键。差异来自 `E` 和 SQL 的结果：

| SQL 世界行为 | 世界反馈 |
|---|---|
| 查询 / 识别 | 恢复名字、弱点、身份或位置 |
| 筛选 / 判断 | 选中正确目标、路线、开关或证据 |
| 聚合 / 比较 | 改变仪表、水位、群体状态或优先级 |
| 连接 / 关联 | 连接人物、岛屿、房间、装备或信号 |
| 追踪 / 递归 | 点亮能源链、关系链或路径 |
| 排名 / 时序 | 预测换岗、选择目标或绕开战斗 |
| 写入 / 事务 | 在隔离副本中预览、提交或回滚变化 |
| 计划 / 优化 | 比较访问路径并打开视觉短路 |
| 事故诊断 | 组合证据、确定处理顺序和最终迁移方案 |

### 5.3 每层体验 DNA

每层必须填写并实现：

1. 一个核心玩家动词；
2. 一个独有宏观拓扑；
3. 一种独有移动或交通；
4. 一次 SQL 直接改变环境；
5. 一个非战斗解决方案；
6. 一次必然场景事件；
7. 一个有明确返回理由的捷径；
8. 一个不能只靠加 HP 复制的 Boss；
9. 抄写员的一次行动；
10. 一个本层答案和下一层问题。

缺少任意三项，不得称为完成楼层差异化。

## 6. 疲劳与节奏预算

硬规则：

- 不允许连续出现三场同类型战斗；
- 两次必修战斗后，必须穿插调查、交通、机关、人物或奖励；
- 每层至少一次 SQL 正确结果直接改变环境；
- 每层至少一个事件可以不通过击杀解决；
- 每层至少一个非敌对异常生物或 NPC；
- 连续只有移动、没有新目标、景观、预告或互动的时段目标不超过 15 秒；
- 主线相邻目标继续遵守当前不超过 18 个步行格的边界；
- 随机遭遇只复习，不承担新机制和主线剧情；
- Boss 阶段不能要求重复完全相同的正确查询；
- 第八层不再生成普通“清图式”主线流程。

推荐楼层节奏：

```text
入层异常
→ 教学 / 调查
→ 一场短战斗
→ 独有交通或机关
→ 第二场变式战斗
→ 环境状态改变
→ 捷径回访
→ 抄写员行动与证据整理
→ 区域首领或非战斗挑战
→ 楼层 Boss
→ 回答本层问题并上升
```

## 8. 八张楼层体验卡

### 8.1 第一层：地下余烬档案

**核心问题**

> 当前登记册中没有玩家，为什么篝火仍能恢复玩家？

**地图结构**

```text
出生安全区 / 无名村与登记厅
→ 排水渠与水车
→ 史莱姆池
→ 余烬仓库 / 中段篝火
→ 地下档案室
→ Boss 门前 / 后段篝火
→ 登记官大厅

仓库背面铁门 ──回到──> 登记厅
```

当前只保留一条正式捷径；货梯可以作为区域交通或演出，不在本文偷偷增加第二把捷径钥匙。

**SQL 世界行为**

- `SELECT / WHERE`：读取门牌、怪物和水闸控制记录；
- `IS NULL`：确认被擦除姓名的居民；
- `GROUP BY / HAVING`：证明多份恢复回执都指向玩家；
- 正确结果启动水轮、降低水位、露出档案道路；
- 第一只怪击败后将 `ID` 恢复成直白名字并进入怪物图鉴。

**非战斗事件**

玩家首次接近登记碑：

```text
CURRENT RECORD：0 ROWS
RESTORE PERMISSION：VALID
```

**回访**

从仓库背面打开出生时看见的铁门。回到登记厅后：

- 原本空荡的村庄出现无名居民轮廓；
- 抄写员离开书桌，第一次走到大厅门前；
- 大厅音乐和灯光变化；
- 登记官从原本封闭的大厅苏醒。

**Boss**

Boss 不是“更厚的史莱姆”。登记官尝试以当前居民记录定位玩家，得到 0 行，却无法撤销玩家的
恢复权限。战斗阶段围绕“记录、空值、分组证据”逐步解除它的排除规则。

**抄写员行动**

她原本坚持“没有记录就不能登记”，结尾主动用自己的纸替玩家建立《失名录》第一页。

**本层答案**

> 玩家不属于当前居民表，但属于一段仍可恢复的历史。

**下一层问题**

> 那段历史中到底有几个名字？

**不重复保证**

- 本层允许最传统的步行与查询战，作为系统教学；
- 第二层必须立即改变移动方式和空间结构。

### 8.2 第二层：潮汐群岛

**核心问题**

> 多个旧名字共享同一条恢复轨迹，它们是重复记录，还是不同的人？

**地图结构**

```text
潮汐码头
├─ 白沙浅滩
├─ 芦苇湖与沼泽
├─ 沉水村落
├─ 沉船区
└─ 灯塔岛 / 中央船闸
```

地图采用紧凑岛屿和短船程，不扩大成开放海洋。船只是一种可控交通和转场，不实现真实浮力。

**SQL 世界行为**

- `ORDER BY / LIMIT`：找到最强或最近的灯塔信号；
- `DISTINCT`：证明信号里存在多个不同名字；
- `INNER JOIN`：连接名字、岛屿与房间；
- `LEFT JOIN / IS NULL`：找到有信号却没有身体或住所的记录；
- 正确结果点亮浮标、校准航向或开放靠岸点。

**非战斗事件**

玩家在浅海看见水下屋顶、钟楼和移动的巨大影子。查询港口日志可以选择绕开影子，或前往调查，
不要求每次发现都进入战斗。

**回访**

击败沼泽区域首领后水位下降，中央船闸打开，形成返回码头的短航线。回到码头后：

- 七盏浮标依次亮起；
- 水面出现七道人形倒影；
- 抄写员在旧页上发现一份相似笔迹；
- 湖中可选大怪或新证据出现。

**Boss**

区域 Boss“湖兽”负责改变水位；楼层 Boss“塔卫”试图按出现次数只保留一个名字。玩家需要证明
这些名字来自不同地点，不能被简单聚合覆盖。

**抄写员行动**

她乘实体升降机抵达码头，在固定记录台工作；她不是每个篝火旁的复制体。

**本层答案**

> 这些名字不是同一条记录的简单重复，而是多个不同来源留下的共同恢复轨迹。

**下一层问题**

> 它们之间是什么关系，又曾经属于谁？

**不重复保证**

- 船、岛屿和潮汐替代第一层连续地下步行；
- 至少一个主要目标允许通过查询航线避战。

### 8.3 第三层：白霜墓原

**核心动词**：侦查、对照、还原关系。

**独有机制**

- 白昼状态只看见墓碑、足迹、装备和冻结建筑；
- 幽灵状态看见死者、主人关系和过去路径；
- 状态切换由固定调查点触发，不随机、不消耗道具；
- `SELF JOIN`、三表链和 `UNION` 让两种状态中的信息合并。

**回访**

打开墓门返回前庭后，早先孤立的墓碑出现人物轮廓和关系线，守墓人的位置与台词改变。

**Boss**

错误连接形成的“关系树”。每个阶段要求识别一类错误关系；正确后断开一段树枝，而不是重复扣同一
血条。

**抄写员行动**

她第一次无法立即解释证据，主动请求守墓人保留互相冲突的记录，而不是选择一条覆盖其余内容。

**本层答案**

> 多个旧名字之间存在真实关系，不能只按相同恢复轨迹合并成一个人。

**不重复保证**

- 不使用船与水位；
- 普通幽灵中至少一半先调查、后决定是否战斗。

### 8.4 第四层：元素升炉

**核心动词**：追踪、接线、断路。

**独有机制**

- 火、冰、雷三条能源链连接源头、中继、管道和核心；
- 子查询用于确定依赖来源；
- CTE 命名中间状态；
- 递归 CTE 沿链路逐段点亮；
- 正确查询改变管道、升降机和炉区的可见状态。

**回访**

修复维护升降机后回到中央控制室，三条能源链以新的状态同时出现，早先无法解释的异常命令来源
显现。

**Boss**

先切断三条错误回路，再暴露元素核心。Boss 难度来自依赖结构，而不是持续增加 HP。

**抄写员行动**

她在命令日志中认出一段被故意隐藏的档案官签名，但暂时没有告诉玩家全部内容。

**本层答案**

> 多个地区异常并非独立事故，而是来自同一条仍在传播的历史命令。

**不重复保证**

- 不使用第三层双状态调查；
- 本层至少一半 SQL 用于机关和能源，而不是怪物攻击。

### 8.5 第五层：黑铁外城

**核心动词**：潜入、观察时序、绕开战斗。

**独有机制**

- 城墙、兵营与内城形成三个警戒分区；
- 守卫按固定可查询时序巡逻；
- 窗口函数揭示分区排名、前后岗次、并列和累计警戒；
- 正确查询可以选择第二弱守卫、关闭警戒或从换岗空档通过；
- 没有实时思考倒计时，终端打开时世界继续遵守暂停边界。

**回访**

放下吊桥回到城门后，城防队列根据玩家已经破坏的岗位重新排序，旧路线出现新的安全窗口。

**Boss**

Boss 是动态城防序列。玩家需要处理分区、顺序、前后行和 Top-N，不能靠同一条查询反复攻击。

**抄写员行动**

她第一次反对玩家立即公开全部历史证据，因为错误的公开顺序可能让无名居民受到清除。

**本层答案**

> 正确的事实仍可能因排序、优先级和公开时机不同而伤害不同的人。

**不重复保证**

- 正确 SQL 至少可以跳过两场普通战斗；
- 不复用元素机关和关系树结构。

### 8.6 第六层：龙脊上城

**核心动词**：预演、修改、回滚、承担后果。

**独有机制**

- 所有写操作只发生在一次性沙箱；
- 桥梁、龙蛋、洞穴和守卫状态显示修改前后；
- 错误更新可以造成可见破坏，但 `ROLLBACK` 恢复沙箱；
- `SAVEPOINT` 允许局部撤销；
- 只有通过验证的提交结果才映射成剧情旗标，永久课程数据不被污染。

**回访**

返回事务工坊时并排看见“原始状态”和“候选状态”，玩家必须先验证再提交。

**Boss**

龙王阶段要求在约束错误后安全恢复，完成局部回滚并验证最终状态。失败教会恢复，而不是只造成生命
惩罚。

**抄写员行动**

她倾向完全回滚；玩家通过可验证沙箱证明还有安全迁移的第三条路。两人第一次产生明确立场冲突。

**本层答案**

> 玩家来自未完成的历史撤销，但恢复过去并不必然比保存现在更正确。

**不重复保证**

- 不以潜行或巡逻为主；
- 本层的主要世界变化必须可撤销并清楚标记为沙箱。

### 8.7 第七层：残照索引王苑

**核心动词**：比较路径、选择、验证。

**独有机制**

- 同一目标同时展示扫描路与索引路；
- 计划节点沿巨树根系逐段点亮；
- 合理索引打开视觉短路，但较差路径仍可达；
- 评分使用稳定计划证据，不以设备毫秒数作为唯一标准；
- 不加入反应速度倒计时。

**回访**

晶体短路把玩家送回主园。早先看似无意义的长路变成一次完整扫描的空间解释，而不是再次要求玩家
重走。

**Boss**

索引古树要求记录基线、选择索引、必要时改写查询，再用执行计划证明改善。Boss 不因“索引越多”
自动受伤。

**抄写员行动**

她公开此前隐瞒的签名，并承认自己保存记录的方式也可能让某些历史永远无法被访问。

**本层答案**

> 记录存在不代表能够被找到；访问路径本身也体现权力与取舍。

**不重复保证**

- 不用沙箱写入改变永久世界；
- 大幅减少普通怪，增加安静观察和计划对照。

### 8.8 第八层：黑金高堂

**核心动词**：诊断、排序事故、迁移。

**独有机制**

- 取消普通清图式主线；
- 七个知识翼作为可重复检查的事故证据站；
- 中央长阶固定，Seed 只改变非关键侧室；
- 前七层获得的名字、证据和空间记忆进入最终调查；
- 五阶段 Boss 允许阶段保存，但每阶段独立通过。

**回访**

第八层不再新建普通钥匙捷径作为主要卖点。七翼完成后金色拱门直接回到中央长阶，意义是汇总证据，
不是继续赶路。

**Boss**

最后的档案官与五阶段事故：

1. 综合查询恢复事实；
2. 执行计划定位负载；
3. 并发时间线判断可见性与锁；
4. 建模、复制、分片与安全取舍；
5. 执行可验证、可回滚的 `MIGRATE`。

**抄写员行动**

她不再替玩家总结答案，只负责确认每项证据来源，把最终写权限决定交给玩家。

**本层答案**

> 玩家不是某个唯一旧版本，而是多次删除、覆盖、失败和修正共同留下的历史集合。

**不重复保证**

- 无普通楼层 Boss 前刷怪；
- 无新随机关键证据；
- 无第二结局和隐藏必修答案。

## 9. 抄写员四阶段人物弧

角色与篝火的目标分工：

| 对象 | 目标职责 |
|---|---|
| 篝火 | 回血、复活点、安全区、整理装备、原始答题记录 |
| 抄写员 | 当前调查问题、证据解释、名字恢复、图鉴、《失名录》和人物关系 |

角色分工方向为 `CONFIRMED`；“每层唯一实体、随剧情移动”的具体运行方式仍是 `PROPOSED`，需要在
后续角色契约和实现计划中批准。

| 阶段 | 楼层 | 关系变化 | 可见行动 |
|---|---|---|---|
| 建立信任 | 1–2 | 她从相信登记制度，转向替无记录者保留证据 | 为玩家建档；乘升降机同行 |
| 产生怀疑 | 3–4 | 她发现冲突记录与档案官签名 | 请求保留冲突；第一次隐瞒部分事实 |
| 正面冲突 | 5–6 | 她担心玩家取得写权限后重演事故 | 反对错误公开顺序；主张回滚并接受沙箱验证 |
| 共同决定 | 7–8 | 她承认保存与访问都包含取舍 | 公开证据；交出最终决定但保留审计责任 |

目标表现硬规则（具体实体数量、移动方式和旧存档迁移仍受 `E-06` 的后续批准约束）：

- 不再把“在每个篝火旁复制同一个人物”作为目标方案；
- 不让她代答 SQL；
- 不用长篇旁白代替人物行动；
- 每层最多一个核心人物变化；
- 她的温暖通过“记得、诚实、等待”兑现，不滑向万能保姆或无条件赞美。

## 11. 地图与素材生产方向

### 11.1 地图不是色块

每个区域的物件只允许承担三类职责：

1. 导航：地标、道路边界、远景轮廓；
2. 交互：机关、交通、可调查证据；
3. 叙事：居民生活痕迹、事故后果、怪物生态。

随机小方块、无法解释的线条和仅用于填空的图标不得作为区域差异的主要证据。

### 11.2 视觉层级

保留俯视 3/4 玩法，借鉴童话横版冒险的环境层次，不复制商业游戏素材：

```text
远景 / 地区剪影
→ 基础地形
→ 岸线、墙顶与高低差
→ 可交互物与角色
→ 前景树冠、桥梁或建筑遮挡
→ 低密度天气、水面与灯光动画
```

### 11.3 外部素材候选边界

以下只作为后续授权审查候选，不进入本轮运行时：

- [`Puny World`](https://merchant-shade.itch.io/16x16-puny-world)：16×16 地表、河流、海水和建筑的主地形候选；
- [`Scallywag – Water and Islands`](https://foozlecc.itch.io/scallywag-water-islands)：第二层海岸、岛屿和水面动画候选；
- [`16×16 DungeonTileset II`](https://0x72.itch.io/dungeontileset-ii)：第一层档案库和地牢环境候选；
- [`Ninja Adventure`](https://pixel-boy.itch.io/ninja-adventure-asset-pack)：角色、怪物与 VFX 动作参考候选；
- [`Kenney Tiny Town`](https://kenney.nl/assets/tiny-town) /
  [`Tiny Dungeon`](https://kenney.nl/assets/tiny-dungeon)：低风险原型占位候选。

后续接入必须：

- 逐文件确认许可证，不把“免费下载”等同于可改编；
- 保存来源 URL、作者、许可证快照、下载日期与 SHA-256；
- 更新 `ATTRIBUTIONS.md`；
- 固定 16×16 世界网格、整数倍缩放和统一光照方向；
- 选择一套主色板，其他素材必须重配色、重描边或重新组合；
- 只打包实际使用的图集，按楼层延迟加载；
- 禁止使用《冒险岛》《死亡细胞》或其他商业游戏拆包素材。

## 12. 音频方向边界

`CURRENT`：程序化 Web Audio 合成仍是当前运行事实。

`CONFIRMED`：当前合成音色、连续性和响度未通过玩家主观验收，不得继续以“已接入”作为完成证据。

`PROPOSED`：

- 探索真实公版古典录音，而不是继续依赖蜂鸣感较强的合成长音；
- 作曲作品公版不等于现代录音公版，录音必须逐文件确认 `CC0` 或可靠的全球公版标记；
- 第一、二层先选探索、战斗和 Boss 所需的最小曲目；
- 按楼层延迟加载压缩音频，不一次解码八层曲库；
- SQL 终端打开时降低音乐而不是停止；
- 合成音保留给短 SFX 或无录音时的降级回退；
- 正式曲目、响度、循环点与许可证另立音频计划，不由本文冻结。

## 13. 实施顺序与 Checkpoint

本文批准的是设计，不是以下代码实施。每个阶段仍需独立目标、范围、验收和发布权限。

### 阶段 A：第一、二层灰盒验证

- 第一层登记厅—排水渠—档案室；
- 第二层码头—浅滩—灯塔岛；
- 验证拓扑、交通、回访和连续 15 秒内容密度；
- 不先制作八层完整素材。

Checkpoint：

- 玩家能在无小地图提示下说出当前位置与返回目标；
- SQL 至少一次改变水位或灯塔；
- 玩家能区分篝火和抄写员；
- 捷径开启后自然发生回访。

### 阶段 B：第一、二层正式垂直切片

- 正式 Tile / Sprite / 环境动画；
- 剧情事件、名字恢复、图鉴与击杀反馈；
- 经许可的音频样板；
- 浏览器、窄屏、iframe、30 FPS 与 Reduced Motion 验收。

Checkpoint：

- 第一层完整回答“0 行但可恢复”；
- 第二层完整回答“多个名字不是简单重复”；
- 两层不用文字标签也能辨认；
- 体验不依赖扩大地图和随机关键内容。

### 阶段 C：第三至五层

- 第三层关系调查；
- 第四层能源网络；
- 第五层时序潜入；
- 每层复用同一编辑器，但拥有不同世界结果。

### 阶段 D：第六、七层

- 事务沙箱的可撤销世界状态；
- 执行计划的路径对照；
- 严格保护永久数据和 SQLite 证据边界。

### 阶段 E：第八层与全局收口

- 七翼证据站与五阶段最终事故；
- 前七层证据回收；
- `MIGRATE` 结局；
- 全局疲劳、音频、包体、无障碍和完整 Run 验收。

## 14. 验收标准

### 14.1 八层差异

- 玩家隐藏 HUD 后，可以从截图识别八层；
- 玩家可以用不同动词概括每层；
- 每层至少一个 SQL 结果直接改变环境；
- 每层至少一个非战斗解决方案；
- 每层至少一次人物行动和一次回访后状态变化；
- 每个 Boss 验证本层独有动词，不能只增加 HP；
- 第八层不重复普通楼层清图结构。

### 14.2 剧情

- 第一层结束后，玩家知道“无当前记录但有恢复权限”；
- 第二层结束后，玩家知道“多个不同名字共享恢复轨迹”；
- 每层回答一个问题并提出一个新问题；
- 关键真相不依赖随机掉落和可错过死路；
- 文字卡数量不作为剧情完成证据；
- 抄写员与篝火的职责可以被试玩者分别描述。

### 14.3 节奏

- 不连续出现三场同类型战斗；
- 两次战斗之间存在非战斗节拍；
- 连续纯移动目标不超过约 15 秒；
- 随机遭遇不引入新语法；
- 捷径在开启后 2–3 分钟内产生可见价值；
- 单层时长来自学习、调查和事件，不来自重复赶路。

### 14.4 工程与非功能

- 保留离线、博客 iframe、本地 SQLite、确定 Seed 和现有读写安全边界；
- 初始页面不一次加载八层全部专用素材与音频；
- 目标 30 FPS，页面隐藏后暂停，Reduced Motion 保留完整状态语义；
- 第三方素材和录音逐项通过许可证检查；
- 旧 `generator-v4` 只作为兼容路径，不成为新地图设计依据；
- 不能用单测和构建成功替代真人完整 Run 与主观音频验收。

## 15. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 八层各加一套小游戏导致维护爆炸 | 共享操作和状态机，每层只增加一个主要机制与一个一次性惊喜 |
| 玩法隐喻误教 SQL | 终端继续显示完整任务、字段、结果和错误；世界反馈不能替代真实证据 |
| 地图更加精致但仍然空洞 | 验收状态变化、回访目标和人物行动，不只验收截图 |
| 公共素材形成拼盘感 | 一套主网格与色板，其他素材重配色、重描边，只保留独特地标 |
| 真实录音扩大包体 | 每层延迟加载少量压缩循环，不一次打包解码全部音乐 |
| 抄写员独立后增加剧情状态 | 第一、二层只做固定据点与少量移动，不做自由寻路和分支对话 |
| 课程长期重排与本轮体验冲突 | 锁定当前 47 组课程，课程迁移另立版本 |
| 捷径为剧情服务后绕过课程 | 回访只改变已完成区域，不能跳过必修依赖和 Boss 门 |
| 第五层潜入变成实时压力 | 终端打开继续暂停，不设置思考倒计时 |
| 第六层世界写入破坏存档 | 所有练习在一次性沙箱，永久变化只来自验证后的剧情旗标 |

## 16. 停止与返工条件

出现任一情况，应停止继续铺后续楼层并返工当前切片：

- 第一、二层仍主要靠颜色和文字标签区分；
- 玩家无法解释为什么打开捷径后要返回；
- 玩家仍认为抄写员就是篝火菜单；
- SQL 正确结果仍然只表现为伤害数字；
- 新机制需要额外三组以上操作键；
- 新素材未经许可证记录进入 `src/`；
- 为增加内容而扩大地图或增加无目标走路；
- 第一、二层未通过完整试玩就批量制作第三至八层；
- 性能、窄屏或 SQL 可读性因视觉升级明显退化。
