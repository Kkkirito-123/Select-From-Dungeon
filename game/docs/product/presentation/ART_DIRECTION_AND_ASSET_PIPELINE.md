## 1. 目标、用户与制作边界

### 1.1 本次目标

制作两层能够在关闭 HUD 后被立即辨认的正式垂直切片：

- 第一层像一座潮湿、仍在错误运转、但留有唯一暖火的地下档案设施；
- 第二层像一片真正开阔、可以短航、会退潮、拥有岛屿生活痕迹的群岛；
- 玩家、抄写员、课程怪、区域 Boss 和楼层 Boss 的轮廓与模型职责一致；
- SQL 成功不仅显示数值，也改变水位、航线、桥、浮标、灯塔和档案状态；
- 外部素材可替换、可重制、可审计，而不是不可追溯的 PNG 拼盘。

### 1.2 用户与干系人

| 角色 | 本文需要保证的结果 |
|---|---|
| SQL 初学者 | 交互物、危险和任务目标一眼可读，不因美术升级看不懂题目 |
| 像素冒险玩家 | 两层具有地点记忆、地标、生态和回访变化 |
| 美术 / 动画 | 每类素材有网格、尺寸、帧数、色板、命名和验收依据 |
| 关卡设计 | 装饰不改变碰撞，不遮挡主路、怪物、篝火、捷径或调查点 |
| Phaser 工程 | 图集、图层、加载、像素对齐和降级边界明确 |
| QA | 能按截图、动图、碰撞、性能和授权清单验收 |
| 法务 / 发布 | 每个第三方文件都能追溯到来源、许可、原包和派生过程 |

### 1.3 MVP 范围

- 第一层完整地形、建筑、交互物、角色、怪物、Boss、VFX 和状态变化；
- 第二层完整地形、岸线、水面、交通、角色、怪物、Boss、VFX 和状态变化；
- 两层各一套正式运行时图集与清单；
- 共享玩家、抄写员、篝火、宝箱、基础 UI 标记和通用反馈资产；
- 开发者模式中的图集检查、碰撞检查、动画检查和状态切换需求；
- 外部 CC0 素材的来源、哈希、许可和派生记录；
- 程序化图形作为素材加载失败时的降级，不作为正式视觉目标。

### 1.4 本次不做

- 不制作第三至八层正式素材；
- 不改变 `48×36 / generator-v5` 地图数据、课程顺序或核心输入；
- 不引入 3D、动态光照引擎、实时阴影、粒子物理或自由航船；
- 不整包接入 89 MB 角色素材库；
- 不使用商业游戏拆包、来源不明像素图、AI 模仿具体在世艺术家的素材；
- 不把概念图直接缩小当作 Sprite；
- 不用持续全屏天气、后处理或高密度装饰掩盖缺少关卡内容；
- 不因视觉资产切换而改变存档中的逻辑坐标和碰撞真相。

## 2. 总体美术命题

### 2.1 一句话方向

> 被数据库规则侵蚀的手工童话遗迹：世界由石、木、纸、水、火和旧机械组成，SQL 痕迹只在权限、
> 字段、记录与恢复发生时显现。

视觉不能变成“霓虹终端铺在迷宫上”。数据库意象应依附真实物件：

| 数据概念 | 世界载体 |
|---|---|
| 行 / 记录 | 纸页、门牌、床牌、航海日志、浮标回执 |
| 主键 / ID | 铜牌、刻印、怪物档案编号 |
| `NULL` | 已调查但为空的姓名栏、缺失装备挂钩 |
| 聚合 | 被重新归档的纸堆、汇入同一水轮的回执 |
| 排序 | 按强度亮起的浮标、先后靠岸的航线 |
| 连接 | 树根桥、绳索、航标链和房间—实体关系 |
| 查询成功 | 世界状态被纠正，而非通用绿色闪光 |

### 2.2 五个视觉支柱

1. **地点先于系统**：先读出档案库、码头、沼泽和灯塔，再读出 SQL。
2. **轮廓先于颜色**：墙、青蛙、猎犬、篝火、箱子和机关不能只靠色相区分。
3. **温暖有来源**：暖色只来自篝火、抄写员灯、浮标和被恢复的有效记录。
4. **变化留下痕迹**：排水、退潮、开捷径和名字恢复必须改变地形或物件状态。
5. **低密度动画**：关键动得清楚，背景动得克制；不以闪烁和噪点制造“像素感”。

### 2.3 视角和构图

- 世界采用俯视 3/4 视角，不切换横版或等距菱形；
- 地面遵循 16×16 逻辑格，墙面可向上延伸 8–16 像素但碰撞仍落在底部格；
- 角色脚点位于逻辑格中心偏下，遮挡排序以脚点而非图片中心计算；
- 主路宽 2–4 格，门洞至少 2 格宽；单格只用于短桥、证据点或有意识的收束；
- 远景与主地标不承担碰撞，不能与可走地形使用相同边缘；
- 相机内同时出现的高对比交互热点原则上不超过 4 个；
- 大面积地图状态变化使用局部序列，不用整屏白闪代替演出。

## 3. 像素网格与技术美术规范

### 3.1 逻辑网格

| 项目 | 规格 |
|---|---|
| 源 Tile | `16×16 px` |
| 当前逻辑显示 | `32×32 px`，即 2× 整数放大 |
| 世界坐标 | 继续使用当前 `TILE_SIZE = 32` |
| 纹理采样 | Nearest Neighbor；`pixelArt: true`、`antialias: false` |
| 对齐 | 世界物件的脚点、碰撞和锚点必须落在整数像素 |
| 旋转 | 世界 Sprite 禁止任意角度旋转；仅允许预制 90° 方向帧 |
| 缩放 | 资产构建只允许整数缩放；运行时角色不使用长期小数缩放 |
| 透明边 | 图集帧外至少 1 px 透明 Padding，防止邻帧渗色 |

`Phaser.Scale.FIT` 可能使最终 CSS 展示发生非整数缩放。验收需同时检查：

- 内部画布仍以 32 px 逻辑 Tile 渲染；
- 1×、1.5×、2× 浏览器缩放下不出现纹理平滑；
- 窄屏优先保证 SQL 与操作可读，不强求每个 CSS 像素都对应设备像素；
- 截图审查以浏览器 100% 缩放和固定测试视口为基准。

### 3.2 Sprite 画布

| 类别 | 源画布 | 脚点 | 说明 |
|---|---:|---|---|
| 玩家 / 抄写员 | `16×24` 或 `16×32` | 底部中心 | 允许头部跨出 Tile |
| 小型怪 | `16×16` | 底部中心 | 史莱姆、青蛙、小水怪 |
| 中型怪 | `24×24` 或 `32×24` | 底部中心 | 猎犬、水蛇、树妖 |
| 区域 Boss | `32×32` 或 `48×32` | 底部中心 | 湖兽、蛙王 |
| 楼层 Boss | `48×48`，最大 `64×64` | 底部中心 | 登记官、灯塔守卫 |
| 单格交互物 | `16×16` 或 `16×24` | 格中心 / 底部 | 箱子、浮标、床牌 |
| 双格地标 | `32×32` 至 `48×48` | 显式锚点 | 水轮、船闸、短船 |

不能为了塞进 16×16 而破坏动物或机关轮廓。超出一格的图像必须在 `manifest.json` 声明：

- `frameWidth`、`frameHeight`；
- `footOffsetX`、`footOffsetY`；
- `collisionFootprint`；
- `occlusionHeight`；
- `interactionAnchor`。

### 3.3 边线与明暗

- 轮廓优先使用带色深灰，不默认纯黑；
- 单个 16×16 Tile 最多 5 个主色阶；发光帧可额外增加 1 个高光色；
- 墙体光从左上或正上偏左进入，两层保持统一；
- 地面明度差不低于墙体与深水边界所需的可读阈值；
- 可交互描边只在靠近、聚焦或管理员检查时出现，不常驻覆盖美术；
- 角色眼睛、名字恢复、权限灯可使用高亮，但面积不超过角色主体约 10%。

### 3.4 色盲与信息冗余

- 安全、危险、毒、水和不可走区域必须同时依靠纹理或轮廓；
- 浅水有波纹与可见底纹，深水有暗边和无底纹；
- 毒区使用气泡 / 斑点纹理，不只用绿色；
- 捷径门的锁、铰链和开合状态具有不同形状；
- ID 未发现状态使用编号牌；名字发现后增加图鉴印记，不能只改颜色。

## 4. 共用色彩、光照与材质系统

### 4.1 色彩结构

两层共享“暗中性色 + 一个环境冷色 + 一个叙事暖色 + 一个 SQL 交互色”的结构：

| 角色 | 第一层 | 第二层 |
|---|---|---|
| 基础暗色 | `archive-ink #111820` | `deep-tide #15364A` |
| 环境中间色 | `wet-slate #2E4650` | `shallow-glass #4A9DB1` |
| 中性浅色 | `paper-ash #D8D0B8` | `sand-letter #D9C89C` |
| 叙事暖色 | `ember-home #E07A45` | `beacon-amber #F0B75A` |
| 交互色 | `query-mint #78C9B8` | `query-mint #78C9B8` |
| 本层异常色 | `registry-gold #D6B86B` | `lost-violet #796B9A` |

色表是方向 Token，不要求所有像素机械使用同一个十六进制值。衍生图集允许在固定亮度关系内使用
邻近颜色，但不得把两层调成同一张蓝灰色表。

### 4.2 光照规则

- 不使用实时逐像素灯光；光照由 Tile 变体、局部 Overlay 与少量 Alpha 动画表达；
- 第一层的局部暖光半径小，边缘快速回到湿冷石色；
- 第二层拥有大范围环境光与水面反光，但角色脚下仍有稳定接触阴影；
- 发光物只照亮附近 1–2 个逻辑格，不把安全区画成荧光圆盘；
- 篝火安全区边界依靠火光、灰烬、地面环形痕迹和无怪物行为共同表达；
- 迷雾 / Fog of War 仍是探索证据，不覆盖关键 UI 和当前交互提示。

### 4.3 材质表

| 材质 | 轮廓与纹理 | 动画 | 碰撞读法 |
|---|---|---|---|
| 湿石 | 大块石缝、下缘湿痕 | 偶发单帧滴水 | 厚墙顶与深色底边 |
| 纸 / 档案 | 不规则边缘、线条方向一致 | 翻页或浮起 2–4 帧 | 默认不阻挡，柜体阻挡 |
| 铜 / 机械 | 暖暗金、铆钉、氧化青 | 齿轮 / 印章短循环 | 实心底座明确 |
| 木 | 清楚木纹与断面 | 水轮 / 船桨低帧 | 栈桥边缘有护边 |
| 浅水 | 可见沙 / 石底、稀疏波纹 | 4–6 帧 | 可走时保留脚下波纹 |
| 深水 | 暗面、岸线泡沫、无底纹 | 4–8 帧 | 不可走边缘有连续暗线 |
| 泥沼 | 斑驳泥、水泡与芦苇 | 局部 3–4 帧 | 可走 / 不可走纹理不同 |
| 沙 | 大面平静、局部贝壳 / 脚印 | 默认静态 | 不用随机噪点填满 |
| 火 | 明亮核心、暗红外缘 | 4–6 帧 | 实体篝火有木堆底座 |
| 数据痕迹 | 纸页、刻印或水纹内的 Mint 线 | 触发时短暂出现 | 永不单独作为墙体 |

## 5. 第一层：地下余烬档案

### 5.1 风格支柱

1. **潮湿的制度机器**：排水渠、水轮、铜阀和登记装置仍在运行。
2. **纸比石更危险**：Boss 的压迫来自规则、印章和展开纸页，不来自火焰数量。
3. **唯一的家火**：篝火和抄写员灯构成少量暖色，其他区域保持冷湿。
4. **绕后即理解**：铁门从背面打开后，视觉上直接看见出生登记厅。
5. **0 行留下物理痕迹**：空床牌、湿墙姓名高度线和空白登记页证明“查过但没有”。

### 5.2 区域表现表

| 地点 | 地面 / 墙体 | 主材质 | 主地标 | 状态变化 | 构图要求 |
|---|---|---|---|---|---|
| 无名登记厅 | 干燥青石、较高墙顶 | 纸、铜、石 | 登记桌、关闭铁门、升降机远景 | 回访出现居民轮廓和 Boss 预告 | 首屏看见抄写员、门和一条向下水路 |
| 青石排水渠 | 湿石、沟槽、积水 | 水、石、锈铁 | 连续排水沟 | 水流方向变化 | 水渠是边界，不堆满栅栏死路 |
| 水轮大厅 | 宽空间、中央轴 | 木、铜、水 | 唯一主水轮、唯一主水阀 | 停止 → 转动 | 水阀只出现一处，位于初始复活锚点后方墙面或明确控制位 |
| 无名宿舍 | 低处湿地、整齐床位 | 木、布、床牌 | 成排无名床 | 水退、床牌 `NULL` | 同样床体做 3–4 种损坏变体，避免复制噪声 |
| 余烬仓窖 | 干燥砖石、较低顶 | 木箱、灰烬、纸 | 中段实体篝火 | 休息后成为复活点 | 温暖但不豪华，像临时家 |
| 旧仓库 | 重木地面、货运轨 | 箱、链、铁门 | 确定宝箱、捷径背面 | 门永久打开 | 宝箱与课程掉落不重叠 |
| 聚合档案室 | 环形地面、中央归档槽 | 纸、书架、铜轨 | 多组回执堆 | 零散 → 分组排列 | 纸堆高度表达 COUNT，标签可读 |
| 后段篝火 | Boss 前避难小室 | 灰烬、石、少量布 | 第二处实体篝火 | 休息 / 复盘 | 与 Boss 厅保持一扇厚门的安全距离 |
| 登记大厅 | 对称、纵深、较高墙 | 铜印、纸幕、黑石 | 登记官与规则墙 | 红色注销 → 金色修正规则 | Boss 是焦点，不放多座可误认篝火 |
| 档案升降机 | 垂直框架和海水渗痕 | 铁、链、木箱 | 实体升降笼 | Boss 后启动 | 远景预告第二层潮光 |

### 5.3 第一层签名镜头

必须能够制作以下无 HUD 截图：

1. 玩家在登记厅出生余烬锚点的低火光中与抄写员相遇，铁门另一侧可见遥远灯光；
2. 水轮启动，水流方向改变，栈桥落下；
3. 无名宿舍退水，床牌统一显出 `NULL`，湿墙出现姓名高度线；
4. 从旧仓库打开铁门，几步外就是出生登记厅，抄写员已走到门边；
5. 登记官展开纸页，铜印压在“0 ROWS”规则上；
6. 修正规则后的升降机向潮光上行。

### 5.4 第一层角色与怪物清单

| 对象 | 轮廓要求 | 探索动画 | 战斗动画 | 特殊状态 |
|---|---|---|---|---|
| 无键者 | 不完整衣领、单侧轮廓、武器清楚 | 4 向步行各 4 帧、待机 4 帧 | 施放 4、命中 4、受击 2、倒下 4 | 提灯与第一页纸片可挂接 |
| 抄写员 | 披肩 / 纸页 / 暖灯三角轮廓 | 待机写字 6、抬头 4、步行 4×4 | 无战斗 | 桌前、门边、装订三姿态 |
| 史莱姆 | 圆软主体、可见核心 | 待机 4、移动 4 | 攻击 4、受击 2、消散 5 | 水 / 毒 / 铁必须改变附属轮廓 |

## 6. 第二层：潮汐群岛

### 6.1 风格支柱

1. **离开地窖后的第一次呼吸**：进入一分钟内看见天空反光、远岸和航线。
2. **水域有层次**：浅滩、深水、泥沼、潮沟和海面使用不同纹理与边缘。
3. **交通就是空间理解**：短船、古树桥和船闸形成路径，而非抽象传送门。

### 7.2 身份标签

- 击败前课程怪和已出现生态怪：`ID #NNN` 常亮；
- 击败前不显示真名；
- 击败后：真名与 ID 都常亮，字号层级以真名为主；
- NPC 名字从第一次正式见面后常亮；抄写员不需要玩家贴身才知道她是谁；
- 标签避让角色头顶、HP 条和交互提示，不叠成截图中的多层黑框；
- 远距离只保留名字 / ID；靠近后才增加 `E` 提示和一句行为状态；
- 管理员模式可切换标签锚点、碰撞框和遮挡框。

## 8. 动画规范

### 8.1 帧率与节奏

- 游戏逻辑目标 30 FPS；
- 像素动画建议按 6、8、10 或 12 FPS 播放，不必逐帧 30 FPS；
- 待机循环至少 0.8 秒，避免高频抖动；
- 水、火、浮标和灯塔不得全部同相位启动；
- 同屏相同装饰用种子化相位偏移，不使用每帧随机；
- 攻击命中帧、判定帧和声音事件由动画事件表统一定义。

### 8.2 最低动画集合

| 类别 | 最低集合 |
|---|---|
| 玩家 | 4 向步行、待机、SQL 施放、受击、倒下、胜利 / 名字恢复见证 |
| 抄写员 | 写字、抬头、步行、整理纸页、岸边观察、装订 |
| 普通怪 | 待机、移动、攻击、受击、名字恢复消散 |
| Boss | 待机、阶段变化、2 种攻击、受击、规则修正 / 退场 |
| 交互物 | 关闭、触发过渡、最终稳定状态 |
| 环境 | 只为水、火、机械和剧情状态制作必要循环 |

### 8.3 Reduced Motion

- 关闭镜头震动、弹跳、长位移粒子和快速光束扫描；
- 保留关键帧：准备、结果、名字恢复、状态已改变；
- 以 120–200 ms 颜色切换、静态碎片和明确文字代替飞行路径；
- 水位和退潮直接交叉淡化到目标 Tile，不要求逐格滚动；
- Reduced Motion 不改变碰撞、计时、伤害或存档时点。

## 9. 图层、遮挡与碰撞

### 9.1 世界图层

建议运行时层次：

```text
00 远景 / Void / 水平线
05 地面 Base
08 地面 Decal：裂缝、湿痕、脚印、浅水波纹
10 地形 Edge：墙底、岸线、桥面
15 地面下层特效：水影、排水、倒影
20 地面物件：箱、床、桌、低草
25 Actor：按脚点 Y 排序
30 高物件：墙顶、树冠、灯塔上部
35 前景遮挡：管道、桥梁上层、门楣
40 Fog / 探索遮罩
45 世界标签、ID、名字、交互提示
50 状态反馈：名字恢复、命中、区域事件
60 HUD / SQL / 背包 / 图鉴
```

现有固定 `depth` 可以作为迁移起点，但正式渲染需为 Actor 与高物件引入稳定脚点排序，避免人物
站在墙或青蛙后方时发生“模型变成墙”的错觉。

### 9.2 碰撞真相

- 逻辑地图仍拥有碰撞，图片不自行决定可走性；
- 每个交互物在清单中声明 `visualFootprint`、`collisionFootprint`、`interactionCells`；
- 水阀、篝火、箱子和船闸不得使用同一通用碰撞类别；
- 湖兽、水蛇与水面装饰必须分离，不能把怪物 Sprite 当成水 Tile；
- 动画改变视觉状态时，碰撞只在领域状态确认后切换；
- 管理员模式必须能同时显示 Tile 坐标、碰撞、脚点、交互范围和导航阻挡。

## 13. 下载、处理与发布流程

### 13.1 下载门禁

1. 产品负责人确认要使用的来源和文件类别；
2. 只从作者官方页或官方仓库下载，不使用素材镜像站；
3. 记录最终 URL、UTC 时间、文件名、响应字节数；
4. 解压前计算原包 SHA-256；
5. 在临时目录列出归档内容，拒绝可执行文件和异常路径；
6. 读取包内 LICENSE / README，与页面声明对照；
7. 许可不一致时标记 `BLOCKED`，不自行选择“更宽松”的解释。

### 13.2 选择与派生

1. 只复制实际需要的源文件到 `selected/`；
2. 对每个选中文件计算 SHA-256；
3. 使用 `scripts/assets/` 下的确定性脚本裁切、重配色和合图；
4. 不用图形编辑器手工覆盖唯一源文件；
5. 必须手工修图时，保留工程文件与导出说明；
6. 派生输出写入新文件，失败时不覆盖上次有效结果；
7. 运行时图集只由 manifest 引用的派生文件构建。

### 13.3 建议脚本

```text
scripts/assets/
  inventory-archive.mjs
  verify-source-license.mjs
  build-floor01-atlas.mjs
  build-floor02-atlas.mjs
  verify-runtime-assets.mjs
  report-texture-memory.mjs
```

脚本必须检查：

- 原包、选中文件和派生文件哈希；
- 图片尺寸、色彩模式和透明通道；
- 16×16 / 16×32 / 自定义帧边界；
- 同名帧冲突；
- 图集外溢和 Padding；
- 运行时孤儿文件；
- `public/` 中来源不明的 PNG、JPG、ASE、PSD、ZIP；
- `ATTRIBUTIONS.md` 和总 manifest 是否包含每个第三方来源。

### 13.4 发布门禁

只有同时满足以下条件才可进入生产构建：

- 来源官方且授权明确；
- 原包与每个运行时文件存在 SHA-256；
- 包内许可与页面事实一致；
- 修改路径可复现；
- `ATTRIBUTIONS.md` 已同步；
- 图集和帧表通过自动检查；
- 美术、关卡、工程和 QA 完成截图 / 动画 / 碰撞验收；
- 生产包不包含 `assets/vendor/original/`、`.ase`、`.psd`、ZIP 或许可截图。

## 14. 图集、加载与性能预算

### 14.1 文件预算

| 楼层 | 地形 | 角色 / 怪物 | 道具 / VFX | 压缩图片合计硬门槛 |
|---|---:|---:|---:|---:|
| F1 | ≤ 256 KB | ≤ 256 KB | ≤ 128 KB | ≤ 768 KB |
| F2 | ≤ 384 KB | ≤ 320 KB | ≤ 192 KB | ≤ 1.0 MB |
| Shared | — | ≤ 256 KB | ≤ 128 KB | ≤ 512 KB |

预算允许发布评审按实际视觉价值调整，但必须同时报告压缩文件和解码纹理内存。RGBA 解码预算按：

```text
width × height × 4 bytes
```

计算，不以“PNG 只有 100 KB”代替内存审查。

### 14.2 纹理与动画预算

- 单张图集优先不超过 `2048×2048`；移动端保守目标 `1024×2048`；
- 同屏常驻独立纹理尽量不超过 8 张；
- F1 与 F2 专属图集不同时常驻；
- 只预加载当前楼层和必要的下一段过渡缩略资源；
- 水、火、浮标等循环使用 Sprite Sheet，不为每帧创建独立纹理；
- 同类静态装饰优先批量绘制或 Tile Layer，不为每块石头创建复杂 Container；
- 粒子同时可见量：普通反馈 ≤ 24，Boss 峰值 ≤ 48；
- 管理员 Overlay 默认关闭，不进入普通玩家渲染路径。

### 14.3 运行时降级

加载失败或低性能模式按以下顺序降级：

1. 关闭纯装饰水面高光、浮尘、纸屑和远景动画；
2. 将 6–8 帧环境循环降为 2–4 帧；
3. 关闭前景非关键遮挡；
4. 使用静态状态 Tile 替代过渡动画；
5. 使用现有程序化 `Graphics` 角色 / 地形作为最终兜底；
6. 始终保留碰撞、交互、ID、名字恢复、SQL 反馈和地图状态。

降级不能把青蛙替换为墙块、把水阀复制成通路、把抄写员隐藏或让名字仅在贴身时出现。

## 15. 旧设计保留 / 改造 / 废弃矩阵

| 旧项 | 决策 | 目标处理 |
|---|---|---|
| 俯视 3/4 与 16×16 逻辑像素网格 | `KEEP` | 继续以 32 px 世界 Tile 进行 2× 展示 |
| `48×36 / generator-v5` 宏观地图与三地区 | `KEEP` | 资产只改变表现，不改变课程和逻辑坐标 |
| 当前程序化地形与 Actor | `FALLBACK` | 保留为缺图和低性能兜底，正式画面改用图集 |
| 当前不同怪物已有 silhouette 分类 | `TRANSFORM` | 保留语义分类，重绘成可识别 Sprite 与专属动画 |
| 角色装备颜色变化 | `TRANSFORM` | 改为身体 + 武器 + 防具 + 剧情挂件分层 |
| 地区主要靠整块颜色区分 | `REMOVE` | 用墙型、材质、岸线、建筑和地标区分 |
| 多个相同“回燃篝火”或火堆 | `REMOVE` | 每层只保留出生安全锚点和中 / 后两座实体篝火 |
| 多条水阀 / 栅栏式水路 | `REMOVE` | F1 只留一个主水阀；水渠主要做视觉边界 |
| NPC 靠近后才显示名字 | `REMOVE` | 正式介绍后 NPC 名字常亮；距离只控制交互提示 |
| 怪物发现前显示真名 | `REMOVE` | 发现前常亮 ID，击败后常亮真名 + ID |
| 怪物模型与文本不一致，如青蛙像墙 | `REMOVE` | 模型、碰撞、文本和图鉴必须由同一 visual profile 驱动 |
| 第二层“丛林王”旧身份 | `REMOVE` | 由灯塔守卫统一替代，禁止残留旧标签和模型 |
| 抄写员复制到每个篝火 | `REMOVE` | 每层唯一实体，在固定剧情点移动 |
| 旧概念 PNG 直接进入运行时 | `REMOVE` | 只作方向参考，正式制作重新像素化 |
| CC0 主包 + 项目专用重绘 | `KEEP` | 原始 / 选择 / 派生分离并记录 SHA |
| 整包 Ninja Adventure | `REMOVE` | 只在后续逐文件审计后选择性使用 |
| 装饰随机覆盖路线 | `REMOVE` | 装饰槽由 Seed 选择，但通过阻挡与交互安全检查 |
| 固定标签黑框叠在 Actor 上 | `TRANSFORM` | 标签避让、距离分层、管理员检查锚点 |
| 水 / 火 / 灯全部高频循环 | `REMOVE` | 低帧、错相、低密度动画 |

## 18. 验收标准

### 18.1 视觉盲测

- 关闭 HUD 后，5 秒内能区分 F1 与 F2；
- F1 截图中至少能辨认登记厅、排水渠、水轮、宿舍、档案室或 Boss 厅中的四类；
- F2 截图中至少能辨认码头、浅滩、沼泽、沉水村落、船闸或灯塔中的五类；
- 玩家能指出 F1 唯一水阀、两座实体篝火和铁门捷径；
- 玩家能指出 F2 深浅水边界、短船、船闸和灯塔；
- 不看名字也能区分青蛙、猎犬、水蛇、树妖、湖兽和灯塔守卫。

### 18.2 状态与叙事

- F1 水轮启动、水位下降、床牌显空、回执分组和规则修正均有独立世界表现；
- F2 浮标排序、频道去重、树根连接、退潮、船闸和七束灯光均有独立世界表现；
- 捷径打开后能从构图上理解为什么缩短路程；
- 抄写员每层只有一个实体，位置随剧情变化；
- 名字恢复前后标签、模型反馈和图鉴状态一致；
- 关键物品和无随机掉落不会使用同一大型战利品画面。

### 18.3 技术与性能

- 30 FPS 目标设备上无长期低于 27 FPS；
- 所有纹理关闭平滑，无半像素和邻帧渗色；
- 当前楼层加载不带入另一个楼层全部专属图集；
- 页面隐藏后动画和加载工作安全暂停；
- 纹理预算、粒子预算和图集尺寸通过；
- 320 px 宽度、触屏、iframe 和 Reduced Motion 可完成核心流程；
- 缺失任一图集时仍能依靠降级图形继续玩。

### 18.4 授权与可追溯性

- 每个第三方运行时文件都可追溯到官方来源、原包、许可证和 SHA-256；
- 每个派生图可追溯到输入、处理脚本和输出哈希；
- `public/` 不存在来源不明 PNG、JPG、MIDI、音频或工程文件；
- `ATTRIBUTIONS.md` 与资产 manifest 一致；
- 构建产物不包含第三方原包；
- 任何许可字段为 `unknown`、空值或互相冲突时，发布失败。

## 19. 停止与返工条件

出现任一情况立即停止继续铺量：

- 地图仍主要靠底色和文字标签区分；
- 青蛙、猎犬或水蛇仍与墙、方块或通用软泥共用轮廓；
- F1 出现多个主水阀或超过两座实体篝火；
- F2 通过扩大空水面延长时长；
- NPC 名字仍只能贴身看见；
- 抄写员仍复制到每个篝火；
- 外部文件先进入 `public/`，后补许可；
- 调色覆盖原始来源文件；
- 图集未记录帧、脚点和碰撞；
- 视觉升级让 SQL 字体、错误反馈、触屏或 30 FPS 明显退化。

## 20. 风险与取舍

| 风险 | 取舍 |
|---|---|
| CC0 素材形成拼盘感 | 每层一套主包；其他来源只补功能并统一重描边、调色 |
| 16×32 高墙与角色串帧 | 帧尺寸进入 manifest，自动检查，禁止按通用 16×16 强切 |
| 正式 Sprite 增加包体 | 每层延迟加载，只发布实际使用图集 |
| 大地图装饰过多影响性能 | Tile / 批量渲染优先，动态对象只用于关键交互 |
| 视觉状态增加存档字段 | 优先从课程、Boss 和门状态派生 |
| 装备外观组合爆炸 | 基础身体 + 少量 Overlay，不为每种组合制作全套角色 |
| 水域开阔导致空走 | 水面负责留白，岛屿和短航线控制 10–15 秒事件间隔 |
| 概念图与 16×16 不兼容 | 概念图只定轮廓、色温和构图，正式 Sprite 独立重制 |
| 授权页面后续变化 | 保存访问事实、原包与 SHA，不依赖未来页面仍相同 |

5. **P4 F1 浏览器垂直切片**：碰撞、动画、降级、性能与盲测；
6. **P5 F2 地形与交通**：岸线、深浅水、短船、树根桥、船闸；

凭静态概念图进入下一阶段。
