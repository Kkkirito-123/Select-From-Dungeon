## 0. 文档职责

本文将玩家对“连续、温柔、不过度尖锐、经典作品电子化、从地窖到群岛逐渐打开”的要求，转换成
可制作、可实现、可测量、可授权审计的 F1 / F2 音频规格。

它负责冻结：

- 第一、第二层的音乐情绪、调性、节拍、编制和状态变化；
- 经典作品的作品版权、版本、编曲、表演、录音和采样权边界；
- 连续循环、分层混音、战斗过渡、SQL 思考降噪与 Boss 状态机；
- SFX 事件表、响度、并发、空间感和抗疲劳规则；
- Web Audio 解锁、页面生命周期、格式、加载、性能和降级；
- 可访问性、浏览器与主观试听验收；
- 旧音频方案的保留、改造和废弃矩阵。

本文不声称任何未下载、未哈希或未逐文件复核的第三方录音已经获得授权。当前运行时事实如下：

- F1 以 Mozart K.265 公版主题为材料，F2 以 Handel《水上音乐》HWV 348–350 为材料；
- 项目独立录入音符、重写编曲并确定性合成，没有导入乐谱扫描、MIDI、采样、SoundFont 或现代录音；
- 两层各有探索、战斗和 Boss 三条 46–55 秒循环，发布 OGG 与 MP3，切换时交叉淡化 1.2 秒；
- `assets/audio/public-domain-arrangements/audio-source.json` 记录作品、生成器、响度、时长与哈希；
- 第三至八层继续使用 Web Audio 兼容配方，运行时音频解码失败不会阻塞游戏。

## 1. 目标、用户与边界

### 1.1 本次目标

- F1 从“地窖里仍留着的一盏家灯”开始，温暖、小编制、略带疑问；
- F2 在保留人物主题联系的同时打开空间，呈现水面、航行与冒险；
- 探索音乐连续，不再出现短句熄火、重新点火或长期低频“嗡嗡”；
- 战斗通过速度、切分、低音脉冲和声部密度变紧张，不通过刺耳高频和噪声墙；
- SQL 编辑时降低音乐存在感，但不硬切、不丢节拍；
- 任何音乐都不依赖不明版权录音、平台抓取、商业游戏音轨或来源不清的 MIDI / SoundFont；
- 音频在博客 iframe、桌面和移动浏览器中具有明确解锁和降级路径。

### 1.2 用户与干系人

| 角色 | 本文需要保证的结果 |
|---|---|
| 玩家 | 音乐有旋律、有旅程感、不疲劳，不干扰 SQL 思考 |
| 音乐设计 / 编曲 | 作品选择、编制、循环和状态变奏有明确 Brief |
| Sound Designer | 每个游戏事件有优先级、频段和并发预算 |
| 前端 / Phaser | 解锁、加载、状态切换、Duck、暂停和释放边界明确 |
| QA | 可按响度、循环、浏览器、状态机和主观体验验收 |
| 法务 / 发布 | 作品、版本、编曲、表演、录音和样本逐层可追溯 |

### 1.3 MVP 范围

- F1：探索、篝火 / 抄写员、普通战、登记官 Boss、楼层过渡；
- F2：码头 / 浅滩探索、湖 / 沼泽变化、普通战、湖兽、灯塔守卫、短船与楼层过渡；
- 一组共享 SQL、角色、物品、门、名字恢复、胜败 SFX；
- F1 / F2 专属环境和地标 SFX；
- 音乐与 SFX 独立总线、静音和音量控制；
- 无录音时的项目内安全降级；
- 权利清单、源文件、衍生文件、哈希和发布门禁。

### 1.4 本次不做

- 不为第三至八层制作正式音频；
- 不加入语音配音；
- 不复制《赛尔号》或其他商业游戏的旋律、和声、录音或音色；
- 不从 QQ 音乐、网易云、Spotify、YouTube、CD 或视频中提取音频；
- 不把“作曲家去世已久”当作现代录音可用的证明；
- 不使用授权不明的 MIDI、SoundFont、采样包、混响脉冲或 DAW 预设内容；
- 不以大型交响采样库实现“大编制”；
- 不因音乐切换阻塞 SQL、战斗或地图状态。

## 2. 音频支柱

### 2.1 从温暖地窖到开阔群岛

```text
F1 出生火光：低处、亲近、迟疑
→ F1 排水与档案：冷湿机械中保留一条暖旋律
→ F1 登记官：制度性的压力，不是恐怖噪声
→ 升降机：低音持续，上方第一次出现海的摆动
→ F2 码头：旋律打开、呼吸变长
→ F2 群岛：6/8 航行感、木管 / 弦乐式回应
→ F2 灯塔：更庄严，但七个方向都被保留
```

### 2.2 经典作品“电子化”的定义

“电子化”不是播放现代唱片再加滤镜，也不是用廉价方波逐音复刻。目标是：

- 使用已确认进入公版的作品动机；
- 依据可用的公版乐谱或项目自行转写的基础旋律；
- 由项目重新设计和声、节奏、结构、配器、音色和循环；
- 使用项目自有合成器、明确许可的工具或项目自制录音；
- 保留古典旋律的可识别性，但服务关卡情绪和交互状态；
- 生成项目拥有或明确获准分发的最终录音。

### 2.3 连续但不持续轰鸣

连续性来自：

- 足够长的乐句；
- 小节边界上的无缝调度；
- 旋律、低音和和声层交替接力；
- 状态切换时保持调性、拍点或尾音；
- 乐句留白中保留空气和环境，而不是持续固定低音 Pad。

禁止：

- 全程不变的低频正弦 / 三角长音；
- 8–16 秒短循环不断从头开始；
- 每次进区域、开 SQL 或上船都重启整首；
- 用白噪声和高频帽音掩盖调度断点；
- 多个接近频率的长音叠加形成拍频“嗡嗡”。

## 3. 版权与来源门禁

### 3.1 六层权利

每首音乐必须分别判断：

| 权利层 | 需要证明什么 |
|---|---|
| 原始作品 | 作曲和基础旋律在目标发布地区已进入公版，或获得授权 |
| 乐谱版本 | 使用的具体校订、排版、注释或数字版是否可复制 / 改编 |
| 转写 / MIDI | 谁制作、依据什么版本、是否允许再分发和修改 |
| 新编曲 | 项目是否拥有重新和声、结构和配器的权利 |
| 表演 | 演奏者是否授权录制与发布 |
| 录音 | 具体声音文件是否 CC0、可靠 Public Domain 或项目自有 |

任意一层为 `unknown`，最终音频均为 `BLOCKED`。

### 3.2 当前运行时作品

| 楼层 | 当前代码标记 | 作品层判断 | 输入与录音事实 | MVP 结论 |
|---|---|---|---|---|
| F1 | Mozart《小星星变奏曲》K.265 | Mozart 逝于 1791 年，基础作品在中国及 life+70 地区属于公版 | 项目独立录入熟知主题音符并自行编曲、合成和录音；未导入乐谱、MIDI、采样或现代录音 | 已按项目自制录音发布；生成器、时长、哈希与权利说明进入双份 manifest |
| F2 | Handel《水上音乐》HWV 348–350 | Handel 逝于 1759 年，基础作品在中国及 life+70 地区属于公版 | 项目独立录入熟知主题音符并自行编曲、合成和录音；未导入乐谱、MIDI、采样或现代录音 | 已按项目自制录音发布；生成器、时长、哈希与权利说明进入双份 manifest |

不能从 Musopen 的作品总页、流媒体页面或“免费听”按钮推断单条录音可修改和分发。

### 3.3 已知可靠但非目标曲目的录音候选

- [Open Goldberg Variations](https://opengoldbergvariations.org/)：Kimiko Ishizaka 录音明确以
  CC0 / 公版方式开放；
- [Open Well-Tempered Clavier, Book I](https://kimikoishizaka.bandcamp.com/album/bach-well-tempered-clavier-book-1)：
  页面明确说明录音与乐谱开放。

这些候选只能在产品决定改变选曲、并对具体文件完成下载、许可和哈希审计后使用。它们不能证明
莫扎特 K.265 或亨德尔《水上音乐》的其他录音也可用。

### 3.4 明确禁止

- 流媒体缓存和录屏；
- 商业唱片、电影原声、游戏原声；
- “变调后就不侵权”的现代录音；
- 只写“Public Domain Classical”但不指向具体文件与录音者的包；
- 来源不明的 MIDI；
- 包含第三方 SoundFont 但未说明再分发许可的导出音频；
- AI 音乐服务输出但其商用、训练来源或独占条款不清楚的文件；
- 将《赛尔号》战斗音乐改调、加速或重制。

## 4. 当前事实与已落实边界

当前仓库已经统一以下事实：

- 第一、二层运行时明确标记为 Mozart K.265 与 Handel《水上音乐》公版主题的新编；
- `ArcadeAudio.ts`、运行时 Credit、`ATTRIBUTIONS.md` 和双份 `audio-source.json` 使用同一来源描述；
- `scripts/generate-runtime-classical-audio.mjs` 是唯一母带生成入口，OGG / MP3 哈希均可复核；
- 仓库不包含外部表演录音、MIDI、乐谱扫描、采样、SoundFont 或《赛尔号》等商业游戏音频；
- 第三至八层的小型 Web Audio 配方继续作为兼容内容，不冒充第一、二层正式录音。

本轮已经完成的发布验收为：

1. 基础作品、独立音符录入、编曲、合成、表演与录音责任逐层记录；
2. 生成脚本与 12 个运行时编码文件进入哈希清单；
3. 代码注释、运行时 Credit、`ATTRIBUTIONS.md` 与音频 manifest 同步；
4. 校验脚本验证运行时文件、字节数和 SHA-256；
5. 当前结论只覆盖仓库实际声明与发布文件，不替代面向特定司法辖区的外部法律意见。

## 5. 音乐制作策略

### 5.1 MVP 推荐：项目自有离线渲染循环

优先制作：

```text
公版谱源事实
→ 项目自行转写的声明式音符 / 工程
→ 项目原创和声、结构、节奏与音色
→ 离线渲染无缝 WAV Master
→ OGG + MP3 运行时版本
→ Web Audio 分层播放与状态切换
```

推荐离线渲染而不是继续把所有音乐声部实时创建为大量短 Oscillator，原因：

- 更容易控制连续性、混音、响度和抗疲劳；
- 可以试听并消除低频驻波、点击和拍频；
- 浏览器调度抖动不会切断乐句；
- 最终文件和权利链容易哈希、复核与回滚。

实时 Web Audio 仍适合：

- 短 SFX；
- 音乐加载失败时的简化主题；
- 小范围滤波、Gain、Duck 和交叉淡化；
- 不依赖外部样本的 UI 声音。

### 5.2 允许的替代

如果 MVP 暂不制作音频文件，可以继续程序化音乐，但必须：

- 删除持续低频 Bed；
- 乐句长度达到本规格最低值；
- 使用 Band-limit 或低谐波音色；
- 保持小节级连续调度；
- 离线录制 10 分钟压力样本并通过响度、频谱和主观试听；
- 将具名作品的谱源、转写与编曲事实写入 manifest。

## 6. F1 音乐方向：地下余烬档案

### 6.1 情绪和乐理

| 项目 | 规格 |
|---|---|
| 核心情绪 | 温暖、孤独、可理解，但“不知道自己是谁” |
| 作品候选 | Mozart K.265 基础动机，项目重新和声与结构 |
| 调性 | A Dorian / A 小调边缘；避免直接欢快 C 大调童谣感 |
| 拍号 | 探索 4/4；篝火可弱化拍点 |
| 探索速度 | `66–72 BPM` |
| 战斗速度 | `96–106 BPM` |
| Boss 速度 | `108–116 BPM` |
| 主音域 | 旋律约 `A3–C5`；长时集中在 `A3–A4` |
| 编制印象 | 柔和电钢 / 拨弦、低音大提琴式合成、纸页敲击、少量暖 Pad |

### 6.2 探索层

至少包含：

- `F1_MEL`: 可识别但不完整的主题；
- `F1_HARM`: 每 2–4 小节变化的暖和声，不持续停在同一低音；
- `F1_PULSE`: 极轻木质 / 纸页节拍，仅排水与机械区提高；
- `F1_AIR`: 稀疏房间尾音，不使用连续噪声；
- `F1_EMBER`: 篝火附近出现的高音暖色回应。

区域变化：

| 区域 | 增减声部 | 听觉目的 |
|---|---|---|
| 登记厅 / 出生 | `MEL + HARM + EMBER` | 像家，但旋律缺一部分 |
| 排水渠 / 水轮 | 加 `PULSE`，低音短促 | 机械可理解，不做工业噪声墙 |
| 无名宿舍 | 减节拍，增加旋律留白 | 让 `NULL` 的不安被听见 |
| 余烬仓窖 | `EMBER` 更清楚，低频减少 | 休息与人物温度 |
| 聚合档案室 | 主题分成 2–3 个短回应 | 表现不同来源被保留 |
| 登记大厅 | 和声收紧、低音更明确 | 制度压力 |

### 6.3 战斗与登记官

普通战：

- 沿用探索主题，不另写无关战斗旋律；
- 增加切分低音和短打击；
- 不使用持续锯齿、25% Pulse 主旋律或白噪声帽音；
- SQL 打开后移除最密节奏层，保留拍点与和声定位。

登记官 Boss：

- 铜印使用低中频短冲击，不用大音量金属爆音；
- 纸页使用轻噪声 / 高频短擦，但每次不超过约 250 ms；
- 阶段二增加大提琴式低声部和不协和悬挂音；
- 规则修正后不落入传统凯旋大调，保留未解决的二度或六度；
- 升降机开始时保留一个 F1 低音，并逐渐引入 F2 的 6/8 摆动。

## 7. F2 音乐方向：潮汐群岛

### 7.1 情绪和乐理

| 项目 | 规格 |
|---|---|
| 核心情绪 | 第一次开阔、流动、冒险；潮声下仍有身份不安 |
| 作品候选 | Handel《水上音乐》动机，项目重新选段、和声与结构 |
| 调性 | D Mixolydian / D 大调边缘；保留降七度的旧世界感 |
| 拍号 | `6/8` 为主 |
| 探索速度 | `72–80 BPM`，以附点四分音符感知 |
| 战斗速度 | `100–110 BPM` |
| Boss 速度 | `112–118 BPM` |
| 主音域 | `D3–D5`，长时主旋律不持续占据高音 |
| 编制印象 | 柔和木管式主旋律、拨弦 / 轻弦、圆号式中音回应、低频船桨脉冲 |

### 7.2 探索层

至少包含：

- `F2_MEL`: 开阔的 6/8 主旋律；
- `F2_OAR`: 每小节两次或三次轻船桨脉冲；
- `F2_HARM`: 低密度弦乐式和声；
- `F2_CALL`: 木管 / 圆号式远处回应；
- `F2_TIDE`: 只在水域变化时出现的上下行音型；
- `F2_BEACON`: 浮标与七倒影事件使用的七音序列。

区域变化：

| 区域 | 增减声部 | 听觉目的 |
|---|---|---|
| 潮汐码头 | `MEL + HARM`，轻 `CALL` | 第一口开阔空气 |
| 白沙浅滩 | 加轻 `OAR` 和高音拨弦 | 冒险与路线选择 |
| 月影湖 | 减节拍，低音与 `TIDE` 更明显 | 水下巨大影子 |
| 古树桥 | 两个声部一问一答 | 表现连接两端 |
| 芦苇沼泽 | 收窄频谱、使用断续木质脉冲 | 视野收缩但不噪 |
| 退潮村落 | 逐步恢复 `CALL`，加入门牌短音 | 旧生活被看见 |
| 船闸回航 | `OAR` 与 `BEACON` 对齐 | 空间掌握和回访 |
| 灯塔岛 | 圆号式中音增加，旋律更庄严 | 光明的规则压力 |

### 7.3 短船程

- 不重启整首探索音乐；
- 在当前拍点触发 1 小节出航过门；
- 航行中保持同一全局相位；
- 靠岸前 1 小节触发方向性 Cadence；
- 区域 Stem 在乐句边界交叉淡化；
- Reduced Motion 只改变画面，不改变音乐时间线；
- 连续来回乘船时，过门至少有 1.5 秒冷却，避免快速叠加。

### 7.4 湖兽与灯塔守卫

湖兽：

- 低频水冲只在攻击或阶段转换时出现；
- 不使用持续 60–120 Hz 正弦模拟“水下”；
- 排序阶段的节奏由弱到强，DISTINCT 阶段移除重复脉冲；
- 胜利后音乐在 2–4 小节内打开高频和空间，配合退潮。

灯塔守卫：

- 圆号式中声部承担庄严感，避免尖锐铜管；
- 单束灯光阶段让强声部压过弱回应，但不完全静音；
- 玩家证明七个来源后，七音 `BEACON` 以不同音区依次进入；
- 结尾同时保留七个方向的和声，不把它们收束成唯一主音单声部；
- 北岸渡船过门逐渐减少水面节奏，为第三层冰岸留空间。

## 8. 音乐状态机

### 8.1 状态

```text
LOCKED
→ EXPLORE
↔ SAFE / SCRIBE
→ ENCOUNTER_STINGER
→ COMBAT_THINKING
↔ COMBAT_RESOLVING
→ VICTORY / DEFEAT
→ EXPLORE

EXPLORE
→ BOSS_INTRO
→ BOSS_THINKING
↔ BOSS_RESOLVING
→ FLOOR_CLEAR
→ TRANSITION
```

### 8.2 切换规则

| 切换 | 时间 | 规则 |
|---|---:|---|
| 首次解锁 → 探索 | 400–800 ms | 从静音淡入，不补播已错过 SFX |
| 同层区域 | 1–2 小节 | 保持主相位，在乐句边界换 Stem |
| 探索 → 遭遇 | 0.8–1.2 s | 先 Stinger，再垂直增加战斗层 |
| 战斗 → SQL 思考 | 150–300 ms | 音乐降低约 4–6 dB，移除密集节奏层 |
| SQL 执行 | 1–2 小节 | 恢复 Resolve 层；结果 SFX 独立 |
| 战斗 → 探索 | 0.8–1.5 s | 胜利 / 撤退后按拍点交叉淡化 |
| 探索 → Boss | 1.0–2.0 s | 允许专用 Intro，不硬切当前声音 |
| 楼层完成 → 过渡 | 2–4 小节 | 保留共同音或环境尾音 |
| 页面隐藏 | ≤ 100 ms | 停调度并 Suspend；不在后台继续进度 |
| 页面恢复 | 用户设置允许时 | 从安全小节或保存相位恢复，不叠播旧节点 |

当前约 100 ms 的“全停—重启”只可作为兼容起点，不是正式听感目标。

### 8.3 相位与连续性

- 同一楼层的探索、战斗和 Boss 尽量共享可换算的拍点；
- 同区域切换不重置 `barIndex`；
- 播放器保存 `floor`、`region`、`mode`、`barPhase` 和 `focus`；
- 若音频文件无法相位对齐，使用 1–2 秒音乐性淡化，而非 50 ms 硬切；
- 每次模式变化只允许一个过渡事务；快速重复事件合并到最终目标；
- 旧 BufferSource、Timer 和 Gain Automation 必须在切换后释放。

## 9. 循环与文件制作

### 9.1 循环长度

| 状态 | 最低长度 | 推荐长度 |
|---|---:|---:|
| F1 / F2 探索 | 48 s | 64–96 s |
| 普通战 | 40 s | 48–72 s |
| Boss | 48 s | 64–96 s |
| 篝火 / 抄写员 | 32 s | 48–64 s |
| 船程 / 楼层过渡 | 一次性 1–8 小节 | 不循环或有限循环 |

不允许把 8–16 秒主题简单复制四次满足时长。

### 9.2 循环点

- 循环起点和终点落在完整小节；
- 渲染包含 1 小节 Pre-roll 和 Reverb Tail；
- Runtime 文件导出精确 `loopStartFrames` 与 `loopEndFrames`；
- 循环前后波形、DC Offset 和混响尾音连续；
- 若使用交叉淡化，长度建议 30–120 ms，并在 manifest 记录；
- 连续播放 20 次不得出现点击、节拍拖延、音量抽吸或混响突变。

### 9.3 源与运行时格式

```text
assets/
  audio/
    scores/
      f01/
      f02/
    sessions/
      f01/
      f02/
    masters/
      f01/*.wav
      f02/*.wav
    licenses/
    audio-source.json

public/
  assets/
    audio/
      shared/sfx/
      f01/
        explore.ogg
        explore.mp3
        combat.ogg
        combat.mp3
        boss.ogg
        boss.mp3
        manifest.json
      f02/
        ...
```

- Master：WAV / PCM，建议 24-bit，44.1 或 48 kHz；
- Runtime：OGG Vorbis + MP3 回退；不得只提供单一浏览器不稳定格式；
- 导出前去除不可用 Metadata、封面和 DAW 私有块；
- 文件名稳定，不包含“final-final”；
- Master、Runtime 和循环点全部计算 SHA-256。

### 9.4 包体与解码预算

| 类别 | 目标 | 硬门槛 |
|---|---:|---:|
| 每层压缩音乐 | ≤ 2.5 MB | ≤ 4 MB |
| Shared SFX | ≤ 512 KB | ≤ 1 MB |
| 每层专属 SFX | ≤ 256 KB | ≤ 512 KB |
| 移动端同时解码音乐 | 1 主 + 1 过渡 | ≤ 24 MB PCM |
| 桌面同时解码音乐 | 1 主 + 1 过渡 | ≤ 40 MB PCM |

仅加载当前楼层；Boss 音频可在接近 Boss 区或后台空闲时加载。加载失败不得阻塞地图、SQL 或战斗。

## 10. 混音与响度

### 10.1 总线

```text
MASTER
├─ MUSIC
│  ├─ MELODY
│  ├─ HARMONY
│  ├─ RHYTHM
│  └─ MUSIC_FX
├─ AMBIENCE
│  ├─ ROOM / WIND
│  └─ WATER / FIRE
├─ SFX
│  ├─ GAMEPLAY
│  ├─ WORLD
│  └─ CHARACTER
└─ UI
```

当前 `masterGain → musicGain / sfxGain` 可作为起点；正式实现需至少拆出 `AMBIENCE` 和 `UI`，
并让音乐、环境和 SFX 可独立调节。

### 10.2 响度目标

| 内容 | 目标响度 | True Peak |
|---|---:|---:|
| F1 / F2 探索 | `-24 ～ -22 LUFS-I` | ≤ `-3 dBTP` |
| 篝火 / 抄写员 | `-25 ～ -23 LUFS-I` | ≤ `-3 dBTP` |
| 普通战 | `-22 ～ -20 LUFS-I` | ≤ `-2.5 dBTP` |
| Boss | `-21 ～ -19 LUFS-I` | ≤ `-2 dBTP` |
| 一次性 SFX | 按短时响度匹配 | 单文件 ≤ `-3 dBTP` |
| 最终 MASTER | — | Ceiling ≤ `-1 dBTP` |

音乐模式变化的主观响度差原则上不超过 3 LU。紧张感主要来自节奏和编制，不来自突然变响。

### 10.3 Duck 与优先级

- SQL 编辑器打开：MUSIC 降 `4–6 dB`，RHYTHM 再降 `2–4 dB`；
- SQL 结果语音式提示不存在，UI / 命中 SFX 可让 MUSIC 短暂再降 `1.5–3 dB`；
- 名字恢复、死亡、楼层完成拥有最高 SFX 优先级；
- Step、火焰和水面不得触发全局 Duck；
- Duck Attack `20–60 ms`，Release `180–500 ms`；
- 不使用过强压缩制造持续“抽吸”。

### 10.4 频率与抗疲劳

- 音乐低频在约 40–60 Hz 以下逐步衰减，不保留无意义次低频；
- 避免 80–160 Hz 固定音持续超过 4 小节；
- `2.5–5 kHz` 刺耳区控制声部并发与峰值；
- 战斗主旋律长期不高于 `C5 / D5`；
- 探索无持续白噪声、海浪噪声或帽音；
- 水声、纸声和火声均使用短、稀疏、种子化触发；
- 小音箱、手机扬声器和耳机都需试听，不能只在监听耳机上验收。

## 11. SFX 设计

### 11.1 共享事件

| 事件 | 声音身份 | 并发 / 冷却 |
|---|---|---|
| 脚步 | 按石、木、沙、浅水、泥区分的短音 | 同类 ≤ 2；每步一次 |
| 撞墙 | 柔短低音，不惩罚玩家 | 120 ms 冷却 |
| 遭遇 | 约 0.6–1.0 s 引子 | 单实例 |
| 打开 SQL | 纸页 / 终端短音 | 150 ms 冷却 |
| 查询执行 | 向前的短扫频 | 单实例 |
| 查询正确 | 清楚的两音确认 + 命中 | 与攻击分层 |
| 查询错误 | 下行短音，不用刺耳蜂鸣 | 300 ms 冷却 |
| 敌人受击 | 物种材质 + 数据碎片 | 同时 ≤ 3 |
| 玩家受击 | 低中频冲击 + 明确呼吸 | 高优先级 |
| 阶段完成 | 上行 2–4 音 | 单实例 |
| 无掉落 | 不播放大型战利品声 | 可用极短结算点击 |
| 掉落 / 拾取 | 类型不同：恢复、武器、防具、证据 | 单次聚合 |
| 回血 / 休息 | 暖和声 + 火声 | 单实例 |
| 开门 / 捷径 | 机械开合 + 终态落锁 | 单实例 |
| 名字恢复 | ID 音 → 名字和声 → 图鉴印记 | 最高优先级 |
| 胜利 / 死亡 | 明确但不夸张 | 单实例，互斥 |

### 11.2 F1 专属

- 水轮启动；
- 唯一水阀旋转；
- 水位下降；
- 湿墙滴水与纸页浮起；
- 铁门捷径；
- 回执分组；
- 铜印落下 / 裂开 / 停止；
- 档案升降机。

### 11.3 F2 专属

- 浮标依次点亮；
- 船松缆、划行、靠岸；
- 浅水脚步与泥沼脚步；
- 重复水纹 / DISTINCT 收束；
- 树根错连 / 正确闭合；
- 湖兽水冲；
- 退潮；
- 船闸；
- 七道人影；
- 灯塔单束 / 七束；
- 北岸结冰与渡船。

### 11.4 SFX 语义约束

- 一个语义事件只由 `FeedbackDirector` 触发一次；
- 同一状态不能由 Scene、UI 和领域层各播放一遍；
- 死亡后不补播尚未触发的掉落或胜利声音；
- 随机无掉落不播放宝箱音；
- Reduced Motion 不自动静音关键 SFX；
- 静音状态下全部状态仍可通过画面、文字和焦点理解。

## 12. 环境音

### 12.1 F1

- 火焰：短小木裂声，平均间隔 2–6 秒；
- 排水：方向性水滴 / 流水点状事件，不使用完整连续水噪；
- 水轮：可操作附近才出现的低音木轴节奏；
- 档案：极稀疏纸页和链条；
- 安全区：减少机械声，保留火和少量房间尾音。

### 12.2 F2

- 海面：稀疏浪拍，不是全程宽频白噪声；
- 木码头：偶发绳索和木板声；
- 沼泽：低密度蛙鸣 / 气泡，不提示具体怪物答案；
- 灯塔：旋转机构按节拍出现，不持续嗡鸣；
- 风：只作过渡或远景事件，强度不覆盖旋律和 SQL。

环境音同时活动上限建议 2 个近景 + 1 个远景。区域切换使用 0.8–2 秒淡化。

## 13. 浏览器实现

### 13.1 首次用户手势

浏览器通常禁止无手势自动播放。正式流程：

```text
页面加载：音频未解锁，游戏可玩
→ 显示非阻塞“点击 / 按键启用声音”
→ pointerdown / keydown / touchend
→ 创建或 Resume AudioContext
→ 从当前楼层和状态淡入
→ 保存用户静音与音量偏好
```

- 不用全屏 Modal 阻塞首次移动；
- 若第一次解锁失败，保留按钮并等待下一次明确手势；
- Safari / iOS 恢复后可能再次需要手势，UI 必须显示状态；
- 解锁后不补播过去的脚步、对话、拾取或战斗事件；
- iframe 需检查 `allow="autoplay"` 条件，但不能依赖宿主页一定提供。

### 13.2 播放器职责

建议拆分：

```text
AudioDirector
├─ MusicStateMachine
├─ MusicAssetLoader
├─ BusMixer
├─ SfxPlayer
├─ AmbienceDirector
└─ AudioLifecycle
```

职责边界：

- 游戏领域只发送语义事件，不直接操作节点；
- MusicStateMachine 只决定目标楼层、地区、模式和 Focus；
- Loader 负责格式选择、获取、解码、缓存和取消；
- Mixer 负责 Gain、Filter、Duck 与 Master；
- SfxPlayer 负责优先级、并发和冷却；
- Lifecycle 负责用户手势、`visibilitychange`、Suspend、Resume 和 Dispose。

### 13.3 加载与缓存

- 进入楼层时加载探索音乐和共享 SFX；
- 战斗音乐在探索期间空闲加载，Boss 音乐接近 Boss 区再加载；
- 使用 `AbortController` 取消已离开楼层的下载；
- 解码失败时尝试备用格式；
- 同一文件只维持一份解码 Promise；
- 切层后释放上层不再需要的 AudioBuffer；
- 失败进入项目内合成降级，并记录一次非敏感遥测到本地调试日志；
- 不上传用户操作、答题或音频状态。

### 13.4 页面生命周期

- 页面隐藏：停止 Scheduler，淡出并 Suspend Context；
- 页面恢复：校验目标 Scene，清理过期 Source，再从安全小节淡入；
- 不在隐藏页面继续推进音乐拍点或触发环境随机事件；
- `dispose()` 必须停止 Timer、Source、Automation，移除监听并断开节点；
- 快速重开游戏不得出现两个 AudioContext 或双重音乐；
- 静音应停止不必要调度，不只把 Master Gain 设为 0 后继续耗能。

## 14. 降级策略

按以下顺序降级：

1. 备用编码格式；
2. 取消非关键环境层和 Music FX；
3. 使用单一完整混音而非多 Stem；
4. 使用项目内简化程序化主题；
5. 完全静音并保留全部视觉 / 文字反馈。

程序化降级约束：

- 只使用正弦、三角或带限低谐波波形；
- 无持续低频 Pad；
- 无持续噪声；
- 同时音乐声部 ≤ 3；
- 只播放当前楼层主题轮廓，不假装正式混音；
- 在 UI 中不显示错误或打断游戏。

## 15. 可访问性

- Master、Music、SFX、Ambience 分别可调；最低 MVP 至少提供 Music / SFX 两路；
- 提供一键静音和明确当前状态；
- 游戏机制不能依赖听声辨方向、节奏输入或音高；
- 水位、浮标、船闸、怪物攻击、名字恢复和死亡都有视觉与文字等价信息；
- 可选“低刺激音频”模式：战斗减 2 dB、去除高频短音、缩小动态范围；
- Reduced Motion 与静音互不绑定；
- 系统 `prefers-reduced-motion` 只改变视觉动画；音频强度设置由用户决定；
- 焦点进入 SQL 编辑器时自动 Duck，但屏幕阅读器焦点切换不会重复触发 SFX；
- 音量控件可键盘操作、有可读标签，并保存本地偏好。

## 17. 旧设计保留 / 改造 / 废弃矩阵

| 旧项 | 决策 | 目标处理 |
|---|---|---|
| Web Audio 生命周期、手势解锁和页面隐藏 Suspend | `KEEP` | 保留并补充可见解锁状态与重复上下文测试 |
| `floor / region / mode / focus` 音乐状态 | `KEEP` | 继续作为 AudioDirector 输入 |
| SQL `thinking / resolving` Duck | `TRANSFORM` | 改为 4–6 dB、分离节奏层，并按响度验收 |
| F1 Mozart K.265、F2 Handel《水上音乐》方向 | `IMPLEMENTED` | 项目独立音符录入、编配、合成、导出与哈希已进入 Manifest |
| 实时振荡器生成全部正式音乐 | `TRANSFORMED` | F1/F2 改为离线渲染循环；实时仅作 SFX、F3–8 与解码失败降级 |
| 长时间持续低音 Bed | `REMOVE` | 以短低音、和声接力和房间尾音保持连续 |
| 8–16 秒短句重复 | `REMOVE` | 最低 40–48 秒，推荐 64–96 秒 |
| 约 100 ms 全停 / 重启模式切换 | `REMOVE` | 相位保持或 0.8–2 秒音乐性交叉淡化 |
| 随机换轨导致主题突然跳转 | `TRANSFORM` | 只在乐句边界、按状态和 Seed 选择变体 |
| 探索持续白噪声 / 高频帽音 | `REMOVE` | 环境和节奏改为短、稀疏、低并发事件 |
| 战斗靠更尖锐、更响制造压力 | `REMOVE` | 靠速度、切分、低音脉冲和声部密度 |
| SQL 打开后音乐完全停止 | `REMOVE` | 保留节拍与和声，降音量和密度 |
| 《赛尔号》战斗音乐变调 | `REMOVE` | 不使用旋律、录音或实质性改编 |
| 公版作曲自动等于录音可用 | `REMOVE` | 六层权利逐项审查 |
| `ATTRIBUTIONS.md` 声称完全原创而代码标记具名改编 | `REMOVE` | 正式 PR 前统一事实、Credit 和 Manifest |
| Open Goldberg / Open WTC | `DEFERRED` | 仅在改选曲并完成具体文件审计时可用 |
| 项目自制合成简化主题 | `FALLBACK` | 无正式音频或解码失败时启用 |

## 18. QA 与验收

### 18.1 自动检查

- 每个音乐与 SFX 文件均在 manifest 且哈希匹配；
- 不存在未登记 MP3、OGG、WAV、MIDI、SF2、SFZ、采样或 IR；
- Runtime 文件有两种浏览器兼容格式或明确能力检测；
- 循环帧在文件范围内并落在完整小节；
- 20 次循环无采样缺口和 DC 点击；
- 各模式响度与 True Peak 在目标范围；
- 页面隐藏后无 Scheduler、Timer 和 Source 继续增长；
- 连续重启游戏不会创建双重 AudioContext 或叠播；
- 静音后不进行无意义音乐调度；
- 当前楼层不会一次解码两层全部音乐。

### 18.2 状态机验收

逐项录屏 / 录音：

1. 首次无手势进入，游戏可玩且音频状态明确；
2. 第一次点击成功淡入；
3. F1 登记厅 → 排水渠 → 篝火，音乐连续；
4. 探索 → 普通战 → SQL 思考 → 正确 / 错误 → 探索；
5. 登记官阶段转换、死亡、复活和撤退；
6. F1 升降机 → F2 码头；
7. F2 码头 → 短船 → 月影湖 → 沼泽；
8. 湖兽胜利、退潮和船闸回航；
9. 灯塔守卫单束 → 七束 → 北岸渡船；
10. 页面切后台 30 秒后恢复；
11. 静音、分总线音量、Reduced Motion 和低刺激音频。

### 18.3 浏览器矩阵

最低测试：

- Chrome / Chromium 当前稳定版；
- Safari 当前稳定版与 iOS Safari；
- Firefox 当前稳定版；
- 博客 iframe；
- 桌面键鼠与移动触屏；
- 蓝牙耳机断开 / 重连；
- 页面后台、系统锁屏和 AudioContext Interrupted。

### 18.4 主观试听

至少 5 名未参与制作的试听者，在同一音量校准下回答：

- F1 是否温暖但不甜腻？
- F1 连续步行 10 分钟是否出现嗡嗡、断续或烦躁？
- F2 是否在一分钟内比 F1 更开阔？
- 战斗是否更急促但不更刺耳？
- SQL 输入 30–60 秒时音乐是否仍可接受？
- 登记官和灯塔守卫是否属于各自楼层主题？
- 短船是否像同一首音乐中的过门，而不是重启？
- 名字恢复是否比普通拾取更重要？

停止条件：

- 2 名以上试听者主动提到持续蜂鸣、刺耳或循环过短；
- 音乐让玩家倾向于直接静音才能写 SQL；
- 战斗只被感知为“更响”；
- F1 / F2 像两首无关歌单；
- 循环点、区域切换或 SQL Duck 能被明显听出为技术故障。

## 19. 发布验收

音频进入生产版本前必须同时满足：

- 作品、谱源、转写、编曲、表演、录音和第三方输入均可追溯；
- 不使用不明版权录音、MIDI、SoundFont、采样或商业游戏音乐；
- `audio-source.json`、运行时 Credit 和 `ATTRIBUTIONS.md` 一致；
- F1 / F2 完整状态机通过浏览器矩阵；
- 响度、峰值、循环和包体通过；
- 10 分钟探索与 5 分钟战斗压力试听通过；
- 静音、低刺激、Reduced Motion、页面隐藏与解码失败降级通过；
- 音频失败不阻塞 SQL、战斗、存档或地图切换。

## 20. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 目标曲目找不到可用现代录音 | 项目自行转写、编曲和合成 / 录制，不从平台抓取 |
| 实时合成继续产生蜂鸣和断续 | 正式音乐优先离线渲染，Web Audio 负责播放与混音 |
| 预渲染增加包体和解码内存 | 每层延迟加载，只保留当前与过渡 Buffer |
| 古典旋律变成轻浮童谣 | 使用 Dorian / Mixolydian、新和声和关卡节奏重新解释 |
| 战斗音乐妨碍思考 | SQL Focus 自动 Duck 并移除密集节奏层 |
| 环境音形成噪声床 | 稀疏事件、并发上限和区域距离控制 |
| 两层主题失去联系 | F1 → F2 过渡保留共同低音 / 间隔并在节拍上换拍号 |
| 浏览器自动播放限制 | 非阻塞解锁 UI、第二手势重试和无声可玩降级 |
| 权利文档与代码漂移 | Manifest、Credit、Attributions 作为发布一致性门禁 |
| “公版”地区判断复杂 | 发布前记录目标地区依据；无法确认则不使用 |

## 21. 制作顺序与 Checkpoint

1. **A0 事实统一**：决定 F1 / F2 是具名公版改编还是原创主题，修正权利描述；
2. **A1 谱源与转写审计**：锁定可用谱源、项目转写和编曲责任；
3. **A2 30 秒方向稿**：F1 探索、F1 战斗、F2 探索、F2 战斗；
4. **A3 抗疲劳试听**：每段扩展到最小循环长度，完成 10 分钟压力试听；
5. **A4 F1 全状态**：篝火、区域、普通战、登记官、升降机；
6. **A5 F2 全状态**：码头、船程、湖 / 沼泽、湖兽、灯塔；
7. **A6 SFX 与混音**：共享事件和两层专属事件；
8. **A7 浏览器集成**：解锁、加载、状态、生命周期、降级；
9. **A8 权利与发布审计**：文件哈希、Credit、Attributions、包体和验收报告。

每个 Checkpoint 先通过主观试听和权利检查，再进入工程集成。任何“听起来像目标曲目”的文件都不能
绕过来源审计。
