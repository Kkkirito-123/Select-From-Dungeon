## 1. 产品定义

### 1.1 一句话

一款可以直接嵌入博客的轻量像素冒险：玩家通过真实 SQLite 查询调查世界、改变环境并找回自己的
名字，而不是把 SQL 当成脱离场景的答题卡。

### 1.2 玩家承诺

完成前两层后，玩家应同时获得三种进展：

1. **知识进展**：能独立写出第一层单表查询、空值与聚合，以及第二层排序、去重和连接；
2. **空间进展**：记住两个真正不同的地点，并理解至少一条捷径为什么值得返回；
3. **人物进展**：相信抄写员，同时开始怀疑“恢复玩家”是否等于“恢复唯一的旧身份”。

### 1.3 核心主题

> 学会查询，不只是更了解数据库，也是在逐渐了解自己。

玩家不是等待找回的唯一旧版本，而是许多删除、覆盖、错误和修正留下的历史集合。前两层只提出并
验证前两步：

- 第一层：当前记录里没有玩家，但玩家拥有有效恢复权限；
- 第二层：与玩家有关的不止一个旧名字，它们不能被简单去重成一个人。

## 2. 用户与使用场景

| 用户 | 核心需要 |
|---|---|
| SQL 初学者 | 知道为什么使用某个语句，并看见查询对世界产生结果 |
| 面试复习者 | 通过完整语句、真实结果和错误反馈复习高频知识 |
| 博客试玩者 | 无安装、短时间进入、键盘和触屏都能玩 |
| 像素冒险玩家 | 有地点、人物、悬念、回访和 Boss，而不是换色题库 |
| 项目作者 | 内容可以按楼层独立制作、测试、替换素材和发布 |

典型单次体验：

- 首次试玩：20–35 分钟完成第一层；
- 第二层：30–45 分钟；
- 单场 SQL 战斗：1–4 分钟；
- 单次纯走路段：约 15 秒以内；
- 失败后：30 秒内回到可复盘和再次挑战的状态。

## 3. MVP 范围

### 3.1 必须完成

- 第一、第二层完整可玩；
- 两层拥有不同地图轮廓、地形、交通、环境状态和音乐情绪；
- 第一层完整叙事、怪物、SQL、区域事件、Boss 和回访；
- 第二层完整叙事、怪物、SQL、开船/渡点、区域 Boss、楼层 Boss 和回访；
- 抄写员与篝火在职责和地图表现上可区分；
- SQL 正确结果至少用于攻击、调查、机关和路线四类行为；
- 怪物击败前只显示 ID，击败后强反馈恢复名字并进入图鉴；
- 普通怪大概率无随机掉落；随机掉落只保留低概率即时恢复品；
- 关键武器、钥匙、剧情证据和图鉴条目为确定性奖励；
- 第三方素材按来源独立存放，保留许可证、来源、哈希和衍生记录；
- 保持离线、本地 SQLite、博客 iframe、30 FPS、Reduced Motion 和触屏。

### 3.2 本轮不做

- 不实现第三至八层的新地图和新剧情；
- 不更换 Phaser；
- 不改为横版平台动作游戏；
- 不增加联网 Agent、账号、云存档和动态剧情；
- 不新增多结局；
- 不实现开放海洋、真实浮力或自由驾驶物理；
- 不用扩大地图代替内容密度；
- 不把商业游戏拆包素材、现代商业录音或来源不明 MIDI 放入仓库；
- 不为每层增加一套新操作键；
- 不重排当前八层课程。

## 4. 产品支柱

### 4.1 SQL 是世界行为

SQL 的结果必须落到至少一种可见后果：

| 查询意图 | 世界行为 |
|---|---|
| 读取 | 看见名字、字段、弱点、位置或日志 |
| 筛选 | 选中正确水闸、怪物、航线或证据 |
| 空值判断 | 发现“确实没有记录”，而不是“尚未调查” |
| 聚合 | 对齐回执、恢复权限或群体信号 |
| 排序 / 截取 | 选择最强信号、最近浮标或优先目标 |
| 去重 | 识别不同来源，而不是盲目删除重复 |
| 连接 | 把怪物、房间、岛屿、装备和信号连接成事实 |

任何主要任务都不能只在成功后显示“伤害 +N”。

### 4.2 地图是地点

地图必须让玩家通过以下内容辨认位置：

- 独有远景和主地标；
- 路宽、高低差、岸线或墙体轮廓；
- 具有用途的物件；
- 环境状态变化；
- NPC 或怪物生态；
- 回访后的新事件。

颜色、区域标签和随机小图标只能辅助，不能承担地区身份。

### 4.3 捷径是理解奖励

捷径必须满足：

1. 玩家早期从正面看见；
2. 绕行后从背面打开；
3. 打开后 2–3 分钟内有自然回访目标；
4. 回到旧区域后发生人物、环境、剧情或奖励变化。

没有回访内容的捷径不进入正式关卡。

### 4.4 剧情由行动证明

剧情不以“卡片数量”验收。至少需要：

- 一条查询结果；
- 一处地图状态变化；
- 一次角色行动；
- 一次 Boss 对事实的错误处理；
- 一次玩家通过 SQL 纠正世界。

### 4.5 失败是学习循环

死亡不是 Run 结束：

```text
生命归零
→ 回到最近休息篝火；未休息则回出生安全区
→ 玩家恢复满生命；怪物保留死亡瞬间 HP，但本场未提交阶段与世界状态回到入战快照
→ 查看本场错误与本层知识复盘
→ 再次挑战或撤退
```

## 5. 核心循环

```text
看见环境异常
→ 调查表和字段
→ 写出完整 SQL
→ 得到真实 SQLite 结果
→ 世界发生改变或进入战斗
→ 获得名字、证据、路线或确定奖励
→ 通过捷径回访旧区域
→ 抄写员整理本层问题
→ 击败 Boss
→ 自动进入下一层
```

节奏预算：

- 不连续出现三场同类型战斗；
- 两次战斗之间至少一个非战斗节拍；
- 每层至少一个目标可以避战；
- 随机遭遇只复习已学语法；
- Boss 不要求重复完全相同的正确查询；
- 演出不阻塞输入超过合理时长，并支持跳过与 Reduced Motion。

## 6. 操作与界面

### 6.1 操作

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动 | `WASD` / 方向键 | 方向控件 |
| 调查 / 拾取 / 休息 | `E` | 交互按钮 |
| SQL 终端 | `Q + S` | SQL 按钮 |
| 背包 | `B` | 背包按钮 |
| 返回 | `Esc` | 关闭按钮 |
| 提示 | `H` | 下一条提示 |
| 执行 SQL | `Ctrl + Enter` | 执行按钮 |

战斗必须提供“撤退到复活点”按钮。撤退不消耗永久物品，但放弃本场未结算进度。

### 6.2 SQL 编辑器

编辑器必须展示：

- 本回合目标；
- 返回字段、数据表、过滤值和需要的别名；
- 本题主表和关联表；
- 完整字段列表；
- SQL 关键词、表、字段和别名补全；
- 由短到长的四级提示；
- SQLite 真实结果与错误；
- 为什么正确或为什么未命中。

身份字段遵循“最后一击揭示”契约：未发现怪物的世界标签、战斗标题、任务目标和前三阶段
不得直接显示真名；如果课程必须查询 `name`，该查询只能出现在本怪物的最终正确阶段，查询成功、
生命归零、姓名恢复与图鉴写入必须作为同一笔不可分割的结算发生。玩家自由查询得到的数据不应
提前改变世界显示或永久图鉴；后续版本若开放自由数据库沙盒，则通过只读身份视图返回遮罩值，
不以隐藏真实答案的方式破坏 SQL 的真实性。

任务文案必须明确归属，禁止写：

> 查询 id = 12 的 name 与 sector。

应写：

> 连接 `monsters AS m` 与 `rooms AS r`，返回怪物字段 `m.name`，并把房间字段
> `r.name` 命名为 `room_name`；只保留 `m.id = 12`。

### 6.3 界面层次

界面只保留三个主要层级：

1. 地图与角色；
2. 当前目标、生命、装备和交互；
3. 打开时占据主注意力的 SQL、背包、篝火、图鉴或剧情面板。

短暂反馈卡移动三步后消失；剧情关键选择和新名字恢复必须由玩家确认或在图鉴中可追溯。

## 7. 世界与人物

### 7.1 无键者

- 当前居民表中没有唯一主键记录；
- 能被篝火恢复；
- 身体会随知识掌握和装备逐渐显形；
- 不通过“找回唯一旧名字”完成成长，而通过理解多份历史形成自己。

### 7.2 抄写员

人物基调：

- 温柔，但不替玩家做决定；
- 是全游戏唯一稳定的温暖；
- 通过“记得、诚实、等待”建立信任；
- 不代写 SQL；
- 不用赞美掩盖错误。

目标职责：

- 解释当前调查问题；
- 整理证据和《失名录》；
- 告知名字恢复和图鉴变化；
- 进行本层答案复盘；
- 通过行动推进人物关系。

她不是篝火功能的拟人按钮。第一层在出生登记厅工作，第二层通过实体升降机抵达码头记录台。

### 7.3 篝火

职责：

- 休息并恢复满血；
- 更新默认复活点；
- 整理装备和恢复品；
- 查看本层答题复盘；
- 形成安全区。

第一、第二层各保留：

- 一个不可拾取、无休息菜单的出生安全锚点：F1 为低燃余烬环，F2 为港口航灯；它只承担初始和
  无已休息篝火时的兜底复活；
- 中段实体篝火；
- 后段实体篝火。

只有中、后段两处属于可按 `E` 休息的实体篝火。出生锚点可以有火光或灯光，但不得计作第三座
篝火，也不得打开休息菜单。篝火数量不能为了画面热闹随意增加。

### 7.4 登记官

第一层 Boss。它不是邪恶生物，而是拒绝处理“0 行但恢复权限有效”的异常程序人格。它相信无当前
记录就不存在，玩家通过查询证明其判断规则不完整。

### 7.5 灯塔守卫

第二层 Boss。它试图把七个旧名字按频次压成一个“最可能真名”，从而让群岛保持安静。玩家必须
证明不同来源不能因恢复轨迹相同而被覆盖。

## 8. 学习系统

### 8.1 课程边界

当前课程顺序保持：

| 层 | 本层知识 |
|---:|---|
| 1 | `SELECT / FROM / WHERE / AND / IS NULL / COUNT / GROUP BY / HAVING` |
| 2 | `ORDER BY / LIMIT / DISTINCT / INNER JOIN / ON / LEFT JOIN / IS NULL / 综合 JOIN` |
| 3 | JOIN 深化、自连接、三表、`UNION` |
| 4 | 子查询、CTE、递归 |
| 5 | 窗口函数 |
| 6 | 写操作、约束、事务 |
| 7 | 索引与执行计划 |
| 8 | MVCC、锁、隔离、建模、复制、分片、安全与综合事故 |

第三至八层只保留现有运行内容，本轮不写新的详细剧情。

### 8.2 一题四层提示

1. **意图**：告诉玩家要查什么；
2. **结构**：告诉玩家使用哪些语句块；
3. **字段**：给出完整表名、别名、字段和条件值；
4. **完整语句**：最后才显示答案。

提示不会缩短成无法独立执行的“核心算法”。玩家需要练习完整 SQL。

### 8.3 判定

必须同时满足：

- SQLite 可以执行；
- 结果与目标结果一致；
- 本题要求的语法特征出现；
- 只读题不允许写入；
- 允许等价空格、大小写和安全别名写法；
- 错误不会被静默改写为正确答案。

## 9. 战斗系统

### 9.1 进入战斗

- 触碰可见课程怪物自动进入；
- 2% 移动概率触发已学内容的随机遭遇；
- 出生点、篝火安全区和演出期间不触发；
- 击败后的课程怪不重新生成；
- 随机怪不承担新语法和主线证据。

### 9.2 回合

```text
怪物预告意图
→ 玩家打开 SQL
→ 查询成功：播放强命中特效，推进阶段
→ 查询失败：解释错误，怪物反击
→ 怪物归零：恢复名字、经验结算、低概率掉落
```

### 9.3 数值

- 初始生命：2；
- 普通怪伤害：1；
- 精英和区域 Boss：1–2；
- 楼层 Boss：通过多阶段形成压力，不依赖一次秒杀；
- 普通怪经验：1；
- 高级怪经验：3；
- 区域/楼层首领经验：5；
- 升级阈值继续使用当前 `2、4、6、8...` 进度契约。

### 9.4 击杀反馈

必备序列：

1. 屏幕短促停顿；
2. 怪物轮廓碎成数据行；
3. 查询结果中的目标行高亮；
4. `ID #xxx → 名字` 大字恢复；
5. 图鉴盖章；
6. XP 数字飞向状态栏；
7. 掉落或“没有掉落”明确结算；
8. 地图相关状态变化。

Reduced Motion 下使用闪白、颜色和文字顺序表达相同语义，不依赖震动和位移。

## 10. 怪物、身份与图鉴

### 10.1 分类

| 分类 | 作用 | SQL 难度 | 掉落 |
|---|---|---|---|
| 普通怪 | 基础题和生态 | 一阶 | 98% 无随机掉落 |
| 小型精英 | 两段复合题 | 二阶起 | 5% 恢复品 |
| 区域 Boss | 改变地图状态 | 本层复合题 | 10% 恢复品 + 确定剧情结果 |
| 楼层 Boss | 回答本层问题 | 本层综合 | 确定钥匙、证据和进度 |

### 10.2 身份显示

击败前：

```text
ID #001
HP
动作意图
```

击败后：

```text
史莱姆
ID #001
栖息地、已见字段、弱点、掉落和本次答案
```

图鉴跨 Run 保存名字发现，但不会把未学答案直接写给新 Run。

身份状态机：

```text
UNKNOWN（仅 ID）
→ FINAL_QUERY_PENDING（最终 name 查询尚未通过）
→ REVEAL_SETTLEMENT（查询命中、击杀、演出、图鉴原子结算）
→ DISCOVERED（真名与 ID 常亮）
```

死亡、撤退、刷新页面或读档不得留下“怪物未死但名字已永久发现”的中间状态。

## 11. 成长、装备与掉落

### 11.1 装备

- 12 格装备背包；
- 三格恢复品；
- 战斗外可更换和丢弃；
- 武器改变伤害和热量，不跳过题目阶段；
- 防具提供额外护甲生命，并改变角色外观；
- 获得物品时必须解释用途和数值变化。

### 11.2 掉落

随机掉落按每个候选独立计算，同一战斗不重复：

- 普通怪：2% 即时恢复品；
- 小型精英：5%；
- 区域 Boss：10%；
- 楼层 Boss：0% 随机掉落；
- 普通怪、精英和 Boss 不随机掉落武器或防具；
- 关键武器、防具、钥匙和剧情物品放在确定宝箱、课程奖励或 Boss 结算中。

### 11.3 前两层确定奖励

| 来源 | 奖励 | 用途 |
|---|---|---|
| 第一层 SELECT | 过滤弓 | 强化 WHERE 查询伤害 |
| 第一层 IS NULL | 空值提灯 | 强化空值题并恢复角色光源外观 |
| 第一层聚合区 | 聚合战锤 | 强化聚合阶段 |
| 第一层 Boss | 第一层钥匙、《失名录》第一页 | 开启升降机 |
| 第二层 ORDER BY | 雷序军刀 | 强化排序阶段 |
| 第二层古树桥 | 关系链刃 | 强化 JOIN |
| 第二层支线宝箱 | 藤甲 | 1 点护甲 |
| 第二层 Boss | 第二层钥匙、七名记录页 | 开启北岸渡船 |

## 12. 地图与 Seed

### 12.1 稳定边界

- 新 Run 使用 `48×36 / generator-v5`；
- 关键区域、Boss、篝火、捷径和交通位置固定；
- Seed 只改变非关键装饰、普通怪池、可选宝箱和局部路线细节；
- Seed 不改变课程顺序、主线证据和剧情结论；
- 旧 `64×48 / generator-v4` 仅用于兼容存档。

### 12.2 两层轮廓

第一层：

```text
登记厅 → 排水渠 → 水轮大厅 → 无名宿舍
   ↑          ↓          ↓
   └──捷径── 余烬仓库 → 聚合档案室 → 登记官大厅
```

第二层：

```text
潮汐码头 ──短船程── 白沙浅滩 ── 古树桥
    ↑                      │
  船闸捷径              芦苇沼泽
    │                      │
  沉水村落 ── 湖兽区 ── 灯塔岛
```

两层不是相同走廊换色：

- 第一层以室内环廊、门、排水高低差和回到登记厅为主；
- 第二层以开放水面、岸线、短船转场、岛屿选择和潮位变化为主。

## 13. 视觉设计系统

视觉主题不是霓虹数据库界面，而是“被数据库规则侵蚀的手工童话遗迹”。

### 13.1 共用规则

- 世界素材：16×16 逻辑网格，以 2× 整数倍显示；
- UI 与 SQL 字体保持高可读，不对正文使用难读像素字；
- 前景、角色、交互物、地面和远景分层；
- 水面、火焰和灯光只做低密度循环；
- 禁止随机装饰覆盖路线和交互对象；
- 禁止仅靠颜色区分水、墙、毒和安全区。

## 15. 音频

### 15.1 情绪曲线

```text
第一层：低处、温暖、犹疑，像家中仍亮着的一盏灯
→ 第二层：开阔、流动、带冒险感，但潮声下有不安
→ 后续：逐层扩大编制
→ 第八层：庄严、辉煌、凄凉，像落日照在空王城
```

### 15.2 当前与目标

- `CURRENT`：第一、第二层使用项目基于公版主题独立转写、编配、合成并导出的连续 OGG / MP3；
- `REMOVED`：持续蜂鸣、短句断续、响度过低或刺耳的旧实时音乐床；
- `FALLBACK`：第三至八层与解码失败路径继续使用轻量 Web Audio 配方，事件 SFX 实时生成。

录音规则：

- 原作进入公版不代表现代录音进入公版；
- 禁止从音乐平台、唱片、视频和商业游戏提取；
- 只接入明确 `CC0` 或可靠 Public Domain 的录音；
- 找不到对应曲目授权时，继续使用自制编配，不伪造许可；
- 音频按楼层延迟加载；
- SQL 面板打开时降音量但不中断；
- 战斗使用同主题更急促的编配，不用噪音墙；
- 胜利、名字恢复、捷径和篝火使用短 SFX。

## 16. 状态、存档与管理员模式

### 16.1 存档

## 17. 可访问性与性能

- 目标 30 FPS；
- 页面隐藏时暂停；
- 只加载当前楼层素材和下一次必要转场资源；
- 像素纹理关闭平滑；
- Reduced Motion 保留全部状态语义；
- 所有按钮可键盘聚焦；
- 不只依赖颜色表达生命、毒、路线和错误；
- SQL 字号优先可读；
- 320 px 宽度能完成核心流程；
- iframe 与触屏可操作；
- 外部图片或音频加载失败时有低成本降级表现；
- 主包性能优化晚于两层功能完成，但不能一次打包八层素材。

## 20. 验收标准

### 20.1 第一层

- 无 HUD 截图可以辨认登记厅、排水渠、余烬仓库和 Boss 大厅；
- 至少一次 SQL 降低水位；
- 捷径回到登记厅后发生居民轮廓、抄写员和 Boss 状态变化；
- 玩家能复述“0 行但恢复权限有效”；
- 所有必修题任务表述字段归属清楚；
- 登记官 Boss 必须通过规则阶段体现“0 行但恢复权限有效”，不能只是给普通软泥敌人增加 HP。

### 20.2 第二层

- 无 HUD 截图可以辨认码头、浅滩、泥沼、沉水村落和灯塔；
- 至少一次短船或渡点转场；
- 湖兽改变潮位，打开船闸捷径；
- 七盏浮标与七道人影成为必然场景事件；
- 玩家能复述“多个名字不是简单重复”；
- JOIN 题明确表、别名、字段归属和连接条件。

### 20.3 全局

- 篝火与抄写员能被玩家说出不同作用；
- 怪物击败前只有 ID，击败后有强名字恢复反馈与图鉴；
- 普通怪统计上大概率没有随机掉落；
- 关键奖励不会因随机、背包满或死路丢失；
- 两层完整路径、死亡、撤退、复活、存档、读档可用；
- 自动化测试、生产构建和浏览器试玩通过；
- 320 px、触屏、iframe、Reduced Motion 通过；
- 素材来源、许可证和哈希完整；
- 真人试玩确认地图不是“同一迷宫换色”。

## 21. 停止条件

出现任一情况，停止继续铺内容并返工：

- 地图仍主要由颜色与文字标签区分；
- 外部素材进入 `public/` 但没有来源与许可证；
- SQL 成功仍只表现为伤害；
- 通过增加路程延长单层时长；
- 第一层未通过试玩就开始第三层新内容；
- 抄写员仍复制在每个篝火旁；
- 捷径开启后没有返回理由；
- 为视觉升级破坏 SQL 可读性、窄屏或 30 FPS；
- 现代商业录音被误当成公版；
- 存档版本变化没有迁移测试。

## 22. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 两层内容过厚导致范围扩大 | 固定课程和操作，每层只增加一个主要地图状态系统 |
| 外部素材拼盘感 | 一套逻辑网格、统一色板、只选少量素材并制作衍生图集 |
| 原始图集未知布局 | 保留原包，使用可复现裁切脚本生成楼层图集 |
| 音频授权难 | 找不到明确授权就继续自制，不从平台抓取 |
| 剧情仍像卡片 | 把剧情绑定环境变化、人物移动和 Boss 规则 |
| 新环境状态污染存档 | 单独版本化，提供旧存档默认值和迁移测试 |
| 巨型 `DungeonScene` 继续膨胀 | 把楼层内容和环境渲染拆出专用模块 |
| 美术提高包体 | 当前楼层延迟加载，原始素材不进入生产包 |
