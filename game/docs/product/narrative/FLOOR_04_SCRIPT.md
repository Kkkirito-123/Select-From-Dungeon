# 第四层逐事件叙事脚本：三相升炉

> 脚本版本：`v1.1`
>
> 状态：`RUNTIME V1.1 VERIFIED`
>
> 对应产品版本：`MVP 2.2 — The Ember Echo`
>
> 目标时长：首次 `30–45` 分钟
>
> 课程：`标量子查询 / IN / EXISTS / 相关子查询 / CTE / 递归 CTE`
>
> 最近更新：`2026-07-29`

## 0. 本轮边界

第四层负责第一次明确回访第一层，但不让玩家完整重跑第一层。玩家在升炉中发现一段被反复调用的
“地下余烬档案”残响，并由此确认前三层异常并非彼此独立。

本轮完成：

- 火、冰、雷三个功能和视觉不同的探索区；
- 一个阻断中后段交通的中层首领 `ID #044`；
- 击败中层首领后才出现的“回燃门”；
- 一个压缩的第一层残响隐藏区域；
- 确定获得的专属护甲“回燃衣”；
- 装备护甲后的玩家像素外观变化；
- 元素王和通往第五层的升炉结算。

本轮不做：

- 返回完整第一层地图；
- 在两层之间自由来回刷怪或重复领奖；
- 永久账号衣柜和局外收集；
- 随机掉落“回燃衣”；
- 独立换装菜单或新存档 Schema；
- 在本文件中重复维护第五至八层对白；后续剧情以各层独立剧本与八层总精排为准。

## 1. 本层叙事目标

本层问题：

> 火、冰、雷三种异常是三场灾难，还是同一次命令的不同结果？

本层结论：

> 三种异常沿同一条依赖链回到一条尚未完成的历史命令；第一层的火也是这条命令持续调用的结果。

离层悬念：

> 如果所有异常都来自同一命令，谁在阻止它完成，又为什么不选择直接回滚？

## 2. 地图结构：三相环路

| 区域 | 空间形态 | 核心玩法 | 主要地标 | 交通结果 |
|---|---|---|---|---|
| 烈焰熔炉 | 宽检修道、黑铁炉壁、暗红熔沟 | 标量子查询、命令源定位 | 葬火接收炉、命令源炉、熔沟篝火 | 打开前→中通路 |
| 寒霜冰库 | 镜面大厅、冻结铜管、成组冰槽 | `IN`、相关子查询、中层首领 | 冻结依赖阵列、炉主平台、检修台篝火 | 击败 `ID #044` 后进入后区 |
| 雷晶核心 | 环形执行厅、依赖脊柱、金色导轨 | `EXISTS`、CTE、递归链 | 三相依赖脊柱、回燃门、元素王执行环、垂直升炉 | 击败 `ID #039` 后升层 |

这里的交通门有明确叙事作用：

- 前→中：从单个内层结果进入集合和逐行依赖。
- 中→后：被 `ID #044` 实体封锁，胜利后自动转入雷晶核心。
- 回燃门：只进入同层隐藏房间，不切换楼层状态。
- 垂直升炉：只在最终 Boss 完成后激活并自动进入第五层。

## 3. 中层首领：`ID #044`

制作身份：炉主；击败前玩家只见 `ID #044`。

设计职责：

1. 让第四层中段拥有明确高潮，不连续做六组相似课程怪；
2. 复合检查前三种子查询的基础理解；
3. 物理封锁寒霜冰库通向雷晶核心的区域门；
4. 胜利后显出回燃门，使第一层回访成为探索奖励；
5. 不取代最终 Boss，也不掉落随机专属装备。

胜利演出：

- 镜面平台由冷白变为熄灭黑铁；
- 冻结铜管出现一条逆向流动的暗红余烬；
- 雷晶核心方向的交通边界打开；
- 原本“看不见”的回燃门轮廓变为可调查的封印。

短对白：

> 抄写员：“它守的不是通往上层的路。”
> 抄写员：“它守着一段被炉心反复调用的第一层记录。”

死亡和撤退：

- 战斗中可以撤退到当前复活点；
- 首领剩余 HP 和已完成阶段保留；
- 未胜利时回燃门保持不可见；
- 胜利状态读档后直接恢复，不重播发奖。

## 4. 第一层联动：回燃残响

### 4.1 为什么不是完整传送回第一层

完整回到第一层会造成三个问题：打断第四层进度、让奖励与怪物状态难以解释、制造长距离重复行走。
因此本版采用“记忆空间”：

```text
第四层后区
→ 看见第一层材质和轮廓
→ 走入一间压缩登记厅
→ 分别调查残响登记台、NULL 床位、无温余烬与依赖返回门
→ 获得回燃衣
→ 原路返回第四层
```

它是第一层被升炉保存的调用结果，不是时间旅行，也不是第二份真实第一层。

### 4.2 开门条件

同时满足：

- `f4-scalar` 完成；
- `f4-in` 完成；
- `f4-exists` 完成；
- `ID #044` 已击败；
- 玩家在实体回燃门旁按 `E`。

未满足时提示必须逐项说明缺失条件，不能只显示“锁住了”。

### 4.3 场景识别

残响房间用第一层的形状语言，而不是第四层换色：

- 小型档案水轮；
- 一张 `NULL` 床位；
- 低矮余烬登记炉；
- 地下档案的暗青石墙；
- 放置“回燃衣”的确定奖励束。

场景规模小于普通区域，不刷新怪物、不放篝火、不触发随机遭遇。

四个实体交互点承担不同职责：

- 残响登记台：说明水轮只是被保存的调用轮廓，姓名并未被恢复；
- `NULL` 床位：确认缺失关联与记录不存在仍是两回事；
- 无温余烬：明确它不是篝火，不回血、不更新复活点；
- 依赖返回门：明确离开后仍回到第四层当前状态，不改写第一层真实进度。

短对白：

> 抄写员：“这是第一层，却没有一块石头属于第一层。”
> 抄写员：“升炉记住了你的恢复许可，也记住了火怎样替你留下轮廓。”

## 5. 专属护甲：回燃衣

| 项目 | 运行规格 |
|---|---|
| 物品 ID | `ember-echo-robe` |
| 显示名 | 回燃衣 |
| 来源 | 第四层回燃残响，确定奖励 |
| 随机性 | 无；不进入普通怪掉落池 |
| 防护 | `2` 点护甲生命 |
| 获得方式 | 打开隐藏区后在奖励束旁按 `E`，走标准战利品/背包流程 |
| 满背包 | 玩家明确选择替换或暂留奖励，不静默删除 |
| 丢弃 | 沿用当前装备规则，丢在脚下并可在本层捡回 |
| 存档 | 复用现有装备背包字段，不升级 Schema |

装备后的可见变化：

- 主色从普通蓝袍切换为余烬棕红；
- 头部出现深色兜帽轮廓；
- 肩部增加黄铜护片；
- 胸口出现小型余烬印；
- 武器、脸部和移动动画仍保持可读。

护甲脱下后立即恢复普通外观。变化必须在地图和战斗场景同时出现，不能只改 HUD 图标。

本版“专属”指本局固定来源与独特外观，不等于账号级永久衣柜。永久收藏属于后续版本范围。

## 7. 入层与层末对白

### `F4-E01`｜同一次命令

> 抄写员：“火、冰、雷看起来像三场灾难。”
> 抄写员：“先别分开处理。它们都在等待同一个内层结果。”

镜头依次建立命令源炉、远处冻结阵列和更高处雷晶导轨；总时长不超过 `2.5s`。

### `F4-E07`｜尚未结束的执行

元素王不是命令作者，而是持续执行依赖的控制体。递归查询逐级点亮依赖脊柱，最终回到同一源头。

> 抄写员：“这不是三场灾难。”
> 抄写员：“是一条没有完成、也没有回滚的命令。它已经运行了太久。”

抄写员在本层看见一段档案官签名，但只说“有人在阻止命令结束”，不在第四层揭示魔王身份。

## 8. 课程文案验收

子查询题必须直白区分：

- 外层表与外层返回字段；
- 内层表与内层返回字段；
- 内外层比较字段；
- 子查询返回单值、集合还是布尔存在性；
- 相关子查询引用的外层别名；
- CTE 名称、列名、锚点成员和递归成员。

禁止使用“查出正确的 name”“找到对应 sector”这类无法判断字段归属的任务表述。

## 9. 技术与存档边界

- 第四层联动复用现有 `openedGateIds`、课程完成、怪物 HP、装备背包和管理员预设。
- 不增加 SQLite 教学表，不把故事状态写入查询数据库。
- 隐藏奖励由稳定隐藏区 ID 派生；旧存档若已开门但尚未生成奖励，加载时补建一次。
- 同一存档中不能重复生成“回燃衣”奖励束。
- 回燃门不是楼层切换，因此不会重置第四层怪物、篝火、Fog 或复活点。
- 所有场景图形使用当前轻量 Phaser 图元与共享角色工厂；本轮不引入新依赖或第三方素材。

## 10. 验收标准

现场证据：

- `f4-three-incident-fronts`：分别统计火、冰、雷三个事故区域，先证明三处记录同时存在。
- `f4-dependency-lineage`：从 ID #034 出发沿 `master_id` 递归三层，显示汇入核心的依赖。
- 证据只证明可复现的表关系，不声称 SQLite 已执行真实全城命令。

- `ID #044` 确实封锁中后区，胜利前回燃门不可见。
- 击败 `ID #044` 后可进入后区，并可选择探索回燃门。
- 隐藏区明确像第一层残响，而不是第四层换色房间。
- 回燃衣只出现一次，不来自随机怪物掉落。
- 回燃衣可走标准背包流程，装备后地图与战斗模型都明显变形。
- 脱下护甲后普通外观恢复；读档后装备与外观一致。
- 隐藏区不阻塞主线、不刷新怪物、不修改第一层真实进度。
- 元素王胜利后垂直升炉激活并保持原有自动升层规则。
- 子查询任务明确外层、内层、别名、字段和返回形态。
