## 0. 文档职责

本文负责第一至第八层的因果顺序、每层问题与答案、抄写员关系变化、地图提交结果和 SQL 密文门。
逐字对白归各层脚本，课程答案归运行时代码与测试，数值和掉落归系统规格。

本次精排不改变三个既定真相：

1. 玩家不是一条当前记录，而是多段删除、覆盖、失败与撤销历史形成的人形集合。
2. 最后的档案官保存历史是对的，把无法决定延长为数百年停滞是错的。
3. 唯一正式结局是 `MIGRATE`：建立可验证的新版本，同时保留历史和回滚路径。

## 1. 八层因果链

| 层 | 地区 | 本层直接问题 | 本层可证明答案 | 必须留下的新问题 |
|---:|---|---|---|---|
| 1 | 地下余烬档案 | 当前表查不到玩家，玩家为何仍能行动？ | `0 rows` 只说明当前记录缺失，不证明实体不存在 | 其他来源是否保存了玩家痕迹？ |
| 2 | 潮汐群岛 | 七个来源相似，是否可以合并成一个？ | 来源必须保留；相同值不等于同一生命 | 七份来源彼此是什么关系？ |
| 3 | 白霜墓原 | 名字、主人缺失后，关系是否仍成立？ | 明确连接条件能重建人、房间、遗物和主人关系 | 为什么这些关系都指向同一命令？ |
| 4 | 三相升炉 | 火、冰、雷是三场事故还是一次命令？ | 三种事故来自同一条仍为 `OPEN` 的全城更新 | 谁决定这条命令如何影响每个人？ |
| 5 | 黑铁轮值城 | 事实不变时，排序能否改变命运？ | 分区、排名和窗口范围决定谁先被看见与处理 | 有了改变记录的权力，怎样避免新伤害？ |
| 6 | 龙脊回滚工坊 | 写入是否只能在提交与全部撤销间二选一？ | 隔离副本、约束、事务和保存点让改变可验证、可局部撤销 | 即使数据仍在，系统是否可能永远找不到它？ |
| 7 | 残照索引王苑 | 最快访问路径是否等于唯一事实？ | 索引只改变寻找方式；完整扫描仍能证明被绕开的历史存在 | 如何在不覆盖历史的前提下接管王城？ |
| 8 | 黑金迁移高堂 | 应当提交、回滚，还是继续停滞？ | 先快照、审计、隔离构建、验证，再切换并保留回滚 | 无；以 `MIGRATE` 收束 |

## 2. 抄写员人物弧

抄写员不是教程按钮，也不是篝火的重复功能。篝火负责恢复与答案复盘，抄写员负责“当前证据允许
得出什么结论、仍不允许得出什么结论”。

| 层 | 她相信什么 | 本层被迫修正什么 | 关系变化 |
|---:|---|---|---|
| 1 | 当前表就是全部现实 | 查询不到不等于不存在 | 从引导者变成证人 |
| 2 | 相似记录可以归并 | 来源差异必须保留 | 开始承认自己的判断可能伤人 |
| 3 | 明确关系足以还原真相 | 关系也可能被错误规则裁剪 | 与玩家共同审计 |
| 4 | 找到源命令就能解决问题 | 命令仍未完成，简单终止也会抹去依赖历史的人 | 第一次认出档案官签名 |
| 5 | 公开全部证据天然正确 | 公开顺序本身也会造成伤害 | 主动坦白自己曾延迟公开证据 |
| 6 | 全部回滚是最安全方案 | 回滚保护现在，也不能假装候选从未存在 | 接受隔离验证和局部撤销 |
| 7 | 最快路径是最可靠路径 | 被路径绕开的历史依然存在 | 公开自己曾参与建立“不可达”索引 |
| 8 | 她应继续替玩家解释 | 最终决定必须由玩家承担并接受审计 | 不再代答，只核验来源 |

## 3. SQL 密文门统一契约

每层恰好一个主线附近的高难 SQL 密文门。它是地图上的实体侧门，不是菜单题库。

### 3.1 玩家规则

- 靠近门，常亮显示密文机关轮廓；进入三格内显示 `E · 解读 SQL 密文`。
- 按 `E` 打开只读 SQL 终端；空输入和 `ESC` 不扣生命。
- 正确结果永久打开侧路，并触发地图状态、短反馈与《失名录》记录。
- 语法错误或错误结果反噬 `1` 点，护甲优先。
- 成功不授予课程掌握、经验或掉落，不替代本层 Boss。
- 同一 Run 中门一旦打开不再要求重复解题。

### 3.2 每层密文功能

| 层 | 实体密文 | 使用能力 | 地图结果 | 叙事含义 |
|---:|---|---|---|---|
| 1 | 零行密文门 | 基础筛选与空结果判断 | 登记厅侧廊永久开启 | 空结果也可以是正确证据 |
| 2 | 七源密文门 | 排序、去重与连接 | 灯塔侧航道永久开启 | 七个来源不能被覆盖成一个 |
| 3 | 三表墓印 | 多表关系链 | 王座旁墓门永久开启 | 关系需要明确两端和来源 |
| 4 | 递归炉印 | CTE 与递归追溯 | 元素执行环侧门永久开启 | 多场事故共享同一根依赖 |
| 5 | 轮值密文门 | 窗口分区与 Top-N | 军钟内城侧门永久开启 | 排序决定公开和处理顺序 |
| 6 | 逆鳞密文门 | 只读预演和分区校验 | 龙巢安全旁路永久开启 | 写入前必须先证明影响边界 |
| 7 | 最优叶密文门 | 执行计划与分区最优项 | 树心短路永久点亮 | 快路是工具，不是事实 |
| 8 | 王令校验密文 | 副本健康与最新版本选择 | 迁移王座校验侧门永久开启 | 切换前必须逐区域验证 |

### 3.3 现场 SQL 证据

密文门负责可选高难捷径；现场 SQL 证据负责主线因果。证据节点随课程完成解锁，在主画面记录框中
同时展示标题、真实 SQL、返回字段、真实行数和当前允许得出的结论。玩家按 `E` 关闭后，证据永久进入
《失名录》。

| 层 | 证据查询 ID | 证明内容 |
|---:|---|---|
| 1 | `f1-current-resident` / `f1-restore-contradiction` | `0 rows` 与旧恢复轨迹都不能单独定义玩家 |
| 2 | `f2-seven-source-pages` / `f2-seven-source-summary` | 七页来自五个区域，来源不可覆盖 |
| 3 | `f3-unarmed-record-preserved` / `f3-room-relic-chain` | 明细缺失不等于主体缺失，关系链必须写明两端 |
| 4 | `f4-three-incident-fronts` / `f4-dependency-lineage` | 三处事故同时存在，并沿显式依赖汇入同一核心 |
| 5 | `f5-stable-duty-order` / `f5-ties-preserved` | 排序保留明细，并列不是重复或缺失 |
| 6 | `f6-duplicate-candidates` / `f6-baseline-restored` | 删除前固定边界，沙箱回滚后主档案保持基线 |
| 7 | `f7-all-realms-present` / `f7-crystal-plan-candidates` | 索引没有删去其他领域，选择路径可被解释 |
| 8 | `f8-visible-snapshot` / `f8-deadlock-cycle` | 快照可见性与等待环都由明确记录证明 |

## 4. 每层固定节拍

每层现场剧情统一采用以下顺序；可选隐藏房间和密文门可以错开到达时间，但在档案中仍按因果位置
排序，不抢走 Boss 与层末结论。

```text
入层问题
→ 第一项世界改变
→ 中段证据
→ 可选隐藏区域
→ 第二项世界改变
→ SQL 密文侧路
→ Boss 对错误结论的强制执行
→ 层结论
→ 实体上升设施
```

### 4.1 主线不可随机

- Boss、抄写员、证据、密文门、隐藏区域、两处篝火和上升设施固定。
- Seed 只能改变普通遭遇、装饰、非关键支路和恢复品。
- 随机普通怪不能提前说出主线结论。
- 隐藏区域强化主题并给确定外观/护甲，不承担主线唯一证据。

### 4.2 反馈预算

| 事件 | 主画面 | 右栏 / 图鉴 | 世界 |
|---|---|---|---|
| SQL 课程完成 | 一句结算 | 记录正确语句与知识点 | 机关持续改变 |
| 密文门开启 | 两行以内 | 收录密文与结果摘要 | 门永久开放 |
| 隐藏区域发现 | 两行以内 | 收录补充证据和奖励解释 | 暗门、室内、换装可见 |
| Boss 击败 | 强击杀反馈 + 最多四行 | 获得名字、经验、层结论 | 王座与上升设施改变 |
| 层完成 | 金色完成卡 | 收录本层答案和下一问 | 自动进入下一层 |

## 5. 地图互动与 SQL 的对应关系

地图机关不能只是“完成题后变亮”。每个状态必须能回答“哪一部分 SQL 改变了它”。

| SQL 语义 | 空间表达 |
|---|---|
| `WHERE` | 水位只保留符合条件的排水记录 |
| `JOIN ... ON` | 两端桥梁按关系键接合 |
| `WITH RECURSIVE` | 依赖脊柱逐层追到源命令 |
| `PARTITION BY` | 城墙轮值表分成独立岗区 |
| `ROWS ... CURRENT ROW` | 警戒灯只累计到当前岗 |
| `ROLLBACK` | 候选轨回到原始轨 |
| `SAVEPOINT` | 正确段保留，错误段退回 |
| 覆盖索引 | 镜湖不再返回主表湖底 |
| `EXPLAIN QUERY PLAN` | 树根显示真实 SEARCH / SCAN 路径 |
| MVCC 快照 | 版本长廊只显当前事务可见版本 |
| 死锁检测 | 双骑等待门显示闭合环 |
| 迁移验证 | 七步迁移台逐项亮起，缺一步就不切换 |

## 6. 验收

- 八层每层至少八个可追溯现场节点，第一个为入层、最后一个为层完成。
- 每层恰好一个命名抄写员、两个实体篝火、一个隐藏区域和一个 SQL 密文门。
- 每层至少四项课程能造成持续可见的地图状态变化。
- `???`、`NULL`、实际值与 `0 rows` 始终严格区分。
- 密文门成功后，存档门状态、地图碰撞、视觉状态和剧情档案一致。
- 密文门失败不会授予课程、经验、战利品，也不会产生额外怪物回合。
- 第五至八层管理员预设能分别检查入口、隐藏区、密文门和完成态。
- 第八层完成前不提前展示 `MIGRATE` 的完整步骤；完成后保留历史和回滚路径。
- 八层每层至少一条现场 SQL 证据通过真实 SQLite 执行，且显示字段和行数与运行时一致。
