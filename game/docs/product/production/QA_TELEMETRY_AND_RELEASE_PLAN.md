# QA、体验遥测与发布计划

> 文档版本：`1.0`
>
> 状态：`F1_F2 RC / AUTOMATION + TARGETED BROWSER VALIDATED / FULL MATRIX PENDING`
>
> 发布目标：两层可独立试玩、可连续通关、可嵌入博客的垂直切片

## 1. 质量目标

发布候选不是“能进下一层”即可。必须同时证明：

- SQL 教学正确且任务清楚；
- 战斗、成长、死亡和掉落没有状态丢失；
- 两层地图在轮廓、交通、节奏和世界变化上真实不同；
- 剧情由可见动作和真实查询推动；
- 视听可连续运行且版权可追溯；
- 320 px、触屏、键盘、iframe、离线和 Reduced Motion 可玩；
- 新资源没有把博客页面变成高性能消耗应用；
- 管理员预览能够快速复现所有关键状态。

## 3. 严重度

| 级别 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 数据丢失、安全或完全不可运行 | 存档清空、无限写入、页面崩溃 | 立即停止 |
| P1 | 主线阻塞或错误教学 | 正确 SQL 不通过、死亡不能复活、门不可达 | 必须修复 |
| P2 | 明显体验 / 可访问性损害 | 名字提前泄露、布局遮挡、音乐叠播 | 发布前修复或明确批准 |
| P3 | 轻微表现或文字问题 | 单帧穿插、小范围文案不顺 | 可进入已知问题 |

任何 SQL 答案错误、字段归属错误或身份半结算至少是 P1。

## 4. 自动化门禁

每个 checkpoint 至少执行：

```text
npm test
npm run build
npm run check
```

并新增：

- 内容静态验证；
- F1 / F2 世界状态组合测试；
- 故事表 / 查询策略测试；
- 两层最短合法通关 Session 测试；
- 存档 v11 → v12（若启用）的迁移测试；
- 资源 manifest / SHA / 许可证检查；
- Playwright 主路径与视觉快照。

删除或更新旧测试时，PR 必须解释旧行为被哪个新契约替代。禁止为了绿灯简单删除断言。

## 5. 内容正确性测试

### 5.1 SQL

每个阶段至少测试：

1. 官方答案；
2. 等价大小写 / 空白 / 别名写法；
3. 语法正确但结果错误；
4. 结果正确但缺少要求结构；
5. 不存在字段；
6. 错误表字段归属；
7. 多语句 / 写操作策略拒绝；
8. 真实结果列名和行数；
9. 四级提示顺序；
10. 最终 `name` 揭示时机。

### 5.2 内容静态规则

- 所有怪物 ID 在目标范围唯一，从 1 开始；
- 任务引用字段均存在；
- 两表同名字段全部限定；
- 最终阶段前不出现未发现怪物真名；
- NPC 名字不受怪物身份遮罩；
- 每个资源键在楼层 manifest 或降级配方中存在；
- 每个故事事件触发对象存在且可达；
- 每个确定奖励有容量兜底；
- 每条捷径有前后两态和明确用途；
- 每个 Boss 世界结果可由权威进度派生。

## 6. 第一层完整用例

### F1-E2E-001 新玩家主线

前置：清空当前 Run，保留 / 不保留 Profile 各跑一次。

步骤与检查：

1. 出生在登记厅安全区；HP 2/2；抄写员与低燃余烬锚点可见；锚点没有第三个休息菜单；
2. 调查居民记录返回 0 行，但恢复权限有效；
3. 触碰 ID #001，战斗前不显示真名；
4. 完成 weakness 后仍只有 ID；最终 name 后击杀并恢复“史莱姆”；
5. XP 从 0 → 1，图鉴 +1；
6. WHERE 战不得要求未知真名；水位真实下降；
7. IS NULL 错写 `= NULL` 获得直白解释；正确后宿舍显形；
8. 从旧仓库背面开启铁门捷径，返回登记厅距离明显缩短；
9. GROUP BY 改变档案页，而非只扣血；
10. Boss 前火休息，复活点更新；
11. HAVING 两阶段击败登记官；
12. 显示金色 `CONGRATULATIONS`、5 XP、第一层钥匙和证据；
13. 升降机自动可用，进入 F2；
14. 读档后水位、闸门、图鉴、Boss 和奖励一致。

通过标准：无管理员、无完整提示也可通关；所有必要状态和反馈清楚。

### F1-E2E-002 死亡与撤退

- 在中段火休息；
- 战斗错误至死亡；
- 显示 `YOU DIED`，进入本场复盘，返回中段火并满血；
- 怪物保留死亡时 HP；
- 另一次战斗选择撤退；返回中段火但保持残血，怪物回到战前 HP；
- 两者均不重复 XP / 掉落 / 名字。

### F1-E2E-003 老 Profile 新 Run

- 已发现史莱姆的 Profile 开新 Run；
- 世界可显示永久图鉴中的真名，但当前课程和怪物仍需完成；
- 图鉴不提前显示本 Run 尚未经历的答案结果；
- 开场和故事事件不因 Profile 而跳过关键教学。

## 7. 第二层完整用例

### F2-E2E-001 主航线

1. 从升降机到初始港口，音乐连续转场；
2. ORDER / LIMIT 稳定船班，短船动画进入外岛；
3. DISTINCT 合并水纹但不把不同身份来源叙述成同一个人；
4. INNER JOIN 任务明确 `m.id / r.sector`；第一阶段不泄露树妖名；
5. 最终 JOIN 恢复名字并接通根桥；
6. LEFT JOIN 任务明确无匹配右表记录与 `IS NULL`；
7. 沉水村落显示七个不同来源证据；
8. 击败湖兽后潮位下降、岸线扩大，已探索小地图更新；
9. 船闸从世界中开启，形成直航，不是通用传送文字；
10. 灯塔前火可休息；
11. 综合 JOIN 击败灯塔守卫；
12. 七页证据装订，灯塔从覆盖变为保存；
13. 显示通关反馈与 XP，并自动进入第三层兼容内容；
14. 读档保持全部状态。

### F2-E2E-002 可选蛙王

- 不打蛙王也能通关；
- 接近后 ID 常亮，真名规则一致；
- 题目为本层二阶复合，不使用第三层知识；
- 奖励确定且非主线必要；
- 撤退 / 死亡不破坏主航线。

### F2-E2E-003 航线边界

- 登船期间不能触发随机遭遇；
- 连续快速按 E 不重复创建航行动画；
- 页面隐藏 / 恢复不让船或音乐卡死；
- 资源失败使用几何船和淡出转场仍可到达；
- 船闸开启前后目的地、碰撞和小地图一致。

## 9. 身份、图鉴与叙事用例

- 未发现：地图、HUD、任务、补全、战斗标题仅显示 ID；
- 最终查询正确但演出前强制刷新：恢复为完整击杀 / 已发现或完整未击杀 / 未发现，不允许半态；
- 击杀：大字 `ID → 真名`、图鉴 +1、XP、世界结果顺序正确；
- 读档：永久图鉴与当前 Run 怪物状态组合合理；
- 抄写员名字常亮且是唯一实体；
- 篝火不复制抄写员；
- 开场 `residents` 查询和 F2 `identity_sources` 查询在真实 SQLite 有可复现结果；
- 跳过演出不会跳过证据或奖励；
- 重复调查只显示简短回顾，不重复写证据；
- 死亡后叙事事件按状态恢复，不重复发放。

## 12. 性能 QA

采集：

- 首屏 JS / WASM / CSS；
- F1 / F2 单独资源大小；
- 冷 / 热缓存加载时间；
- 平均和 1% low FPS；
- 活跃 Sprite、Texture、粒子、AudioBuffer；
- 30 分钟内存趋势；
- SQL P50 / P95；
- 存档写入耗时。

场景：

- 普通探索；
- 20 个世界标签；
- Boss 最大粒子；
- 水动画 + 船 + 环境音；
- 反复开关 SQL / 图鉴 100 次；
- F1 ↔ F2 管理员切换 20 次；
- 页面隐藏 / 恢复 20 次。

阻塞条件：稳定低于 30 FPS、持续内存增长、音频叠播、输入丢失、资源失败后不能通关。

## 13. 本地体验遥测

默认只保存在当前浏览器，不上传。调试导出必须由用户主动点击，并移除自由输入 SQL 中可能含有的
个人内容。

建议事件：

```text
run_started
floor_entered
landmark_discovered
lesson_started / submitted / completed
hint_revealed(level)
combat_retreat / player_died / respawned
shortcut_seen / opened / used
campfire_rested / review_opened
monster_identity_revealed
codex_opened
area_boss_defeated / floor_completed
audio_unlocked / asset_fallback_used
```

禁止记录：逐步坐标轨迹、每次按键、完整自由 SQL 默认上传、设备标识、IP、账号或跨站身份。

核心计算：

| 指标 | 计算 | 决策用途 |
|---|---|---|
| 课程首过率 | 首次提交正确 / 开始人数 | 找表述或难度异常 |
| 提示深度 | 最深提示等级分布 | 判断提示是否过早给答案 |
| 空走比 | 无新事件成功移动 / 总移动 | 找地图疲劳 |
| 捷径价值 | 开启前后返程中位步数 | 证明捷径有用 |
| 死亡恢复率 | 成功复活 / 死亡 | 必须 100% |
| 叙事触达 | 关键证据触发 / 到达该段 | 找脚本漏触发 |
| 图鉴查看率 | 揭示后打开图鉴 / 揭示 | 判断反馈是否足够 |
| 资源降级率 | fallback / 场景加载 | 找部署与缓存问题 |

## 14. 试玩问卷

每轮 5–8 人小样本，优先观察行为后再问：

1. 不看 HUD，你觉得自己刚才在哪个地方？为什么？
2. 这道题要求哪个表的哪个字段？你是从哪里看懂的？
3. SQL 成功后，世界发生了什么？
4. 为什么怪物开始只有 ID？名字在什么时候出现？
5. 捷径帮你完成了什么，而不只是“开了一扇门”？
6. 抄写员和篝火分别有什么作用？
7. 第一层和第二层除了颜色，最大的不同是什么？
8. 哪一段让你觉得在赶路或重复？
9. 音乐是否有蜂鸣、断续、太小、尖锐或疲劳？
10. 你认为“七个名字”意味着什么？

如果多数玩家无法回答 1、3、5、6，说明地图 / 叙事仍停留在 UI 文案，不能进入发布候选。

## 17. 停止与返工条件

出现任一条件，停止继续堆内容，回到设计 / 架构：

- 新地图仍只能靠颜色区分；
- F1 / F2 主线 35% 以上时间是无意义移动；
- SQL 任务仍需要猜字段归属或别名；
- 玩家在击杀前能从常规 UI 得知真名；
- 剧情关键事实只存在侧栏卡片；
- 捷径没有回访、返程或后续战斗用途；
- 抄写员继续被复制成每座篝火附件；
- 随机掉落再次变成必掉或阻塞；
- 音乐出现持续蜂鸣、明显断口或来源不清；
- 新资源使低端设备无法稳定 30 FPS；
- 文档宣称完成但没有可重复验证证据。
