# 第一层关卡圣经：地下余烬档案

> 关卡版本：`v0.1`
>
> 状态：`IMPLEMENTED VERTICAL SLICE / CONTENT LOCKED`
>
> 楼层知识：`SELECT / FROM / WHERE / AND / IS NULL / COUNT / GROUP BY / HAVING`
>
> 目标时长：首次 20–35 分钟

## 1. 本层承诺

第一层不是一条摆着 SQL 怪物的灰色迷宫，而是一座仍在排水、仍在登记、仍然错误地运转的地下
档案设施。

玩家在这里回答：

> 当前居民表中没有我，为什么篝火仍能恢复我？

本层结论：

> 玩家不属于当前居民表，但属于一段仍然有效的恢复历史。

离开时提出：

> 这段历史中，究竟有几个名字？

## 2. 情绪曲线

```text
醒来：安静、温暖、陌生
→ 排水渠：潮湿、机械、可理解
→ 无名宿舍：第一次不安
→ 余烬仓库：短暂像家
→ 聚合档案室：许多笔迹同时出现
→ 登记大厅：制度性的压迫
→ 升降机：带着问题上升
```

本层唯一稳定暖色来自篝火、抄写员的灯和后来点亮的登记页。其他火焰不能滥用相同橙色。

### 3.3 空间规则

- 主路线宽度 2–3 格；
- 登记厅和水轮大厅是明显宽空间；
- 走廊转角不连续超过两次；
- 水渠是视觉边界，不用大量碰撞墙制造死路；
- 玩家从登记厅能看见铁门另一侧的灯，但无法早期开启；
- 旧仓库从背面开门后，回登记厅距离缩短至少 40%；
- 地图内只出现一处主水阀；
- 中后段各一处实体篝火，出生区是安全锚点，不再额外摆放篝火。

## 5. 角色

### 5.1 玩家 / 无键者

入层外观：

- 轮廓不完整；
- 只持有数据之刃；
- 生命 2；
- 身上没有姓名标签；
- 篝火可以恢复玩家，登记台却返回 0 行。

完成本层后的外观变化：

- 胸前出现第一页纸片；
- 空值提灯成为可见挂件；
- 获得第一块清晰的面部或衣领轮廓；
- 变化来自知识进展和确定奖励，不由随机掉落决定。

### 5.2 抄写员

初始位置：登记厅固定记录桌。

外观动作：

- 初见时在写一张没有姓名栏的恢复表；
- 玩家完成 `SELECT` 后抬头，第一次离开椅子；
- 玩家打开捷径回访时走到铁门前；
- Boss 后亲手把空白页装订进《失名录》。

她不会出现在每座篝火旁。篝火菜单仍可打开答题复盘，但人物实体保持唯一。

关键台词：

**初见**

> “这里没有你的名字。”
> “但火记得你。我们先把这两件事分开记录。”

**发现 NULL**

> “空白不是没看见。”
> “你已经查过了——这里确实什么也没有。”

**Boss 前**

> “大厅里的实体只承认一行完整记录。”
> “别求它给你名字。让它承认自己的规则漏掉了你。”

**结尾**

> “我不能替你写名字。”
> “但我可以保证，这一页不会再被当成空白丢掉。”

### 5.3 登记官

世界标签：击败前 `ID #005`。

真名：`登记官`。

外观：

- 由湿泥、纸页、铜印章和旧锁组成；
- 仍继承第一层软泥生物形态，避免完全跳出生态；
- 头顶不是王冠，而是一枚倾斜的登记印；
- 第一阶段封闭，第二阶段纸页展开。

动机：

- 相信每个可恢复对象必须对应当前居民表中的一行；
- 玩家返回 0 行，因此它不断尝试注销恢复权限；
- 它不是主动说谎，而是错误地把 Schema 当成世界全部。

## 6. 剧情节拍

### Beat 1：火记得你

**触发**：进入第一层。

**演出**：

- 黑场先听见柔和火声；
- 玩家轮廓从低燃余烬锚点旁恢复；该锚点不是可休息的第三座篝火；
- 登记台打出：

```text
SELECT id
FROM residents
WHERE restore_trace = 'CURRENT';

0 ROWS
```

- 侧面权限灯同时显示 `RESTORE PERMISSION: VALID`。

**玩家目标**：走到抄写员桌前调查。

**永久证据**：无。

### Beat 2：第一只名字

**触发**：触碰 `ID #001`。

**演出**：

- 怪物只显示 ID；
- 玩家完成两段 `SELECT`；
- 最后一击后数据行从怪物身体飞向档案页；
- 大字：

```text
ID #001
NAME RECOVERED
史莱姆
```

**作用**：教会“查询—击败—恢复名字—进入图鉴”的完整循环。

### Beat 3：水轮不是门

**触发**：完成 `SELECT`。

**演出**：

- 正确结果对应控制记录；
- 水轮启动，不弹出“门已开”替代世界反馈；
- 水声方向改变，栈桥从墙体放下；
- 抄写员从远处第一次抬头。

**作用**：证明 SQL 可以改变环境，不只造成伤害。

### Beat 4：无名床位

**触发**：进入无名宿舍。

**演出**：

- 高水位时只能看见床头；
- 完成 `WHERE` 后水位下降；
- 完成 `IS NULL` 后床牌出现 `current_owner = NULL`；
- 墙上湿痕显示这里曾经有许多人。

**抄写员行动**：她通过管道传声，只确认事实，不给结论。

### Beat 5：打开身后的门

**触发**：从旧仓库背面打开捷径。

**演出**：

- 铁门打开，登记厅就在几步外；
- 抄写员实体从桌边走到门前；
- 空厅出现三到五个无名居民轮廓；
- 远端登记大厅传出铜印落下的声音；
- 玩家获得明确目标：“回登记厅调查异常”。

**作用**：捷径同时提供路程、人物行动和剧情价值。

### Beat 6：许多笔迹

**触发**：完成 `GROUP BY`。

**演出**：

- 多张恢复回执从积水中升起；
- 依来源分成若干组；
- 每组笔迹不同，但结束位置相同；
- 抄写员不再说“也许是重复”，而是把所有组都保留。

**证据**：`current-record = 0 ROWS`。

### Beat 7：篝火复盘

**触发**：在后段篝火休息。

界面：

- `在此休息`：回血并更新复活点；
- `答案复盘`：按 SELECT、WHERE、NULL、GROUP 展示本层答题；
- `本层问题`：显示“没有当前记录，为什么仍能恢复？”。

抄写员不需要站在火旁，复盘以她此前整理的纸页形式出现。

### Beat 8：登记官的规则

**触发**：进入 Boss 大厅。

**演出**：

- 登记官尝试读取玩家；
- 每次得到 0 行；
- 它把 0 行解释为“不存在”，开始注销恢复权限；
- 玩家不攻击身体，而是逐步修正规则。

### Beat 9：失名录第一页

**触发**：Boss 完成。

**演出**：

- 登记官印章停住；
- 权限规则改写；
- 玩家获得 5 XP、第一层钥匙和恢复权限证据；
- 抄写员把空白页装订为《失名录》第一页；
- 档案升降机自动启动；
- 潮声从上方出现。

## 7. SQL 课程与世界反馈

### 7.1 字段归属规则

- `monsters.id` 是怪物主表主键；
- `monster_signals.monster_id` 是信号明细指向怪物主表的关联字段；
- 任务不得在 `monsters` 上错误使用 `monster_id`；
- 出现两个 `name` 时必须使用表别名或说明归属；
- 目标和提示必须写出完整字段。

### 7.2 SELECT / FROM：ID #001

| 阶段 | 明确任务 | 答案 | 世界反馈 |
|---|---|---|---|
| 1 | 从 `monsters` 返回 `id = 1` 的 `weakness` | `SELECT weakness FROM monsters WHERE id = 1;` | 水轮卡住的未知软泥核心暴露，但仍只显示 ID |
| 2 | 从 `monsters` 返回 `id = 1` 的 `name` | `SELECT name FROM monsters WHERE id = 1;` | 最后一击、姓名恢复和图鉴写入原子结算 |

提示：

1. “先读取弱点，最后读取名字；锁定 ID #001。”
2. “结构是 `SELECT ... FROM ... WHERE ...`。”
3. “表 `monsters`；第一阶段字段 `weakness`，第二阶段字段 `name`；条件 `id = 1`。”
4. 显示完整答案。

第二阶段的查询成功、怪物生命归零、`ID #001 → 史莱姆` 演出和图鉴写入是同一结算；
撤退或死亡不能把名字单独留下。

### 7.3 WHERE / AND：ID #002

| 阶段 | 明确任务 | 答案 | 世界反馈 |
|---|---|---|---|
| 1 | 从 `monsters` 返回同时满足 `room_id = 2`、`status = 'escaped'` 的 `id` | `SELECT id FROM monsters WHERE room_id = 2 AND status = 'escaped';` | 正确排水控制目标被高亮 |
| 2 | 从 `monsters` 返回同时满足 `id = 2`、`status = 'escaped'` 的 `weakness` | `SELECT weakness FROM monsters WHERE id = 2 AND status = 'escaped';` | 水闸打开，水位降一级 |

禁止在击败前要求玩家用未知真名过滤怪物。

### 7.4 IS NULL：ID #003

| 阶段 | 明确任务 | 答案 | 世界反馈 |
|---|---|---|---|
| 1 | 从 `monsters` 返回 `room_id = 3` 且 `master_id IS NULL` 的 `id` | `SELECT id FROM monsters WHERE room_id = 3 AND master_id IS NULL;` | 无名宿舍床牌显形 |
| 2 | 返回 `master_id IS NULL` 且 `status = 'cursed'` 的怪物 `name` | `SELECT name FROM monsters WHERE master_id IS NULL AND status = 'cursed';` | 最后一击恢复“毒史莱姆” |

错误反馈：

- `= NULL`：解释未知值比较结果不是 `TRUE`；
- 只写 `IS NULL`：指出缺少字段；
- 查询正确但返回多行：指出未按任务限制房间或状态。

### 7.5 COUNT / GROUP BY：ID #004

任务：

> 从信号明细表 `monster_signals` 读取 `monster_id = 4` 的记录；按字段 `channel`
> 分组，返回 `channel` 与每组行数 `COUNT(*) AS total`。

答案：

```sql
SELECT channel, COUNT(*) AS total
FROM monster_signals
WHERE monster_id = 4
GROUP BY channel;
```

世界反馈：

- 零散回执按 `channel` 归档；
- 每组数量以纸页高度表现；
- 聚合战锤获得确定性解锁。

### 7.6 HAVING：ID #005 登记官

**阶段 1：恢复有效组**

```sql
SELECT channel, COUNT(*) AS total
FROM monster_signals
WHERE monster_id = 5
GROUP BY channel
HAVING COUNT(*) >= 2;
```

反馈：登记官的“无记录即删除”护盾裂开。

**阶段 2：确认最强恢复轨迹**

```sql
SELECT channel, COUNT(*) AS total
FROM monster_signals
WHERE monster_id = 5
GROUP BY channel
HAVING COUNT(*) >= 3;
```

反馈：保留 `echo` 组，阻止恢复权限注销。

## 9. 战斗与 Boss

### 9.1 普通战

- 终端打开后世界暂停；
- 怪物每次反击前显示意图；
- 错误一次造成 1 伤害；
- 玩家初始 2 HP，因此错误有压力但不直接结束学习；
- 每个正确阶段至少播放命中和字段高亮；
- 最后一击触发名字恢复。

### 9.2 登记官 Boss

阶段结构：

1. **行锁**：登记官坚持必须有当前居民记录；
2. **分组**：玩家证明多个恢复回执形成有效组；
3. **阈值**：玩家用 `HAVING` 保留可靠恢复轨迹；
4. **规则修正**：Boss 不死亡消散，而是停止错误注销。

失败：

- Boss 反击名为“注销印”；
- 生命归零后回到后段篝火；
- 死亡复盘只显示本场 HAVING 和前置 GROUP BY 问题；
- 可直接撤退到复活点。

胜利反馈强度高于普通怪：

- 120–180 ms 短停顿；
- 铜印碎裂；
- 纸页由红变金；
- `ID #005 → 登记官`；
- 5 XP；
- 权限证据进入剧情档案；
- 第一层钥匙进入关键物品；
- 升降机远景启动。

## 10. 奖励与掉落

### 10.1 随机

- 普通怪：2% 凝胶或水珠；
- 小型精英：5% 凝胶；
- 登记官：无随机掉落；
- 未掉落时结算明确写“没有发现可用物品”，不弹大型空战利品面板。

### 10.2 确定

| 位置 | 奖励 |
|---|---|
| SELECT 教学结算 | 过滤弓 |
| IS NULL 结算 | 空值提灯 |
| 聚合档案室 | 聚合战锤 |
| 旧仓库宝箱 | 软泥甲或固定恢复品，最终选其一 |
| 登记官 | 第一层钥匙、恢复权限证据、《失名录》第一页 |

拾取卡必须包含：

- 名称；
- 类型；
- 具体数值；
- 与当前装备的变化；
- 如何使用或更换；
- 是否为关键物品。

## 15. 验收

- 10 分钟内完成第一次名字恢复；
- 玩家至少一次看见 SQL 改变水位；
- 玩家早期看见捷径正面；
- 开捷径后自然返回登记厅；
- 回访同时改变人物、居民轮廓和 Boss 预告；
- 抄写员不是篝火复制体；
- 所有题明确表、字段、条件和输出；
- 击败前不显示怪物真名；
- 登记官胜利后玩家能复述本层答案；
- 读档后水位、捷径、Boss、名字和奖励一致；
- Reduced Motion 和静音仍可理解全部状态；
- 无 HUD 截图可辨认至少四个主要地区。
