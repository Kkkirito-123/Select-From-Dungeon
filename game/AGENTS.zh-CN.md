# 游戏编码 Agent 稳定规则

本文件是 `game/` 的稳定操作权威。先阅读仓库根 `AGENTS.md`。实现依赖游戏职责、执行流、命令、
数据、兼容性或运行事实的改动前，阅读 `ARCHITECTURE.md`。本文件是英文权威 `AGENTS.md` 的
同步中文译文。

## 权威与阅读顺序

1. 阅读根级及本目录 `AGENTS.md`。
2. 按适用的仓库 Skill 路由。
3. 已批准的 L1/L2 工作需阅读根 `TASK.md` 中的准确契约及其 `ARCHITECTURE_REF`。
4. 只读取完成有界改动所需的所属源码、测试、契约和文档。

源码和可执行测试是当前行为证据，已批准 Task 是预期行为证据。两者实质漂移时应报告，不得静默
选择其中一方。

## 工作契约

- 默认使用中文回复，除非用户要求其他语言。使用 UTF-8；标识符、API 与测试遵循代码库语言。
- 每次只服务一个明确目标，编辑前定义可观察的成功标准。
- 保护用户的无关改动。未经明确授权，不得覆盖、回滚、删除、发布、格式化或暴露无关内容。
- 新功能、重构、删除、依赖或 Schema 变化、批量修改、全局配置和其他高影响工作，需要已批准的
  目标、范围、验收标准、验证方式与风险边界。
- 优先最小完整纵向切片，不增加推测性功能、抽象、兼容路径、依赖或重复权威。
- 区分实现、环境、验证路径和工具失败；同一种实质失败最多尝试三次。
- 只声明实际执行的检查，并区分单元、类型、构建、浏览器、Provider、设备与端到端证据。
- 本地检查和验证不代表获得 Commit、Push、PR、部署、破坏性操作或其他外部写入权限。

## 游戏边界

- 依赖方向应指向父级契约与共享规则。Domain、Content 与 Infrastructure 不得反向导入 Application、
  Presentation 或 Devtools；纯运行参数由 `contracts/config` 单向提供。引入新的持久层级边界时，应扩展
  `scripts/check-architecture.mjs`。
- `.maintainer/architecture-map.json` 是游戏拥有的机器路由权威，登记稳定 area、职责 partition、
  跨层 feature 与八层 `floorScopes`，不是代码索引。楼层子单元不得引用兄弟楼层；共同逻辑上提到父级
  服务 partition，再由唯一 registry 装配。普通文件和内部子目录变化不更新地图；只有稳定 root、职责或
  route 变化时才更新。
- `GameSession` 与聚焦的领域模块拥有游戏规则。DOM 和 Phaser 只呈现快照并转发明确意图，不能
  成为第二套规则引擎或存储所有者。
- 未启动可选 Python Agent 时，浏览器游戏仍必须可玩。跨工程行为只能通过严格 HTTP 契约完成，
  不得建立共享源码导入或隐藏的第二运行路径。
- 生成题库和转换后的资源是可复现产物；必须修改作者源与生成器，不得手工修改生成字节。
- 存储结构、协议、公开契约、生成代码归属、命令、模块、安全或运行事实发生变化时，必须同步
  `ARCHITECTURE.md` 及其中文译文。

## 安全与证据边界

- Dungeon Maintainer 桥必须保持仅开发态、仅本机且显式启用；生产代码不得暴露其全局桥。
- 外部工具只能收到已记录的玩家可见投影。不得暴露隐藏答案、未揭示提示、完整地图、存档、背包、
  身份、隐藏裁判细节、凭证、私有地址或完整快照。
- SQL 只能从固定且可见的玩家 textarea 输入，并在浏览器内部执行。工具不得接受隐藏 SQL 参数或
  收到管理员答案。唯一例外是当前打开的玩家 textarea 中已可见的文字，且必须处于
  `ARCHITECTURE.md` 记录的投影范围内。
- 保持判题、成长、当前存档校验和作者内容身份的确定性。没有明确范围、版本决策和聚焦证据时，
  不得重新引入历史兼容。
- 未完成许可证、归属、包体和安全审查，不得增加第三方图片、字体、音频、复制关卡文字或运行依赖。

## 验证与停止条件

- 先运行聚焦测试，再按改动风险运行适用的架构检查、完整游戏测试和构建。
- 检查完整 Diff，确认无范围漂移、过期事实、生成产物、安全暴露或未说明的未验证行为。
- 当需求发生实质冲突、批准不再匹配范围、安全边界将被削弱，或没有更大权限就无法获得必要证据时，
  停止并请求方向。
