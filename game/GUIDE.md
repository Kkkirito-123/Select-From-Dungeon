# SQL 魔王城 1.0 游玩指南

> 当前产品版本：`1.0`
>
> 运行方式：浏览器本地运行；无需账号、后端或 AI Agent
>
> 课程范围：八层 47 组必修课程；不是完整 SQL / MySQL 八股题库

## 1. 开始运行

要求 Node.js `>=20.19`、pnpm `11.9.0`：

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 Vite 输出的地址，通常是 `http://localhost:5173/`。不要直接用 `file://` 打开
`index.html`，SQLite WASM 需要通过 HTTP 加载。

## 2. 核心操作

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动 / 探索 | `WASD` 或方向键 | 屏幕方向键 |
| 调查、拾取、篝火、门 | `E` | `E` 按钮 |
| 打开战斗 SQL 终端 | 同时按 `Q + S` | `SQL 战斗` |
| 执行 SQL | `Ctrl/Cmd + Enter` | `执行 SQL 攻击` |
| SQL 补全 | `Ctrl/Cmd + Space`，方向键，`Enter/Tab` | 点击建议 |
| 背包 / 换装 | `B` | `背包 / 换装` |
| 关闭当前界面 | `Esc` | 界面关闭按钮 |

只有触碰存活怪物或触发伏击后才能打开战斗终端。每个阶段从空输入开始，玩家需要写出完整 SQL；
“下一条提示”会由短到长逐步给出方向，最后一条才展示完整参考结构。

## 3. 一局怎么玩

1. 从入口安全区出发，观察地标并探索迷雾。
2. 触碰只显示 ID 的怪物，进入独立单体战斗；最后一击才回收名字并写入怪物图鉴。
3. 阅读任务、主表 / 明细表角色和完整字段。
4. 写 SQL 并执行；正确结果造成攻击，错误结果或语法错误触发已预告反击，空输入不耗回合。
5. 胜利后读取 XP；完成课程会解锁房间宝箱，大多数普通战斗不会掉随机物品。
6. 找到篝火休息，恢复生命和护甲并更新复活点；满足条件后也可查看篝火的确定性复盘。抄写员是独立 NPC。
7. 打开从背面抵达的捷径，减少重复赶路。
8. 击败区域首领和楼层 Boss；前七层会通过实体上升设施自动进入下一层。

新 Run 使用唯一一套八张确定性 `56×42 / generator v7` 地图。Seed 固定地图非关键转折、装饰、
巡逻和低概率恢复，但不会随机必修课程、关键武器、钥匙或主线证据。当前存档只接受这套地图和
当前题库绑定；历史地图、旧题库绑定和旧怪物编号不会被读取，开始新 Run 是恢复路径。八层怪物的
`monsters.id` 按内容顺序连续为 `1–89`；信号与装备明细表中的 `monster_id` 是指向该主键的关系字段。

## 4. 八层路线

| 层 | 地区 | 课程 |
|---:|---|---|
| 1 | 地下余烬档案 | `SELECT`、`WHERE`、`IS NULL`、`GROUP BY`、`HAVING` |
| 2 | 潮汐群岛 | `ORDER BY / LIMIT`、`DISTINCT`、`INNER JOIN`、`LEFT JOIN`、JOIN 综合 |
| 3 | 白霜墓原 | JOIN 深化、自连接、三表链、`UNION`、关系审计 |
| 4 | 元素升炉 | 标量 / `IN` / `EXISTS` / 相关子查询、CTE、递归 CTE |
| 5 | 黑铁外城 | 窗口、分区、排名、前后行、Frame、分组 Top-N |
| 6 | 龙脊上城 | 受控 `INSERT`、`UPDATE`、`DELETE`、约束、事务与保存点 |
| 7 | 残照王苑 | B-Tree、复合 / 覆盖索引、执行计划与优化 |
| 8 | 黑金高堂 | MVCC、锁、隔离、建模、复制、分片与查询安全 |

第六层写操作只发生在一次性 `repair_queue` 数据库副本；每次判定后丢弃。第七层使用真实
SQLite `EXPLAIN QUERY PLAN`；第八层通过确定性事故数据讲解并发与分布式概念，不冒充 SQLite
原生实现。

## 5. 战斗、成长与掉落

- 初始生命 2；反击通常造成 1 点伤害，护甲先承受。
- 普通、精英、Boss 胜利分别获得 `1 / 3 / 5 XP`。
- 升级阈值会逐步提高，以游戏内 XP 进度条为准；升级增加 1 点生命上限并恢复 1 点生命。
- 可以撤退到当前复活点；撤退不回血，也不重置敌人生命。
- 死亡显示 `YOU DIED`，自动回最近休息篝火或入口，满血复活并打开本场复盘；课程、XP、
  装备、门和敌人剩余生命保留。
- 随机即时恢复概率为：普通 / 必修怪 `2%`、小型精英 `5%`、区域 Boss `10%`、楼层 Boss
  `0%`。命中后立即使用，不进入背包；随机装备不会掉落。
- 课程武器、钥匙、明确宝箱和主线证据是确定奖励，不受随机概率影响。

## 6. 篝火、抄写员与《失名录》

每层中、后阶段各有一座实体篝火；入口是前段安全区和兜底复活锚点。靠近篝火按 `E`：

- `在此休息`：恢复满生命 / 护甲，并把这里设为默认复活点；
- `答案复盘`：当前层精英击败前禁用；解锁后查看本层提交过的 SQL、参考答案、错误分类、
  提示等级和结果。

抄写员与篝火相互独立，只总结本层已经发生的事实，不会替玩家答题。顶部《失名录》入口保存每层五个短叙事拍、
固定证据和七段上升路线；证据状态严格区分 `???`、`NULL` 和实际值。第八层通关后完成唯一
主线结局 `MIGRATE`。

## 7. 音乐、性能与隐私

- 第一、二层音乐由项目生成并导出为连续 OGG/MP3，主题取自公版作品；第三至八层保留轻量
  Web Audio 降级，角色、怪物与事件音效继续使用低开销项目代码。
- 第一、二层探索、战斗和 Boss 曲目以 1.2 秒交叉淡化切换；不再使用持续嗡鸣底床。
- 游戏目标 30 FPS；页面隐藏时暂停 Phaser 与音频调度，恢复后不会重复创建循环。
- Run、永久掌握、引导和最多 200 条 SQL 作答记录只保存在浏览器本地，不上传服务器。

## 8. 管理员模式

管理员模式用于检查八层全图、三个区域、怪物、首领和交通节点。预览快照不会写入正式 Run。
它是内容 QA 工具，不提供课程掌握、XP 或奖励捷径。

### Dungeon Maintainer 开发桥边界

维护器只在本地开发试玩页加载协议 1.0 开发桥，要求同时满足 Vite 开发模式、本机地址
（127.0.0.1、localhost 或 [::1]）以及 playtest=agent 查询参数。

模型只获得受限的 look、act、query 语义动作；prepare、checkpoint、judge、events 只供外层评测与
验证流程使用。协议不接受选择器、鼠标轨迹或任意 JavaScript。检查点只使用临时 sessionStorage，恢复后
立即消费；正式 Run、IndexedDB、localStorage 存档和用户 Chrome Profile 不会被维护器读取。

统一 Chromium Shell 会把本游戏嵌入右侧 iframe。生产构建必须移除开发桥全局，发布前在 game/dist
执行固定字符串搜索，预期不再包含 __DUNGEON_PLAYTEST__。

## 9. 当前发布边界

自动化测试和生产构建已覆盖核心规则。完整整局、真实音频设备和逐字文案仍需人工复核；这些调整不得改变课程答案、剧情事实、掉率、
存档或版权边界。
