# 篝火、复活点与安全区实现契约

> 状态：`v0.3.0` 已实现并完成本地自动化、构建与桌面浏览器关键流程验证
> 范围：本轮实现实体篝火、复活点、安全区、死亡复盘、遭遇节奏和卡片生命周期；
> 捷径、背包、防具与随机装备掉落仍是后续候选
> 版本顺序与跨系统边界以 [`GAMEPLAY_EVOLUTION_ROADMAP.md`](../GAMEPLAY_EVOLUTION_ROADMAP.md) 为统一入口。

## 1. 本次目标

让篝火成为地图中的休息与复活节点。玩家死亡后不结束本轮游戏，而是自动回到最近一次休息的篝火，并通过本地答案记录完成复盘。

## 2. 用户与体验目标

- 玩家：正在通过像素肉鸽学习 SQL 的初学者和面试复习者。
- 体验目标：减少死亡后从头开始的挫败感，让篝火成为明确的阶段节点。
- 学习目标：死亡后先看清本次 SQL 错误，再继续挑战。
- 性能目标：不使用 Agent、模型 API、后端服务或额外网络请求。

## 3. 已确认规则

### 3.1 篝火数量与位置

- 每张地图存在 3 个篝火。
- 三个篝火按前期、中期、后期三个区段分别随机分布，每个区段一个。
- 同一局游戏刷新页面后，篝火位置不能发生变化。
- 篝火必须位于可行走位置，且不能阻塞必经通道、知识门或掉落物。
- 三个篝火都可以被玩家使用，不区分主篝火和次篝火。

### 3.2 篝火交互

玩家靠近篝火并按 `E` 后，显示两个选择：

1. `在此休息`
2. `答案复盘`

选择 `在此休息` 后：

- 恢复至当前最大生命值。
- 当前篝火自动成为新的复活点，不再要求玩家执行额外的“设为复活点”操作。
- 后续在同一层死亡时，自动回到这个篝火。
- 玩家之后在另一处篝火休息，复活点自动替换为新的篝火。

选择 `答案复盘` 后：

- 展示当前楼层已经产生的 SQL 作答结果。
- 展示玩家答案、正确答案和直接的错误原因。
- 不调用 AI，不消耗 Token，也不需要 API Key。
- 查看复盘不会改变生命值、经验、装备或复活点。

### 3.3 死亡与复活

- 生命值归零后不再结束当前 Run。
- 游戏自动将玩家送回最近一次选择过 `在此休息` 的篝火。
- 如果玩家尚未在任何篝火休息，则返回当前楼层的出生点。
- 复活后恢复至当前最大生命值。
- 复活后自动进入导致本次死亡的单场战斗复盘，再由玩家选择继续探索。
- 死亡不会删除已获得的 SQL 掌握记录。
- 导致玩家死亡但尚未被击败的怪物保持死亡瞬间的剩余生命值，不恢复满血。
- 已经击败的怪物继续保持死亡。
- 玩家已经获得的经验、武器、道具和已打开的门保持不变。

### 3.4 安全区

- 当前楼层出生房间的全部可行走格属于出生安全区。
- 每个篝火使用同一份确定性安全格掩码同时驱动规则判定与可见边界，不能出现“看起来安全但
  实际遇敌”或“看不见的安全半径”。
- 篝火中心是实体阻挡格；玩家站在相邻可行走格按 `E` 交互。
- 安全区内不会生成怪物。
- 安全区内不会触发随机遭遇战。
- 巡逻怪物不能进入安全区。
- 玩家站在安全区中时，可以安全查看菜单和答案复盘。

### 3.5 遭遇节奏与卡片生命周期

- 初始与战后安全期结束后，只有安全区外、符合条件的成功移动才参与突发遭遇判定。
- 每个符合条件的成功移动采用 `2%` 基础概率；连续 `30` 个符合条件的安静步数后保底触发。
- 判定由稳定种子和已保存计量状态决定，刷新不能重抽。
- 战后 XP 结算卡与物品说明卡从出现时开始计数，在之后完成 `3` 次成功移动后消失。
- 撞墙、打开菜单、查看复盘和普通按键都不计入这 3 次移动。

## 4. MVP 范围

本功能后续实现时只包含：

- 每层 3 个稳定随机的篝火位置。
- 篝火的两个交互选择。
- 休息、满血和自动更新复活点。
- 死亡后自动返回复活点。
- 出生点和篝火安全区。
- 本地答案复盘入口。
- 当前 Run 中必要的本地存档。
- 安全区外 `2%` 基础突发遭遇与 `30` 个符合条件步数保底。
- 战后结算卡和物品说明卡的 3 次成功移动生命周期。

## 5. 本次不做

- 不接入 Agent 或大模型。
- 不加入云端账号和跨设备同步。
- 不加入篝火传送。
- 不加入篝火升级、烹饪、商店或技能树。
- 不通过篝火复活已击败的怪物。
- 不让篝火自动替玩家完成 SQL。
- 不改动八层课程规划和怪物数值。
- 不加入 12 格背包、防具生命或通用随机装备掉落系统。
- 不实现第三至八层。

## 6. 地图种子与引导规则

地图不能采用不受约束的纯随机。推荐使用“种子决定变化、规则保证体验”的受控生成：

```text
地图种子
→ 生成必修课程主路径
→ 生成可选支路与回环
→ 在前/中/后区段各放置一个篝火安全区
→ 放置捷径门与对应钥匙
→ 放置怪物、宝箱和掉落
→ 验证可达性、课程顺序和安全区
→ 不合格时执行有限修复，而不是换一个不可追踪的新种子
```

同一个地图种子、楼层编号和生成器版本应得到相同的：

- 地图通路与房间位置。
- 三个篝火和安全区。
- 捷径门与钥匙位置。
- 固定怪物、宝箱及其掉落判定。

玩家刷新页面或读取存档时不能重新抽取结果。种子只控制“这一局长什么样”，课程依赖、必需武器和通关路径仍由规则控制。

### 6.1 地图必须满足的引导

- 出生点能够到达第一道必修课程。
- 每个阶段至少存在一条清晰的前进路线，且不能由钥匙或随机掉落卡死。
- 前、中、后三个篝火依次出现在合理的探索距离上，不能聚集。
- Boss 前必须存在可返回后期篝火的路线。
- 支路可以藏宝物和高难题，但不能把必修课程伪装成无提示死路。
- 捷径只能减少重复赶路，不能绕过必修 SQL 课程和 Boss 条件。

## 7. 捷径钥匙提案

地图可以出现由钥匙开启的捷径，这与“受控随机”并不冲突。推荐规则：

- 每层生成 1 至 2 道捷径门，具体连接位置由种子决定。
- 捷径连接已经探索过的前后区域，用于缩短死亡后的返回路线。
- 捷径门在早期一侧可以被看见，但钥匙必须从中后段的可达区域获得。
- 捷径不能跳过尚未完成的 SQL 课程、知识门或 Boss 条件。
- `捷径钥匙` 与通往下一层的 `楼层钥匙` 使用不同名称、图标和用途。
- 捷径一旦开启，在当前 Run 中永久保持开启，死亡和休息都不会重新关闭。
- 捷径钥匙应保证能够获得，不能依赖普通怪物的随机掉落。

待讨论：

- 每层固定 1 道捷径，还是允许种子生成 1 至 2 道？
- 拿到钥匙后自动开启匹配捷径，还是玩家靠近门后按 `E` 开启？
- 一把钥匙开启本层所有捷径，还是每道捷径需要自己的钥匙？

## 8. 普通怪物越阶武器提案

普通怪物可以用很低的概率掉落下一层武器，作为肉鸽中的惊喜事件，但不能破坏 SQL 学习顺序。推荐规则：

- 普通怪物约有 `0.25%` 概率掉落下一层的一件武器。
- 一层最多出现 1 件越阶武器，不会连续掉落。
- 越阶范围最多提前 1 层，不能在第一层直接获得高出多层的装备。
- 掉落由“地图种子 + 楼层 + 怪物 ID”稳定决定，刷新页面不能反复抽取。
- 普通怪物和掉落不会因篝火休息而刷新，因此不能反复刷取。
- 越阶武器只提高战斗属性，不能自动解锁下一层 SQL、知识门或课程。
- 必修课程怪物仍保留最低正确作答回合数，越阶武器不能把多道 SQL 题压缩成一击。
- 必修课程仍保留确定性武器奖励，随机运气不能成为通关必要条件。
- 如果玩家之后再次命中同一件确定性武器，应转化为磨刀石；达到强化上限后再转化为 1 XP。

待讨论：

- `0.25%` 是否符合想要的稀有程度？
- 越阶武器是否可以从突发遭遇怪物掉落，还是只允许地图中的固定普通怪物？

本节只保留为 `v0.4.0` 之后的候选设计。当前运行时不存在通用随机装备掉落系统；
课程宝箱、必需武器和钥匙仍按 `100%` 确定获得，不参与减半。

## 9. 复盘内容边界

死亡后的自动复盘只展示导致本次死亡的单场战斗：

- 本场提交过的 SQL。
- 每次错误的直接原因。
- 当前问题的正确答案。
- 一个 `重新出发` 按钮。

篝火中的 `答案复盘` 展示当前楼层从进入到现在的全部作答记录。进入下一层后开始新的楼层复盘记录；上一层记录可以保留在永久学习图鉴中，但不混入当前层列表。

## 10. 概念数据

`v0.3.0` 至少保存以下状态：

```text
当前楼层的三个篝火位置
最近一次休息的篝火
当前复活位置
当前楼层的 SQL 作答记录
导致本次死亡的战斗记录
符合条件的成功移动与遭遇计量
```

只记录 SQL 作答、提示和战斗结果，不记录玩家的每一步移动或每次按键。
捷径门/钥匙与随机掉落判定属于后续存档版本，不在 `v0.3.0` 中提前实现。

## 11. 验收标准

后续实现完成时应满足：

1. 每张地图恰好出现 3 个可到达的篝火。
2. 同一个种子和存档中的篝火位置保持稳定。
3. 在任意篝火选择 `在此休息` 后，玩家恢复满血，该篝火立即成为新复活点。
4. 玩家死亡后自动返回最后休息的篝火；没有休息记录时返回出生点。
5. 出生点和三个篝火的安全区内不会生成、触发或巡逻进入怪物。
6. `答案复盘` 完全由本地记录生成，断网时仍然可用。
7. 死亡与复活不会删除玩家已经获得的经验、装备、道具和课程进度。
8. 篝火不能阻挡道路、门、Boss、课程怪物或关键掉落。
9. 导致玩家死亡的怪物在复活后保持剩余生命值。
10. 死亡复盘只包含本场战斗，篝火复盘包含当前楼层。
11. 地图种子不能生成无法取得钥匙、无法完成课程或无法到达 Boss 的死局。
12. 安全区外突发遭遇采用 2% 基础概率，并在 30 个符合条件的安静步数后保底。
13. XP 结算卡和物品说明卡只在 3 次成功移动后消失。

## 12. 风险与取舍

- 安全区必须具有清楚的视觉边界，否则玩家无法判断什么时候可能遇敌。
- 未击败怪物在玩家死亡后保留残血，会允许玩家通过复活逐渐消耗 Boss；这是当前明确选择，需要通过赶路、复盘或其他轻量成本维持挑战感。
- 捷径钥匙若依赖随机掉落，可能形成无法开启的死局，因此只能随机位置，不能随机是否存在。
- 越阶武器概率过高会削弱下一层奖励，概率过低又可能几乎无人见到。
- 种子必须拆分稳定的地图、掉落等随机阶段，避免调整装饰后意外改变钥匙或课程位置。
- 保存复活点和答案历史会改变当前 Run 存档结构，正式实现时必须决定存档升级或恢复策略。
- 三个篝火必须经过地图可达性验证，不能只检查格子是否可行走。
