## 1. 设计目标、用户与边界

### 1.1 设计目标

1. 怪物首先属于地点和生态，其次才承担 SQL 题目。
2. 玩家进入战斗前能凭轮廓区分史莱姆、猎犬、水蛇、青蛙、树妖和 Boss。
3. 未发现身份时只显示 ID；最终击败后以强反馈恢复名字。
4. 同名个体允许存在，但 ID、栖息地、形态和课程必须可区分。
5. 普通怪承担一阶复习，小型精英承担两段复合，区域 Boss 改变地图，楼层 Boss回答本层问题。
6. HP 不替代阶段设计；高攻击装备也不能跳过 SQL。
7. 普通怪大概率不掉落，关键奖励完全确定。
8. 图鉴是学习、生态和剧情档案，不是答案抄写页。

### 1.2 用户 / 干系人

| 用户 / 干系人 | 核心需求 |
|---|---|
| 新玩家 | 一眼看懂敌我、危险、ID 和意图 |
| SQL 学习者 | 记住怪物对应的概念、常见错误和字段 |
| 探索玩家 | 发现地区生态、支线 Boss 和世界变化 |
| 美术 / 动画 | 获得明确轮廓、动作、层级和 VFX 需求 |
| 内容策划 | 通过配置增加怪物，不复制战斗逻辑 |
| QA | 可按 ID、阶段和状态稳定复现 |

### 1.3 MVP 2.1 范围

必须完成：

- F1 ID 001–009；
- F2 ID 010–022；
- 四类普通角色与三类 Boss；
- 击杀、名字恢复、XP、无掉落/掉落、图鉴完整结算；
- 已发现名字跨 Run 保留；
- 管理员模式可切换未发现/已发现并直达 Boss 状态；
- F1/F2 正式视觉不再依赖通用方块。

本轮不做：

- 不实现捕捉、养成或怪物伙伴；
- 不让普通怪永久无限刷新；
- 不增加随机词缀名、幻影名或装饰后缀；
- 不为 Boss 增加自由动作弹幕；
- 不随机掉落武器、防具、钥匙或剧情证据；
- 不在图鉴中提前展示完整参考 SQL；
- 不重做第三至八层全部模型。

## 2. 标准功能契约

本文每项以六字段描述：

| 字段 | 含义 |
|---|---|
| 触发 `Trigger` | 遭遇、阶段、击杀或打开图鉴的时机 |
| 输入 `Input` | 怪物配置、玩家进度、SQL 结果、地图状态 |
| 状态 `State` | 身份、HP、阶段、Boss 状态、是否已结算 |
| 输出 `Output` | 战斗、视觉、世界、奖励和图鉴结果 |
| 失败兜底 `Fallback` | 资源、状态、死亡或重复事件异常后的行为 |
| 验收 `Acceptance` | 自动化和试玩可证明的完成条件 |

## 3. 怪物分类与生成

### 3.1 分类

| 分类 | 作用 | 阶段 | 生成 | XP | 随机掉落 |
|---|---|---:|---|---:|---:|
| 课程怪 | 首次教学和主线环境改变 | 1–2 | 固定可见，不随机 | 普通 1 / 精英 3 | 按等级；关键奖励另算 |
| 普通生态怪 | 已学概念复习、地区生态 | 1 | 2% 随机遭遇或少量可见巡逻 | 1 | 2% 恢复品 |
| 小型精英 | 两个已学知识组合 | 2 | 稀有可见或随机池 | 3 | 5% 恢复品 |
| 区域 Boss | 改变潮位、路线或地区状态 | 2–3 | 固定、主动挑战 | 5 | 10% 恢复品 + 确定世界结果 |
| 楼层 Boss | 回答本层问题并开下一层 | 2–4 | 固定 Boss 区 | 5 | 0% 随机 + 确定钥匙/证据 |

### 3.2 随机遭遇

| 字段 | 契约 |
|---|---|
| 触发 | 玩家完成一次合法移动后独立判定 2% |
| 输入 | 当前楼层、生态区域、已掌握课程、安全步 |
| 状态 | 非出生区、非篝火安全区、非演出、非战斗 |
| 输出 | 只从已学题池选择怪物；进入一阶段复习 |
| 失败兜底 | 连续 30 个合格步骤未触发时保底一次；触发后 5 步安全 |
| 验收 | 不能刷出未学语法、Boss 或主线证据怪 |

随机种子可以决定候选和出现位置，但不能决定：

- 主线怪是否存在；
- Boss 是否存在；
- 关键奖励是否掉落；
- 名字和图鉴是否解锁；
- 地图状态是否完成。

### 3.3 可见巡逻

| 字段 | 契约 |
|---|---|
| 触发 | 玩家进入生态区 |
| 输入 | 巡逻路径、碰撞网格、安全区 |
| 状态 | 怪物存活、未处于演出 |
| 输出 | 怪物沿短路径移动；接触玩家进入战斗 |
| 失败兜底 | 路径无效则回锚点，不穿墙、不压在篝火或道具上 |
| 验收 | 青蛙、猎犬、水蛇、树妖不会显示或碰撞成墙 |

## 4. 身份生命周期

### 4.1 状态机

```text
UNKNOWN
→ ENCOUNTERED
→ FINAL_QUERY_PENDING
→ IDENTIFIED
→ MASTERED（可选图鉴完成状态）
```

| 状态 | 世界显示 | 图鉴 | 持久化 |
|---|---|---|---|
| `UNKNOWN` | 轮廓或不可见；无名字 | 锁定条目 | 不保存额外状态 |
| `ENCOUNTERED` | `ID #xxx`、HP、意图 | 本 Run 可显示 ID 和发现地点 | 可从本 Run 访问/答题记录派生 |
| `FINAL_QUERY_PENDING` | 仍是 ID | 不更新 | 瞬时状态 |
| `IDENTIFIED` | `名字 · ID #xxx` | 完整基础条目 | `profile.discoveredMonsterIds` |
| `MASTERED` | 同 IDENTIFIED | 增加本层复盘印章 | 从课程掌握与 Boss 证据派生 |

### 4.2 未发现时允许显示

- ID；
- 当前 HP 和最大 HP；
- 普通 / 精英 / Boss 危险级别；
- 下一次反击伤害；
- 攻击意图的行为描述；
- 与地形一致的轮廓和动作；
- 本回合需要的 SQL 概念。

禁止显示：

- 真名；
- `species` 代号；
- 图鉴 lore；
- 掉落物名称；
- 以真名命名的攻击；
- 任务标题、提示或错误中的真名；
- 其他 UI 通过 `monster.name` 拼接的文本。

攻击名在未发现时使用行为别名，例如：

| 真名攻击 | 未发现显示 |
|---|---|
| 登记官“注销印” | `印章正在落下` |
| 湖兽“深水冲击” | `深水正在抬升` |
| 灯塔守卫“多数强光” | `强光正在聚焦` |

### 4.3 名字恢复原子事件

| 字段 | 契约 |
|---|---|
| 触发 | 最终阶段查询 accepted，目标 HP 归零 |
| 输入 | monster ID、true_name、最终 SQL 结果、图鉴内容、XP |
| 状态 | 未发现，且本次结算尚未提交 |
| 输出 | 短停顿 → 数据碎片 → `ID → name` → 图鉴盖章 → XP → 掉落/无掉落 → 世界变化 |
| 失败兜底 | 任一视觉资源失败时仍以文字、闪白、音效替代；状态只提交一次 |
| 验收 | 名字、XP、图鉴、奖励和世界事件不会重复或部分写入 |

推荐时序：

```text
0 ms      最终命中
0–150 ms  短停顿；Reduced Motion 使用轮廓闪白
150–450   怪物轮廓拆成数据行
450–800   ID #xxx 固定在中央
800–1200  NAME RECOVERED / 真名
1200–1600 图鉴盖章与 XP 飞入 HUD
1600+     掉落和世界变化
```

普通击杀反馈可以缩短，但不能省略 ID、名字、XP 和掉落结算。

### 4.4 跨 Run 行为

- 已发现 ID 在新 Run 中从首次看见起显示真名与 ID；
- 不需要再次隐藏并恢复；
- 新 Run 仍需完成对应课程和战斗；
- 图鉴不会自动给出新 Run 的完整答案 SQL；
- 同名怪物分别按 ID 保存，不能用名字作为主键。

## 5. 第一层生态规格

### 5.1 生态主题

第一层生物共享“软体记录”母题：

- 水与泥代表尚未定形的行；
- 铁块代表聚合后的记录；
- 纸页和铜印从普通史莱姆逐步过渡到登记官；
- 同骨架可以复用基础帧，但水、毒、铁和 Boss 必须有不同轮廓。

|---:|---|---|---|---|---:|---|---:|---|
| 1 | 史莱姆 | 课程普通 | 水轮大厅 | SELECT / FROM | 2 | 12 / 0 / 1 | 1 | 过滤弓、水轮启动 |
| 2 | 水史莱姆 | 课程普通 | 排水渠 | WHERE / AND | 2 | 14 / 0 / 1 | 1 | 水位下降 |

| 5 | 登记官 | 楼层 Boss | 登记大厅 | HAVING 综合 | 2 | 24 / 0 / 1 | 5 | 钥匙、恢复权限证据、《失名录》第一页 |

### 5.3 第一层逐怪遭遇契约

| ID | 触发 | 输入 | 前置状态 | 输出 | 失败兜底 | 验收 |
|---:|---|---|---|---|---|---|
| 1 | 首次抵达水轮大厅并接触 | ID、怪物主表、两段 SELECT | 未学 SELECT；水轮停止 | 首次完整战斗循环、名字恢复、水轮启动、过滤弓 | 死亡回出生区；身份不提前提交 | 10 分钟内可完成第一次名字恢复 |
| 2 | 水轮启动后进入排水渠 | 房间、状态、ID | SELECT 完成；高水位 | 过滤正确目标、水位下降 | 错误不打开水闸 | 不能要求玩家用未知名字过滤 |
| 3 | 水位下降后进入宿舍 | room_id、master_id、status | WHERE 完成；床牌隐藏 | 明确 `NULL`、床牌显形、空值提灯 | `= NULL` 给专项反馈 | 玩家能解释空值不是空字符串 |
| 4 | WHERE 与 NULL 完成后进入档案室 | 多条 signal 行 | 分支均完成；回执散乱 | 分组、精英击杀、聚合战锤 | 错误不移动回执 | 屏幕中可见“行被分成组” |
| 5 | 必修完成并回访登记厅 | 分组信号和恢复规则 | 捷径开；`registry=awake` | 改写规则、钥匙、证据、升降机 | 死亡重置本场 Boss，不撤销捷径 | Boss 不以普通厚血软泥的死亡动画收尾 |
| 6 | 已学 SELECT 后排水区随机遭遇 | 一阶段 SELECT | 非安全区 | 轻量复习与名字 | 5 安全步；不掉关键物 | 只出现已学内容 |
| 7 | 已学 WHERE 后软泥区随机遭遇 | 双条件过滤 | 非安全区 | 轻量复习与名字 | 同上 | 不替代主线课程 |
| 8 | 已学 NULL 后仓窖随机遭遇 | IS NULL + AND | 非安全区 | 轻量复习与名字 | 同上 | 不使用未知真名做输入 |
| 9 | 仓窖稀有精英池 | 分组后身份查询 | GROUP BY 已学 | 3 XP、名字、低概率恢复品 | 可撤退；死亡重置两段 | 两阶段不被高伤武器跳过 |

### 5.4 第一层视觉与动作

| ID / 类别 | 必须轮廓 | 动作 | 禁止 |
|---|---|---|---|
| 史莱姆系 | 低矮软体、明确底部接地 | 呼吸、压缩、跳动 | 单一方块只换色 |
| 水史莱姆 | 身体内有水轮碎片和水滴尾迹 | 液体晃动、跳跃溅水 | 与普通史莱姆完全同轮廓 |
| 毒史莱姆 | 背负空床牌，表面有危险斑点 | 滴落、后缩喷溅 | 只靠绿色表示毒 |
| 铁史莱姆 / 铁泥怪 | 多块软体聚成，边缘有铁片 | 聚合、分裂、重新结合 | 像墙砖或宝箱 |
| 登记官 | 湿泥、纸页、铜印、旧锁 | 印章下压、纸页展开、规则停止 | 王冠大型软泥换色 |

碰撞体使用身体底部，不覆盖头顶名字或大幅纸页装饰。

## 6. 第二层生态规格

### 6.1 生态主题

第二层按地点形成三条生态链：

```text
湖泊：水怪 → 水蛇 → 湖兽
泥沼：青蛙 → 毒蛙 → 蛙王
林岛：猎犬 → 树妖 → 灯塔守卫控制的航标秩序
```

生态链用于：

- 决定随机复习池；
- 解释同名怪物为何在不同地点出现；
- 让区域 Boss 与普通怪有视觉和行为继承；
- 在图鉴中形成关系，不改变 SQL 主键。

### 6.3 第二层逐怪遭遇契约

| ID | 触发 | 输入 | 前置状态 | 输出 | 失败兜底 | 验收 |
|---:|---|---|---|---|---|---|

## 7. Boss 系统

### 7.1 Boss 通用原则

1. Boss 通过阶段和世界规则形成难度，不通过单纯增加 HP。
2. 每阶段使用不同认知动作，不重复完全相同 SQL。
3. Boss 入场展示错误规则，胜利展示规则被修正。
4. 区域 Boss 必须改变地图；楼层 Boss 必须改变本层结论。
5. Boss 名字在最终结算前仍隐藏。
6. Boss 掉落关键物完全确定，随机池不承载进度。
7. 撤退和死亡都重置未提交阶段与世界状态；撤退回滚怪物 HP，死亡保留怪物剩余 HP。

Boss UI 用“规则阶段”替代只看 HP：

```text
ID #005
注销规则 0 / 2
HP 24 / 24
下一意图：印章正在落下
```

### 7.2 登记官 ID #005

#### 核心幻想

登记官不是邪恶魔王，而是把“当前表中 0 行”错误解释成“不存在”的旧规则执行者。玩家不是摧毁它，
而是迫使它承认恢复轨迹也是证据。

#### 阶段

| 阶段 | 触发 | 输入 | 状态 | 输出 | 失败兜底 | 验收 |
|---|---|---|---|---|---|---|
| 入场：0 行 | 进入登记大厅 | 当前记录与恢复权限演出 | `registry=awake` | Boss 尝试注销；显示本层问题 | 演出可跳过，证据仍进入档案 | 复用开场只读 `residents` 查询已提交的 0 行证据；Boss 阶段不重复查询 |
| 1：有效组 | 提交 HAVING ≥2 | ID #005 信号 | 规则护盾完整 | echo 与 ward 两组显形，护盾裂开 | 错误使用“注销印”反击 1 | 世界纸页和 UI 同步变更 |
| 2：可靠轨迹 | 提交 HAVING ≥3 | 同一信号 | 护盾已裂 | 只保留 echo，停止注销 | 死亡重置两阶段演出并保留剩余 HP | 最终不重复第一条查询 |
| 结算：修正规则 | 阶段 2 通过 | 身份、证据、奖励 | 未结算 | 揭名“登记官”；规则改为 `RESTORE TRACE ACCEPTED` | 视觉失败使用文本/音效 | 钥匙、5 XP、证据只发一次 |

#### 表现

- 第一阶段铜印压住纸页；
- 正确查询后纸页按组升起；
- 最终铜印停在半空，不爆炸消失；
- 红色规则逐字改为金色；
- 登记官可以保留为不再敌对的设施残骸。

### 7.3 湖兽 ID #021

#### 核心幻想

玩家不在水里盲目砍击，而是通过信号顺序判断湖兽浮出，再通过去重分辨真实波纹。

| 阶段 | 触发 | 输入 | 状态 | 输出 | 失败兜底 | 验收 |
|---|---|---|---|---|---|---|
| 观察 | 调查深潭或主动挑战 | 湖面波纹 | 潮位高 | 展示多个重复波纹，不揭名 | 玩家可以离开 | 不强制第一次看到就战斗 |
| 1：浮出排序 | ORDER BY / LIMIT 通过 | 五条 signal | 潜伏 | 锁定两次最高信号，露出完整轮廓 | 错误“深水抬升”反击 2 | 不是查询单一 `status` |
| 2：真实波纹 | DISTINCT 通过 | deep/surge/wake | 已浮出 | 击败、揭名、潮位提交为低 | 死亡恢复高潮位与阶段演出，保留剩余 HP | 世界变化只在最终阶段提交 |
| 结算 | 身份事件完成 | 湖兽、潮位、船闸 | 未结算 | 5 XP、10% 恢复品判定、船闸权限 | 掉落失败不影响船闸 | 村落、浅滩、船闸同时变化 |

### 7.4 蛙王 ID #022

#### 核心幻想

蛙王利用“装备明细中没有记录”隐藏在泥宫。它是本层可选的 JOIN 综合挑战，而非主线门锁。

| 阶段 | 触发 | 输入 | 状态 | 输出 | 失败兜底 | 验收 |
|---|---|---|---|---|---|---|
| 支线发现 | 退潮后调查门牌 | 泥宫、无装备线索 | 支线未完成 | 显示 ID #022 与危险预告 | 可以拒绝挑战 | 不阻塞灯塔 |
| 1：缺失装备 | LEFT JOIN 通过 | monsters + monster_gear | 泥冠护甲完整 | 护甲消失 | 反击 2；可撤退 | 检查右表 NULL |
| 2：来源房间 | JOIN + DISTINCT 通过 | monsters + rooms | 护甲已破 | 击败、揭名、泥宫踏石出现 | 死亡重置阶段演出并保留剩余 HP | 最终阶段才显示 name |
| 结算 | 最终通过 | 藤甲、XP | 未结算 | 5 XP、藤甲、安全踏石 | 背包满时藤甲进入保留宝箱 | 不随机掉第二件装备 |

### 7.5 灯塔守卫 ID #014

#### 核心幻想

灯塔守卫把“出现最多、信号最强”当作唯一真实。这个规则在海上可以救人，用于身份记录却会抹掉
少数来源。

| 阶段 | 触发 | 输入 | 状态 | 输出 | 失败兜底 | 验收 |
|---|---|---|---|---|---|---|
| 入场：多数规则 | 进入灯塔岛 | 七页记录、地区统计 | 只照亮多数 | 七束光收束成一束 | 演出可跳过 | 玩家能看见被遮蔽记录 |
| 1：多地区证据 | JOIN + GROUP + HAVING 通过 | lake/swamp/forest | 规则完整 | 三地区均被承认为可靠 | 错误“强光聚焦”反击 2 | 不再返回 `ambush/storm` |
| 2：主透镜 | 装备 JOIN + Top-1 通过 | ID #014 装备 | 核心暴露 | 关闭覆盖透镜，最终击败 | 死亡重置阶段演出并保留剩余 HP | 真名在此后才显示 |
| 结算：七束光 | 最终通过 | 身份、钥匙、七页 | 未结算 | 揭名、5 XP、钥匙、七页、渡船 | 任一资源失败使用静态光束和文字 | 不出现“丛林王”残留 |

灯塔守卫不会倒塌成废墟；它停止覆盖后继续作为多方向灯塔工作。

## 8. 掉落、奖励与结算

### 8.1 独立概率

每个随机候选独立判定，同一战斗不重复同 ID：

| 角色 | 恢复品概率 | 随机武器/防具 | 关键物 |
|---|---:|---:|---:|
| 普通怪 | 2% | 0% | 无 |
| 小型精英 | 5% | 0% | 无 |
| 区域 Boss | 10% | 0% | 确定世界结果 |
| 楼层 Boss | 0% | 0% | 钥匙、证据、楼层进度 |

“2%”表示大概率没有任何随机物品，不是至少掉一件。

随机恢复品：

- 若当前受伤且恢复品设定为即时使用，直接结算生命变化；
- 若生命已满，不产生无意义掉落或塞满背包；
- 大型战利品面板只在确实有多件可选物时打开；
- 无掉落使用小型文字“本次没有发现可用物品”。

### 8.2 确定奖励

| 来源 | 奖励 | 触发 | 失败兜底 |
|---|---|---|---|
| ID #001 | 过滤弓 | 课程结算 | 地面位置无效则进入固定宝箱 |
| ID #003 | 空值提灯 | 课程结算 | 同上 |
| ID #004 | 聚合战锤 | 聚合档案室结算 | 不受随机和背包满影响 |
| ID #005 | 第一层钥匙、恢复权限证据、《失名录》第一页 | Boss 结算 | 关键物直接进入关键栏 |
| ID #010 | 雷序军刀 | 课程结算 | 固定宝箱 |
| ID #012 | 关系链刃 | 课程结算 | 固定宝箱 |
| ID #021 | 退潮、船闸权限 | 区域 Boss 结算 | 与物品背包无关 |
| ID #022 | 藤甲 | 可选 Boss 结算 | 背包满时保留在泥宫宝箱 |
| ID #014 | 第二层钥匙、七名记录页 | 楼层 Boss 结算 | 关键栏直接接收 |

### 8.3 结算顺序

```text
击杀视觉
→ 名字恢复
→ 图鉴盖章
→ XP / 升级
→ 确定奖励
→ 随机恢复品或无掉落
→ 世界状态
→ 下一目标
```

不得让随机战利品面板遮住名字恢复或 Boss 世界变化。

## 9. 图鉴系统

### 9.1 产品职责

图鉴需要同时回答：

1. 我遇见了谁；
2. 它生活在哪里；
3. 它守护什么 SQL 概念；
4. 我通过哪些字段确认了它；
5. 它和本层生态、剧情有什么关系；
6. 它可能掉什么；
7. 我是否已经掌握对应课程。

图鉴不提供：

- 未发现怪物真名；
- 未进入地区的完整模型；
- 完整参考 SQL；
- Boss 后续阶段答案；
- 隐藏支线精确位置。

### 9.2 图鉴条目字段

| 字段 | 未发现 | 已遭遇未击败 | 已发现 |
|---|---|---|---|
| ID | 可显示楼层内未知格 | 显示 | 显示 |
| 真名 | `尚未获得名字` | 隐藏 | 显示 |
| 楼层 / 栖息地 | 模糊楼层 | 当前发现地区 | 精确地点 |
| 剪影 / 模型 | 锁定轮廓 | 剪影 | 完整模型/立绘 |
| 种族 | 隐藏 | 隐藏 | 玩家可读中文种类 |
| 等级 | 隐藏 | 危险级别 | 普通/精英/区域 Boss/楼层 Boss |
| SQL 概念 | 隐藏 | 当前回合概念 | 完整概念列表 |
| 发现字段 | 隐藏 | 本回合字段 | 击败时实际使用字段 |
| 行为 / 攻击 | 隐藏 | 当前意图 | 完整行为描述 |
| 生态关系 | 隐藏 | 模糊 | 完整关系链 |
| 掉落 | 隐藏 | “未知” | 概率和确定奖励 |
| 世界作用 | 隐藏 | 模糊目标 | 已发生的世界变化 |
| lore | 锁定说明 | 一句未确认记录 | 完整线索 |
| 掌握状态 | 无 | 进行中 | 已识别 / 已掌握 |

### 9.3 已发现字段

“发现字段”记录字段名和含义，不复制答案 SQL。例如：

```text
ID #012 · 树妖
发现字段：
- monsters.id：怪物主键
- monsters.room_id：所在房间
- rooms.id：房间主键
- rooms.name：房间名
关系：
- monsters.room_id = rooms.id
```

这样图鉴可以帮助复习 JOIN，但不会变成答案抄写页。

### 9.4 图鉴排序与重复名字

- 主排序：floor，再按 monster ID；
- 支持筛选：未发现、已发现、课程、生态、Boss；
- 同名怪物分别显示：

```text
水蛇 · ID #011 · 月影湖 · 课程个体
水蛇 · ID #016 · 镜潮湾 · 生态个体
```

- 不按名字去重；
- 详情页显示它们的生态关系，但不共享击杀状态。

### 9.5 持久化

目标优先复用当前 Profile：

- `discoveredMonsterIds`：永久名字发现；
- `masteredLessons`：课程掌握印章；
- 本 Run 的 `visitedRoomIds / answerHistory`：遭遇和发现字段；
- 静态内容：栖息地、生态、lore、掉落说明。

第一版不需要把完整图鉴正文复制进存档。

若未来新增：

- 击杀次数；
- 特殊形态；
- 可选 lore 页；
- 图片拍摄状态；

再升级 Profile 版本，不提前扩字段。

### 9.6 图鉴打开契约

| 字段 | 契约 |
|---|---|
| 触发 | 点击“怪物图鉴”或对应快捷键 |
| 输入 | 当前楼层、Profile、当前 Run 记录、静态内容 |
| 状态 | 探索、篝火可打开；战斗中只允许简版目标卡 |
| 输出 | 楼层标签、发现计数、条目列表和详情 |
| 失败兜底 | 某个模型资源失败时显示剪影与文字 |
| 验收 | ESC、键盘焦点、触屏、320 px 和 Reduced Motion 可用 |

## 10. 怪物与图鉴反馈

### 10.1 世界标签

| 状态 | 标签 |
|---|---|
| 未发现普通怪 | `ID #007` |
| 未发现 Boss | `BOSS · ID #005`，不显示真名 |
| 已发现 | `小史莱姆 · ID #007` |
| 同名已发现 | `水蛇 · ID #016` |

标签默认常亮：

- 未发现时 ID 常亮；
- 已发现后名字与 ID 常亮；
- 距离较远时可降低不透明度，但不能完全消失；
- 遮挡时使用边缘指示，不让文字全部堆叠；
- 不在地图上显示 `species` 英文代号。

### 10.2 击杀反馈强度

| 角色 | 停顿 | VFX | 文本 | 世界输出 |
|---|---:|---|---|---|
| 普通怪 | 60–100 ms | 6–10 个数据碎片 | ID → 名字、+1 XP | 可无 |
| 小型精英 | 100–140 ms | 轮廓破裂、图鉴印章 | ID → 名字、+3 XP | 可选奖励 |
| 区域 Boss | 120–180 ms | 场景级变化 | ID → 名字、+5 XP | 必须 |
| 楼层 Boss | 150–220 ms | Boss 规则和地标变化 | ID → 名字、+5 XP、证据 | 必须 |

Reduced Motion：

- 不执行镜头大位移和粒子飞散；
- 使用轮廓闪白、分阶段文字和颜色变化；
- 事件顺序、名字、XP、奖励和世界结果必须完整。

### 10.3 无掉落反馈

无随机掉落时：

```text
+1 XP
名字已收入图鉴
本次没有发现可用物品
```

不打开空的全屏战利品面板。

| 5 | 黑铁外城、兵营、王厅 | 窗口函数 | 排名与 Frame | 堡主改变城墙时序 | 排名靠后即可删除 |
| 6 | 龙脊工坊、晶洞、巢穴 | 写入与约束 | 保存点与回滚 | 古龙开放安全沙箱 | 成功写入即可提交 |
| 7 | 水晶林、根系、索引树心 | 索引与计划 | 覆盖/失效组合 | 林王改变路线代价 | 最快计划永远正确 |
| 8 | 黑曜长厅、虚空王庭、王座 | 系统事故证据 | 多系统诊断 | 王兽开放最终证据链 | 旧身份必须覆盖新集合 |

跨层规则：

- 每层至少一个新轮廓家族；
- 前层怪物只作为少量生态回声，不整层复用；
- 区域 Boss 不得连续两层都是“大号普通怪”；
- 楼层 Boss 的错误规则必须对应本层 SQL 认知；
- 第八层最终答案是 `MIGRATE`，不是恢复某个唯一旧名。

## 12. 管理员模式与 QA

管理员模式必须支持：

| 功能 | F1 | F2 |
|---|---|---|
| 身份状态 | 全部未知 / 单个已发现 / 全部已发现 | 同左 |
| 直达怪物 | 001–009 | 010–022 |
| Boss 阶段 | 登记官入场 / 阶段1 / 阶段2 / 结算 | 湖兽、蛙王、灯塔各阶段 |
| 世界状态 | 水位、床牌、回执、登记规则 | 浮标、根桥、潮位、船闸、灯塔 |
| 视觉检查 | 所有史莱姆轮廓与碰撞 | 猎犬、水蛇、蛙、树妖、Boss |
| 结算检查 | 名字、XP、无掉落、确定奖励 | 同左 |

管理员预览：

- 不写正式存档；
- 不增加永久图鉴；
- 可以模拟 Profile 视图；
- 刷新后回到正式进度；
- 不暴露全局 JavaScript 修改函数。

## 14. 验收与测试

### 14.1 内容完整性

- F1 ID 001–009 唯一且连续；
- F2 ID 010–022 唯一且连续；
- 每只怪物具有 species、archetype、rank、lesson、stages、codex 和 visual key；
- 主线怪和 Boss 的生成不受随机概率影响；
- `true_name` 与产品稿一致；
- ID #014 的任何玩家文本都不再出现“丛林王”；
- ID #021 使用“湖兽”，不混用“湖怪”。

### 14.2 身份与图鉴

- 未发现世界标签只有 ID；
- 未发现 SQL 反馈不含真名；
- 最终成功前图鉴仍锁定；
- identity-recovered 后世界、图鉴和 Profile 同时更新；
- 重复提交、读档和页面恢复不会重复解锁；
- 同名 ID #011/#016、#010/#019 等保持两条独立记录；
- 新 Run 已发现名字可直接显示，但课程仍需重打。

### 14.3 战斗与奖励

- 普通、精英、区域 Boss、楼层 Boss XP 分别为 1、3、5、5；
- 高伤武器不能跳阶段；
- 撤退与死亡不授予名字、XP 或奖励；
- 普通怪随机恢复品概率为 2%，且允许完全无掉落；
- 随机池没有武器和防具；
- 背包满不会丢失确定奖励；
- 登记官、湖兽、蛙王、灯塔守卫的世界状态只提交一次。

### 14.4 视觉与碰撞

- 无 HUD 截图能区分 F1 五种主要轮廓；
- 无 HUD 截图能区分 F2 猎犬、水蛇、青蛙、树妖、湖兽和灯塔守卫；
- 青蛙不显示成墙；
- 标签不与碰撞体、角色身体和环境提示重叠；
- 安全区不生成或巡入怪物；
- 30 FPS 下动画稳定；
- Reduced Motion 保留所有信息。

### 14.5 Boss

- 登记官修正规则而非普通死亡；
- 湖兽胜利改变潮位、村落和船闸；
- 蛙王完全可选且奖励确定；
- 灯塔守卫使用地区证据和主透镜两种阶段；
- 四个 Boss 均可撤退、死亡复盘和重试；
- 读档后 Boss、世界、身份和奖励一致。

### 14.6 图鉴 UI

- 320 px 可查看条目；
- 键盘、触屏和 ESC 可用；
- 焦点不会落到隐藏面板；
- 资源失败有剪影 fallback；
- 发现计数按 ID，不按名字去重；
- 图鉴不会展示未学完整答案。

### 14.7 停止条件

出现任一情况，停止继续制作第三层素材：

- F1/F2 仍有怪物以墙、纯色块或错误 species 显示；
- 名字在最终结算前泄露；
- Boss 没有对应的世界变化；
- 关键奖励依赖随机；
- 无掉落仍占满玩家视线；
- 同名怪物在图鉴中被错误合并；
- 死亡或读档造成重复 XP、装备、名字或钥匙；
- 正式模型和玩家文本使用不同身份。
