# 旧设计继承、改造与废弃矩阵

> 文档版本：`1.0`
>
> 目的：确保新两层垂直切片建立在旧设计资产上，而不是重新发明或继续继承已经被试玩否决的内容。

## 1. 决策规则

| 决策 | 定义 | 实施含义 |
|---|---|---|
| `KEEP` | 规则已经验证且与新方向一致 | 保留行为，只调整表现或文案 |
| `EVOLVE` | 核心意图正确，但当前实现不足 | 保留玩家价值，重做数据、地图或演出 |
| `REPLACE` | 与新方向冲突或造成明确疲劳 | 新实现完全取代旧行为 |
| `DEFER` | 有价值但不属于前两层切片 | 不进入本轮代码和验收 |
| `RETIRE` | 误导性或重复真源 | 仅作历史记录，不再引用为目标 |

## 2. 产品级迁移

| 旧设计 / 当前行为 | 决策 | 新两层落点 | 原因 |
|---|---|---|---|
| 真 SQLite WASM 执行 SQL | `KEEP` | 课程与战斗规格 | 产品可信度核心 |
| SQL 一次提交等于一回合 | `KEEP` | 战斗状态机 | 规则清楚、适合学习 |
| 空输入不受惩罚 | `KEEP` | 错误与反击规则 | 不惩罚思考和误触 |
| 错误查询触发已预告反击 | `KEEP` | 战斗 UI 与复盘 | 失败有后果但可解释 |
| 提示从短到长四级展开 | `KEEP + HARDEN` | 每道题强制四级 | 早期版本曾出现先长后短 |
| 击败前只显示 ID | `KEEP + HARDEN` | 最后一击原子揭示 | 当前 SQL 题仍可能提前查询 `name` |
| 所有怪物常亮现实名字 | `REPLACE` | ID 常亮、真名击败后常亮 | 破坏“恢复身份”叙事 |
| 纯答题框与世界割裂 | `REPLACE` | SQL 结果直接改变水位、桥、潮位和灯塔 | 查询必须是世界行为 |
| 八层一次性做完 | `REPLACE` | 先完成两层垂直切片 | 防止八层换色、重复和低质量 |

## 3. 地图与探索迁移

| 旧设计 / 当前行为 | 决策 | 新方案 |
|---|---|---|
| `64×48` 或 `48×36` 算法迷宫 | `EVOLVE` | 仍使用稳定 Seed 与网格碰撞，但宏观拓扑由关卡圣经固定 |
| 三块颜色代表生态区 | `REPLACE` | 每区至少有轮廓、材质、地标、交通、动态状态五重差异 |
| 大量窄路和死角 | `REPLACE` | 2–5 格宽主路、广场、岸线、栈桥、房间组和明确回环 |
| 每层三个通用篝火 | `EVOLVE` | F1 出生余烬锚点 + 余烬仓窖火 + Boss 前火；F2 港口航灯锚点 + 避风岛火 + 灯塔火；出生锚点不可休息，只有中后两处为实体篝火 |
| 抄写员复制到每个篝火 | `REPLACE` | 抄写员是唯一角色，随剧情移动或以远处可见轮廓出现 |
| 一把钥匙开启随机捷径 | `EVOLVE` | 捷径由具体世界行为开启：F1 旧仓库背面铁门，F2 船闸直航 |
| 捷径只把深处送回无用区域 | `REPLACE` | F1 回访登记厅触发新手村强敌伏笔；F2 缩短湖兽 / 灯塔间航线并开放村落回访 |
| region portal 仅文字传送 | `EVOLVE` | F2 实体码头、上船、短航行动画、换层音乐连续过渡 |
| 纯随机主线 | `REPLACE` | 固定拓扑 + Seed 控制非关键装饰、巡逻和低概率事件 |
| 隐藏洞穴、海洋副本、服装奖励 | `DEFER` | 基础两层验证后作为内容季扩展 |

## 4. 战斗、成长与掉落迁移

| 旧设计 / 当前行为 | 决策 | 新方案 |
|---|---|---|
| 初始 2 HP | `KEEP` | 第一层保持 2 HP，通过等级 / 防具成长 |
| 普通怪 +1、精英 +3、层主 +5 XP | `KEEP` | 数值规格固定，并显示结算前后 |
| 经验阈值 `2/4/6/8...` | `KEEP` | 明示下一等级阈值 |
| 普通怪必掉或高概率掉装备 | `REPLACE` | 普通怪 98% 无随机掉落；命中时优先即时恢复品 |
| 每个候选掉落独立判定、不重复 | `KEEP` | 仅适用于允许随机掉落的池 |
| 普通怪越阶武器 0.25% | `DEFER` | 两层平衡稳定后再评估，不进入当前验收 |
| 必修武器和钥匙随机掉落 | `REPLACE` | 关键奖励 100% 确定获得 |
| 武器提高伤害到跳过题目 | `REPLACE` | 关键战至少保留规定正确查询阶段 |
| 背包 12 格、恢复品 3 格 | `KEEP` | 满包有明确替换 / 丢弃，不生成死锁弹窗 |
| 战斗撤退 | `KEEP + HARDEN` | 明确按钮，返回最近复活点，放弃本场未结算进度 |
| 死亡重置游戏 | `REPLACE` | 回最近休息篝火，保留永久和已结算状态，进入本场复盘 |

## 5. 课程迁移

| 旧行为 | 决策 | 新方案 |
|---|---|---|
| F1 `SELECT → WHERE → IS NULL → GROUP BY → HAVING` | `KEEP` | 与第一层环境机关逐一绑定 |
| F2 `ORDER/LIMIT → DISTINCT → INNER → LEFT → 综合 JOIN` | `KEEP` | 与航线、倒影、根桥、孤立记录、灯塔绑定 |
| 任务写“查询 name 与 sector” | `REPLACE` | 明确 `m.name` 属于 `monsters`、`r.sector` 属于 `rooms` |
| INNER JOIN 不要求别名 | `REPLACE` | 目标、字段速查、补全和提示明确 `AS m / AS r` |
| 第一击查询 `name` | `REPLACE` | 前阶段查询 `id/weakness/status/sector`，最终阶段才查询 `name` |
| F1 WHERE 用未知真名过滤 | `REPLACE` | 用 ID、房间与状态定位 |
| 错误只显示 SQLite 原文 | `EVOLVE` | 保留原文，同时解释字段归属、语法或结果不匹配 |
| 一次背完整答案 | `REPLACE` | 短概念 → 结构 → 完整字段与值 → 完整答案 |

## 6. 叙事与角色迁移

| 旧设计 | 决策 | 新方案 |
|---|---|---|
| 玩家是多次删除、覆盖、回滚的历史集合 | `KEEP` | 八层核心真相，不在前两层全部说破 |
| 抄写员是唯一温暖 | `KEEP` | 温柔、克制、只总结已发生事实 |
| 抄写员等于篝火菜单 | `REPLACE` | 她有移动、观察、保存纸页和迟疑；篝火只负责系统功能 |
| 篝火会“记住玩家” | `KEEP` | F1 开场用权限有效但居民表 0 行证明 |
| 剧情只在侧栏卡片出现 | `REPLACE` | 环境、动作、地图状态、SQL 结果与可追溯日志共同叙事 |
| 泥王为第一层终点 | `REPLACE` | 同一课程槽位重构为“登记官” |
| 丛林王为第二层终点 | `REPLACE` | 同一课程槽位重构为“灯塔守卫” |
| 湖兽、蛙王等生态首领 | `EVOLVE` | 湖兽成为改变潮位的区域 Boss；蛙王为可选高阶战 |
| 第一层立即解释完整身世 | `REPLACE` | 只回答“记录不存在但恢复权限有效” |
| 第二层把多个名字去重为一个 | `REPLACE` | 证明不同来源不能因轨迹相同被覆盖 |

## 7. 视觉与音频迁移

| 旧行为 | 决策 | 新方案 |
|---|---|---|
| Phaser Graphics 大色块与小符号 | `EVOLVE` | 保留轻量碰撞和降级渲染，正式层使用 CC0 Tile / Sprite 与手工组合地标 |
| 只换地板颜色区分楼层 | `REPLACE` | F1 室内档案、水轮、宿舍；F2 岸线、船、村落、灯塔 |
| 所有怪物共用方块配方 | `EVOLVE` | 同网格和调色规范下提供物种轮廓、动作和死亡差异 |
| 高频振荡器持续蜂鸣 | `REPLACE` | 录音 / 导出音乐 BGM + 程序化轻量 SFX，移除持续蜂鸣底床 |
| 音乐短段落熄火后重启 | `REPLACE` | 无缝循环、场景间相位 / 淡入淡出连续调度 |
| 直接使用现代商业录音 | `RETIRE` | 作品和录音版权分别可验证，未确认来源禁止接入 |
| 模仿商业游戏旋律 | `RETIRE` | 只继承情绪和结构，不复制旋律、音色或录音 |

## 8. 工程与文档迁移

| 旧行为 | 决策 | 新方案 |
|---|---|---|
| `DungeonScene.ts` 持续堆叠分支 | `REPLACE` | 拆分楼层体验、世界状态、素材加载、环境渲染与 Setpiece 工厂 |
| `GameSession.ts` 直接承担所有内容 | `EVOLVE` | 保留权威状态机，新增纯派生楼层世界状态 |
| `floorContracts.ts` 被当内容真源 | `RETIRE` | 新 `floorExperience` 为 F1/F2 真源；旧文件只做兼容摘要 |
| 旧文档宣称八层“已完整实现” | `RETIRE` | 实际代码 / 测试与本产品目录共同决定状态 |
| 原始素材直接进 `public` | `REPLACE` | `assets/vendor/<source>/raw` 与 `public/assets/floors/<floor>/derived` 分离 |
| 许可证只写一句 CC0 | `REPLACE` | 每源 `source.json`、许可证副本、SHA256、选用文件和派生关系 |
| 只跑单元测试就视为完成 | `REPLACE` | 增加两层完整通关、视觉、音频、触屏、读档和管理员预设验收 |

## 9. 本轮明确不继承

- 以地图面积、死路或重复赶路增加时长；
- 把颜色和随机地面符号当成地区设计；
- 每座篝火复制一个抄写员；
- 击杀前常亮现实怪物名；
- 必定掉落、满屏掉落弹窗或关键道具随机化；
- 直接下载或转存流媒体平台中的现代演奏录音；
- 用“像某商业游戏”代替可执行的原创设计；
- 以八层数量掩盖第一、二层内容不足。

## 10. 迁移验收

迁移完成时，制作人应能逐项回答：

1. 每个保留机制是否仍有测试？
2. 每个改造机制是否保留原玩家价值而移除已知痛点？
3. 每个废弃机制是否已经从运行时、文案、测试和管理员入口同时移除？
4. 旧存档是否有降级或迁移路径？
5. 新文档是否成为代码使用的数据契约，而不是只存在于 Markdown？
6. 第一、二层是否在轮廓、移动、节奏、故事问题和音乐上都能盲测区分？
