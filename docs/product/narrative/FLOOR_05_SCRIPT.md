# 第五层逐事件叙事脚本：黑铁轮值城

> 脚本版本：`v1.1` · 状态：`RUNTIME V1.1 VERIFIED`
>
> 目标时长：首次 `30–45` 分钟
>
> 课程：`OVER / ROW_NUMBER / RANK / LAG-LEAD / Window Frame / 分组 Top-N`

## 0. 本层职责

第五层把第四层“同一条全城命令”推进到“谁决定命令先影响谁”。本层不把窗口函数包装成魔法：
窗口只保留明细、建立顺序、读取前后行和定义计算范围；造成伤害的是王城如何使用这些结果。

本层问题：

> 事实没有改变时，排序和公开顺序能否改变一个人的命运？

本层结论：

> 能。窗口不会删除行，但分区、排名、前后位置和范围会决定谁先被看见、谁先被处理。

离层问题：

> 取得改变记录的权力后，怎样证明改变不会越过目标边界？

## 1. 地图与空间叙事

| 区域 | 空间 | SQL | 持续变化 |
|---|---|---|---|
| 黑铁外城 | 宽吊桥、轮值表、铆钉城墙 | `OVER / PARTITION BY`、`ROW_NUMBER` | 名册从折叠总计变成分区明细和稳定岗次 |
| 轮值兵营 | 双旗、前后岗灯、无编号铁门 | `RANK / DENSE_RANK`、`LAG / LEAD` | 并列旗同时升起，岗灯显出巡逻空档 |
| 内城军钟 | 累计警戒墙、密文侧门、军钟 | Window Frame、分组 Top-N | 警戒范围明确，军钟停止宣告唯一第一名 |

主路线为宽双环，不做连续细廊。静默名册室是环间暗室；黑铁吊桥在层结算后落下并自动上行。

## 3. 抄写员关键对白

入层：

> “外城没有删除任何一行。”
> “它只是决定谁先被看见、谁先被带走。”

静默名册室：

> “我在第四层认出了档案官的签名。”
> “我没有立刻告诉你，因为公开顺序也会伤人。”

Boss 后：

> “事实没有改变。”
> “改变的是王城再也不能用一个名次覆盖其余历史。”

## 4. SQL 密文：轮值密文门

- 位置：内城军钟侧墙，使用 Boss 课程门的实体格。
- 终端：只读 `SELECT / WITH`。
- 目标：在分区内建立稳定排名，再返回指定分区的 Top-N。
- 正确：侧门永久打开，密文核心由青色变为金色。
- 错误：护甲优先承受 `1` 点反噬。
- 明确不奖励：课程掌握、XP、武器、名字。

密文的叙事作用不是“提前跳课”，而是证明玩家能在王城使用排名，却不把排名误作身份。

现场证据：

- `f5-stable-duty-order`：四条守卫记录按区域稳定编号，证明窗口没有吞掉明细。
- `f5-ties-preserved`：同时显示 `RANK` 与 `DENSE_RANK`，证明并列不是缺失。
- 两条结果都以 ID 展示；怪物名字仍由击杀结算恢复。

## 5. 隐藏区与换装

`静默名册室` 前置为 `f5-over / f5-row-number / f5-rank`。室内保存未公开的居民轮值表，并确定
获得 `iron-armor`。

- 黑铁甲是低饱和重甲轮廓，不能与基础角色只换一个色块。
- 获取时解释：提供护甲生命，先承受反击；篝火与复活恢复护甲。
- 隐藏门、奖励、发现剧情各只结算一次。
- 未进入隐藏区不影响军钟 Boss 和升层。
