本文不定义最终像素坐标和代码字段名，但每个事件都必须映射到：

对白、字幕、无障碍名称或战斗面板。

## 1. 本层叙事目标

本层问题：

> 当前居民表中没有玩家，为什么篝火仍能恢复玩家？

本层结论：

> 玩家不属于当前居民表，但属于一段仍然有效的恢复历史。

离层悬念：

> 那段历史中究竟有几个名字？

必须由玩法证明的三件事：

1. 当前登记读数是 `0 ROWS`，恢复权限却是 `VALID`；
2. 水位、床牌、回执和登记规则都因 SQL 结果改变；
3. 抄写员亲手为没有当前记录的玩家保留第一页。

## 2. 演出硬规则

### 2.1 身份

- `ID #001–#005` 在各自胜利结算前只显示 ID。
- NPC 不得提前说出“史莱姆”“水史莱姆”“毒史莱姆”“铁史莱姆”或“登记官”。
- 查询姓名字段只允许出现在最后一击阶段。
- 第一次出现真名的唯一顺序是：最终结果行→HP 归零→数据碎片→`NAME RECOVERED`→图鉴盖章。
- 已在永久图鉴发现的名字可在新 Run 显示，但脚本仍不得因此跳过首层身份教学。

### 2.2 镜头

- 普通镜头移动不超过 `1.2s`；地点建立镜头不超过 `2.0s`。
- 玩家输入恢复前，镜头必须回到角色或清楚标出下一目标。
- 所有镜头可跳过；Reduced Motion 使用淡入、目标框和字幕替代平移、震动与粒子。
- SQL 编辑器打开时不播放会遮挡字段或结果的对白。

### 2.3 事件提交

- 环境变化演出完成后才提交对应状态，避免半开门和半降水位。
- 战斗胜利结算完成后才提交真名、XP 和确定奖励。
- 关键演出被中断时，从最近安全事件检查点重播精简版。
- 已提交事件不得因后续死亡或撤退重复发奖。

### 2.4 对话呈现

- 首次对话使用本文完整文本。
- 重复交互只保留当前事实和下一目标。
- 抄写员不代写 SQL，不使用玩家尚未学到的技术术语解释答案。
- 系统读数与人物对白分层显示，不让玩家误把世界隐喻当成真实 SQLite 表结构。

## 5. 逐事件脚本

## `F1-S00`｜进入或读档时恢复场景

**类型**：系统事件，玩家不可见。

**触发条件**：加载第一层、死亡返回、撤退返回或读取第一层存档。

**前置检查**：

1. 已完成课程；
2. 已发现怪物 ID；
3. 正式捷径状态；
4. 当前和已休息篝火；
5. Boss 是否完成；
6. 确定奖励是否领取。

**镜头 / 角色动作**：

- 首次进入转交 `F1-E01`；
- 普通读档直接聚焦玩家，不重播地点长镜头；
- 抄写员按故事阶段出现在唯一位置：`desk → gate → archive/elevator`；
- 已完成的水位、床牌、回执和门直接恢复最终状态。

**对白**：无。

**SQL 证据**：不执行新查询，不改变课程状态。

**重复 / 错过 / 死亡**：该事件可无限重复，但不得发奖、解锁名字或追加重复日志。

**图鉴 / 日志**：只恢复，不新增。

## `F1-E01`｜火记得你

**类型**：必看开场。

**触发条件**：新 Run 首次进入第一层，且 `f1.arrived = false`。

**镜头 / 角色动作**：

1. 黑场中先出现柔和火声和字幕“恢复路径正在读取”。
2. 画面淡入出生余烬锚点；玩家轮廓由四块低亮像素逐步完整。锚点只有低火光和兜底复活功能，
   不提供 `E` 休息菜单，也不计作第三座篝火。
3. 镜头向右移动半屏，框出登记台的两盏矛盾状态灯。
4. 抄写员仍坐在桌前书写，不立即看向玩家。

**玩家可见读数**：

```text
CURRENT RECORD：0 ROWS
RESTORE PERMISSION：VALID
```

该读数来自真实 SQLite 只读世界表 `residents` 的审核查询。开场不要求玩家输入，但允许展开
查看 SQL 与真实 0 行结果；普通怪战不展示该故事表，避免首战 Schema 过载。

**对白**：无。让玩家先看见矛盾。

**环境变化**：出生余烬锚点稳定，登记台的空记录灯与权限灯同时保持点亮。

**SQL 证据**：当前无玩家输入；建立第一条叙事证据“0 行 / 有效权限”。

**可重复 / 错过 / 死亡后行为**：

- 不可错过。
- 重新进入只显示一行日志：“当前记录仍为 0；恢复权限仍有效。”
- 开场期间退出，重进从完整开场开始。
- 死亡返回不重播。

**图鉴 / 日志反馈**：

- 任务日志新增：`异常登记：0 ROWS / VALID`。
- 《失名录》显示新页占位：`???`，尚无可确认结论。

- 当前目标：`调查停止的水轮，确认第一条怪物记录。`
- 人物页新增：`抄写员——为没有当前记录的对象保留空白页。`

## `F1-E03`｜第一只名字

**类型**：必修教学战 + 环境事件。

**触发条件**：进入水轮大厅并触碰玩家可见标签 `ID #001`。

**身份约束**：内部制作真名为“史莱姆”，胜利前禁止显示或播报。

**镜头 / 角色动作**：

1. `ID #001` 堵在水轮齿间，身体内可见一小块水轮碎片。
2. 遭遇镜头只显示 `ID #001 / HP / 下一动作：挤压`。
3. 终端展开后背景暂停，水轮仍以极慢卡顿帧提示关联对象。

**SQL 阶段**：

阶段 A，先查弱点，不泄露姓名：

```sql
SELECT weakness
FROM monsters
WHERE id = 1;
```

反馈：怪物核心和卡住的齿轮同时高亮。

阶段 B，最后一击才查询姓名：

```sql
SELECT name
FROM monsters
WHERE id = 1;
```

反馈：结果行先标记 `PENDING IDENTITY`，随后进入胜利结算。

**名字恢复演出**：

```text
ID #001
NAME RECOVERED
史莱姆
```

- 怪物轮廓碎成两行数据；
- 姓名行落入图鉴；
- XP `+1` 飞向状态栏；
- 水轮碎片归位，水轮连续转动；
- 栈桥放下。

**对白**：远处抄写员不出现在现场，只通过管道传来一句：

> “记录能叫出它。再看看，记录能不能解释你。”

**环境变化**：提交 `f1.water_turning`，开放宿舍与旧仓库方向。

**可重复 / 错过 / 死亡后行为**：

- 不可错过；水轮是主线路径。
- 阶段 A 后死亡：姓名不解锁；怪物保留剩余 HP，但未提交阶段与演出回到入战快照。
- 阶段 A 后撤退：姓名不解锁；怪物 HP 与未提交阶段都回到入战快照。
- 胜利后死亡：姓名、水轮、栈桥、XP 和课程奖励保持。
- 重访只播放水轮工作声；调查提示“水轮已按 ID #001 的记录复位。”

**图鉴 / 日志反馈**：

- 怪物图鉴：`史莱姆 · ID #001`，栖息地“水轮大厅”，线索“身体里卡着停机时留下的齿片”。
- 任务日志：`SELECT 已验证：查询可以读取世界并恢复名字。`
- 确定奖励按课程契约发放“过滤弓”，展示效果说明。

## `F1-E04`｜只打开正确的水闸

**类型**：必修战斗 + 地图状态改变。

**触发条件**：`F1-E03` 完成，进入青石排水渠并触碰 `ID #002`。

**身份约束**：内部制作真名为“水史莱姆”，胜利前只显示 ID。

**镜头 / 角色动作**：

- 镜头先框出唯一主水阀，再框出在多条控制记录间移动的 `ID #002`。
- 错误目标会使错误阀门闪红，但不会永久改变水位。

**SQL 阶段**：

```sql
SELECT id
FROM monsters
WHERE room_id = 2
  AND status = 'escaped';
```

```sql
SELECT weakness
FROM monsters
WHERE id = 2
  AND status = 'escaped';
```

**世界反馈**：

- 第一条查询只高亮正确水闸目标；
- 第二条查询命中后阀柄转动，水位下降一级；
- 敌人归零后从已击败记录恢复名字，不在此前对白中出现。

**名字恢复**：`ID #002 → 水史莱姆`。

**对白**：无强制对白。水位下降后管道传声：

> 抄写员：“筛掉了错误目标。留下来的路才是真的路。”

**可重复 / 错过 / 死亡后行为**：

- 不可错过。
- 查询失败只造成该场反击，不改变任何水阀。
- 战斗失败恢复高水位的战前画面。
- 胜利结算后提交低水位；后续死亡不恢复高水位。

**图鉴 / 日志反馈**：

- 图鉴：`水史莱姆 · ID #002`，线索“它只在被错误分配的排水记录间移动”。
- 日志：`WHERE / AND 已验证：目标过滤使唯一水阀生效。`

## `F1-E05`｜空白不是没看见

**类型**：必修战斗 + 身份主题事件。

**触发条件**：低水位后进入无名宿舍，靠近 `ID #003`。

**身份约束**：内部制作真名为“毒史莱姆”，阶段二胜利前只显示 ID。

**镜头 / 角色动作**：

- 高处床牌先显示 `???`。
- 怪物背着一块没有主人的床牌，地图标签仍为 `ID #003`。

**SQL 阶段**：

```sql
SELECT id
FROM monsters
WHERE room_id = 3
  AND master_id IS NULL;
```

反馈：相关床牌从 `???` 变成“已查询”轮廓，但尚不显示最终值。

最后一击：

```sql
SELECT name
FROM monsters
WHERE master_id IS NULL
  AND status = 'cursed';
```

**世界反馈**：

- 床牌明确显示 `current_owner = NULL`；
- 怪物最后一击恢复名字 `ID #003 → 毒史莱姆`；
- 墙面湿痕显出一排曾经存在过的姓名高度线，但不出现具体名字。

**对白**：抄写员通过管道：

> “空白不是没看见。”
> “你已经查过了——这里确实没有值。”

**错误专用反馈**：

- 使用 `= NULL`：“比较结果没有成为 TRUE。请判断字段是否为 NULL。”
- 只写 `IS NULL`：“需要先指出要检查的字段。”
- 漏掉状态：“结果不只指向当前目标，请继续过滤。”

**可重复 / 错过 / 死亡后行为**：

- 不可错过。
- 第一阶段完成后战斗失败：床牌回到待确认视觉，`NULL` 不提前提交。
- 完整胜利后永久保持 `NULL`，名字和课程不回滚。
- 重访调查：“床位已确认无人登记；不是尚未调查。”

**图鉴 / 日志反馈**：

- 图鉴：`毒史莱姆 · ID #003`，线索“它背着一块已经确认没有主人的床牌。”
- 《失名录》更新概念说明：`??? ≠ NULL`。
- 日志：`已确认无名宿舍存在真实缺失值。`
- 确定奖励“空值提灯”进入背包并展示具体效果。

## `F1-E06`｜余烬仓窖休息

**类型**：必经篝火教学。

**触发条件**：首次进入余烬仓窖安全圈并调查实体篝火。

**镜头 / 角色动作**：

- 不移动抄写员到篝火旁。
- 篝火居中占据一个清楚的可交互实体位置，周围安全圈以地面边界表达。
- 菜单以桌上纸页样式出现，署名来自抄写员此前整理的记录。

**菜单**：

1. `在此休息`：回满生命并设为复活点；
2. `答案复盘`：显示 SELECT、WHERE、IS NULL 的实际输入和错误；
3. `整理装备`：进入背包；
4. `离开`。

**篝火页文本**：

> 已确认：当前记录缺失，恢复权限有效。
> 待回答：是谁留下了这条恢复权限？

## `F1-E12`｜修正登记规则

**类型**：两阶段楼层 Boss 战。

```sql
SELECT channel, COUNT(*) AS total

HAVING COUNT(*) >= 2;
```

演出：

- 每个满足阈值的回执组形成一条保护线；

- 权限灯停止向 `REVOKE` 移动。

**阶段二：确认最强恢复轨迹**

任务：

```sql
SELECT channel, COUNT(*) AS total
FROM monster_signals
WHERE monster_id = 5
GROUP BY channel
HAVING COUNT(*) >= 3;
```

演出：

- `echo` 组高亮；
- 注销动作返回 `CONDITION NOT MET`；
- Boss HP 归零，但不爆炸死亡；它停止盖印并低下主体。

**错误反击**：

- 名称：`注销印`，不得使用 Boss 真名；

- 错误反馈先说明结果或语法问题，再播放反击；
- 玩家可以随时选择“撤退到复活点”。

**镜头 / 音频**：

- 音乐阶段增加低声铜质节奏，不用尖锐噪声。

**图鉴 / 日志反馈**：胜利前仍不写真名。

## 11. QA 验收用例

### 11.1 主线

- 从新档到升降机完整通过，不需要隐藏支线或随机掉落。
- 10 分钟内首次完成名字恢复。
- 玩家看见至少一次 SQL 改变水位、一次 SQL 归组纸页。
- 开捷径后自然回到登记厅，并触发人物、轮廓和 Boss 三项变化。
- Boss 后无需手动操作额外 Run 按钮即可进入第二层。
- 不进入封存旧库也能完成主线；完成 `WHERE + IS NULL` 后可从实体纸缝门进入，读档后仍保持开放。

### 11.2 身份泄露扫描

- 在 `ID #001–#005` 胜利前截图地图、遭遇卡、任务、提示、字幕、ARIA 名称和日志。
- 搜索各真名，预期结果为零。
- 验证 `ID #001` 姓名查询只发生在最后一击。
- 验证战斗失败和撤退不会写入 `discoveredMonsterIds`。

### 11.3 存档与死亡

- 在水轮、水位、NULL 床牌、捷径、回访、聚合、Boss 各状态保存并重载。
- 中断所有关键演出，确认只恢复合法前态或后态。
- 在中段篝火休息后死亡，回中段篝火；在后段休息后死亡，回后段篝火。
- 胜利后死亡不丢名字、XP、钥匙、第一页和确定装备。

### 11.4 可访问性

- 静音完成全层，仍能理解水轮、水位、铜印和名字恢复。
- Reduced Motion 下不依赖镜头摇动、停帧或粒子表达状态。
- 键盘、触屏和 320px 宽度均能完成对话、篝火、战斗、图鉴与离层。
- 对话和演出可跳过，跳过后目标与日志仍完整。
