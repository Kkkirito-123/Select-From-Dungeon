## 1. 本层叙事目标

本层问题：

> 多个旧名字共享同一条恢复轨迹，它们是重复记录，还是不同的人？

本层结论：

> 它们来自不同地点和记录渠道，不能因为恢复轨迹相同就覆盖成一个名字。

离层悬念：

> 这些不同记录之间是什么关系，又曾经属于谁？

必须由玩法证明：

1. 排序只能确定信号优先级，不能确定哪一个身份更真实；
2. `DISTINCT` 能识别不同值，不能决定哪些生命应被删除；
3. `JOIN` 把旧名字分别连回不同地点与生活痕迹；
4. 退潮后七盏浮标和七个倒影同时存在；
5. 最终灯塔同时照亮七个来源，而不是只保留多数。

## 2. 演出硬规则

### 2.1 身份

- `ID #010–#014`、`ID #021–#022` 在各自胜利结算前只显示 ID。
- NPC、任务标题、场景标签和无障碍名称不得提前使用“猎犬、水蛇、树妖、毒蛙、湖兽、蛙王、灯塔守卫”。
- 姓名字段查询必须位于最后一击阶段；旧 INNER JOIN 题第一阶段的姓名字段改为 `m.id`。
- 湖中巨大影子可称“深水影子”或 `ID #021`，不得提前称湖兽。
- 灯塔 Boss 可称“塔内实体”或 `ID #014`，不得提前称灯塔守卫。
- 七个旧名字是主线身份记录，不是怪物名字，也不得标记为玩家真名。

### 2.2 镜头与交通

- 入层地点镜头不超过 `2.5s`，普通状态变化不超过 `1.5s`。
- 短船程 `0.8–1.3s`，不重启整首音乐。
- 转场中关闭移动和随机遭遇；结束后立即显示地点名和下一目标。
- Reduced Motion 使用淡入、航向文字和岸线切换，不横向拖动画面。
- 所有船程有明确起点与目的地，不使用无意义传送门。

### 2.3 环境原子性

- 浮标点亮、树根成桥、潮位下降、船闸开启和七倒影出现都以完整演出为提交边界。
- 读档只能恢复事件前或事件后，不得出现半座桥、半退潮或一半倒影。
- 区域 Boss 胜利前死亡不改变潮位。
- 已完成潮位、船闸、名字、证据和确定奖励不会因后续死亡撤销。

## `F2-E01`｜潮声有顺序

**类型**：必看入层事件。

**触发条件**：第一层升降机抵达，`f2.arrived = false`。

**镜头 / 角色动作**：

1. 升降机门打开前先听见连续潮声，不先显示 HUD。

**对白**：

> 抄写员：“海面把同一段恢复轨迹送来了七次。”

**SQL 证据**：七纸共享恢复轨迹，但来源字段仍为 `???`。

**可重复 / 错过 / 死亡后行为**：

- 不可错过。

- 重访抄写员：“先按信号强度找出可用航线。排序不等于选出真名。”

## `F2-E02`｜第一条航线

**类型**：必修教学战 + 路线机关。

**触发条件**：进入白沙浅滩并触碰 `ID #010`。

**身份约束**：内部制作真名为“猎犬”，胜利前只显示 ID。

**镜头 / 角色动作**：

- 四足轮廓在不同浮标间巡回，模型不得显示成墙或方块。
- 地图标签显示 `ID #010 / HP / 意图：扑击`。
- 远处三盏浮标处于同一构图，便于理解查询结果对应对象。

**SQL 阶段一**：

```sql
SELECT channel
FROM monster_signals
WHERE monster_id = 10
ORDER BY charge DESC
LIMIT 1;
```

反馈：最强浮标先亮，敌人护甲裂开。

**SQL 阶段二**：

```sql
SELECT channel, charge
FROM monster_signals
WHERE monster_id = 10
ORDER BY charge DESC
LIMIT 2;
```

反馈：前两段航向依优先级出现，小船漂到码头。

**名字恢复**：敌人归零后 `ID #010 → 猎犬`，此前不查询姓名字段。

**环境变化**：提交 `f2.beacons_ranked`；第一渡点可用。

**对白**：码头方向传来抄写员一句：

> “最强信号适合先走，不代表它比其他记录更真实。”

**可重复 / 错过 / 死亡后行为**：

- 不可错过。
- 排序失败时浮标按错误顺序短闪，回合结束恢复熄灭。
- 战斗失败不点亮航线、不恢复名字。
- 胜利后死亡不熄灭浮标。

**图鉴 / 日志反馈**：

- 图鉴：`猎犬 · ID #010`，线索“它沿最强信号巡回，把优先级当作领地。”
- 日志：`ORDER BY / LIMIT 已验证：航线获得顺序，身份尚未获得结论。`
- 确定奖励“雷序军刀”进入背包并展示具体效果。

**可重复 / 错过 / 死亡后行为**：

**图鉴 / 日志反馈**：

## `F2-E06`｜树根知道两端

**类型**：必修精英战 + 关系机关。

**触发条件**：到达古树桥并触碰 `ID #012`。

**身份约束**：内部制作真名为“树妖”，胜利前只显示 ID。旧版第一阶段返回 `m.name`，本脚本改为
返回 `m.id`，避免提前泄露。

**镜头 / 角色动作**：

- 树干、冠层和根部是三个清楚层次。
- 多条根系分别伸向错误房间，正确连接前均不可通行。

**SQL 阶段一：先定位区域，不读姓名**

```sql
SELECT m.id, r.sector
FROM monsters AS m
INNER JOIN rooms AS r ON m.room_id = r.id
WHERE m.id = 12;
```

反馈：错误根系收回，只保留连接正确区域的一条。

**SQL 阶段二：最后一击确认姓名与房间**

```sql
SELECT m.name, r.name AS room_name
FROM monsters AS m
INNER JOIN rooms AS r ON m.room_id = r.id
WHERE m.id = 12;
```

反馈：结果行进入待提交状态；敌人归零后恢复 `ID #012 → 树妖`。

**世界反馈**：根系编成可通行桥，房间字段 `r.name` 与输出别名 `room_name` 同时高亮。

**错误演出**：连接条件错误时短暂出现笛卡尔错连，回合结束全部收回，不永久改变地图。

**对白**：

> 抄写员（记录页）：“一个名字和一个地点，必须说明它们怎样相连。”

**可重复 / 错过 / 死亡后行为**：

- 不可错过。
- 阶段一后死亡：名字不解锁，桥不提交。
- 完整胜利后桥永久存在，后续死亡不收回。
- 重访可调查桥根，显示 `monsters.room_id = rooms.id`。

## 7. 七来源日志交付

### 7.1 玩家可见格式

每项使用相同结构，不出现“正确答案”或“真名候选排名”：

```text
[短名]
来源：[地点 / 记录渠道]
共同字段：restore_trace
关系：???
状态：PRESERVED
```

### 7.2 顺序规则

- 玩家可自由发现六项环境来源。
- 灯塔来源固定最后获得，保证 Boss 前形成完整七页。
- UI 可按发现顺序或地点排序，但不得按出现频率给出“最可信”标记。
- `DISTINCT` 统计不得表现为删除七页，只能帮助识别不同值。

### 7.3 新 Run 与永久记录

- 永久《失名录》可以保留已经确认的七页来源。
- 新 Run 仍需完成本层 SQL 与世界状态，不能因图鉴存在自动开放船闸。
- 永久记录不显示第三层尚未确认的关系答案。

## 11. QA 验收用例

### 11.1 主线与差异性

- 进入第二层 60 秒内看见海面、灯塔、岸线和渡点。
- 至少一次 SQL 点亮航线，一次短船程，一次 SQL 形成树根桥。
- 湖兽胜利后全图潮位变化，村落和船闸同时开放。
- 船闸回访必须产生七灯、七倒影和抄写员移动。
- 灯塔 Boss 后自动进入北岸渡船，不需要寻找手动 Run 按钮。

### 11.2 SQL 清晰度

- INNER JOIN 两阶段都明确 `monsters AS m`、`rooms AS r` 和 `m.room_id = r.id`。
- 两个 `name` 同时出现时明确 `m.name`、`r.name AS room_name`。
- LEFT JOIN 明确主表主键 `monsters.id` 与明细外键 `monster_gear.monster_id`。
- 所有提示遵守意图→结构→字段→完整语句顺序。
- 错误关系演出不会永久改变地图或静默修正玩家 SQL。

### 11.3 身份泄露扫描

- 在相关胜利前扫描地图标签、任务、提示、对白、字幕、结果卡、ARIA 名称和日志。
- 玩家可见真名预期为零；深水与塔内目标只能显示 ID。
- `ID #012` 第一阶段不得返回或显示姓名。
- 战斗失败、撤退和关闭终端不写入永久名字。
- 七个旧名字不得被标记为怪物名或玩家真名。

### 11.4 存档与死亡

- 分别在浮标、频道、树桥、LEFT JOIN 门、湖兽、退潮、六来源、船闸、七倒影和灯塔 Boss 后存读档。
- 中断船程、退潮、船闸、七倒影和 Boss 结算，确认只恢复完整前态或后态。
- 湖兽失败不退潮；灯塔失败不丢七来源。
- 胜利后死亡不丢名字、XP、潮位、藤甲、钥匙或七页。

### 11.5 可访问性与性能

- 静音时通过浮标序号、航向文字、潮位刻度和七页状态理解全部剧情。
- Reduced Motion 下使用淡入、固定方向和文本替代船平移、水冲与强光。
- 键盘、触屏和 320px 宽度均可操作渡点、篝火、SQL、图鉴与撤退。
- 当前楼层素材延迟加载；船、倒影和水面对象离开视野后不持续高成本更新。
- 无 HUD 截图可以辨认码头、浅滩、沼泽、沉水村落和灯塔。
