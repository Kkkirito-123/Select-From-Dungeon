## 1. 本次目标

把八层从“依次学习 SQL 并打 Boss”精修为一条能够被玩家复述的完整史诗：玩家从一条查不到的记录
出发，逐层证明来源、关系、顺序、责任与访问路径，最终发现自己不是某一条旧记录，而是所有未被
抹去历史形成的集合，并以可验证、可回滚的 `MIGRATE` 结束王城停滞。

## 6. 叙事支柱与反目标

### 6.1 四个支柱

1. **先有证据，再有结论**：每个重大判断前，玩家必须亲手查询或改变世界。
2. **SQL 是世界动词**：语法不是口令；查询结果会排水、连桥、显墓、接炉、排班、回滚、选路或迁移。
3. **温暖来自诚实**：抄写员不替玩家作答。她会承认不知道、承认过去的判断造成了伤害，并始终在篝火旁等玩家回来。
4. **名字是胜利后的责任**：敌人存活时只显示 `ID #NNN`；最后一击后才回收真名，并永久写入图鉴。

### 6.2 反目标

- 不用大段旁白解释刚刚已经看见的机关；
- 不让 Boss 说出教程答案；
- 不把“数据库”词汇直接拼进怪物姓名；
- 不用假选择制造多结局；
- 不靠“更黑、更大、更吵”假装后期更史诗；
- 不让抄写员退化为篝火菜单、任务箭头或无所不知的系统播报。

## 7. 世界真相与角色弧

### 7.1 世界真相

王城曾进行一次跨时代迁移。档案王为了不让任何历史在迁移中丢失，把事务保持在永不结束的
`OPEN` 状态：旧版本没有被真正提交，新版本也没有获得接管权。数百年的恢复、覆盖、删除和回滚
残片相互叠加，形成了玩家这个“人形集合”。因此当前表查不到玩家，但历史证据不断证明玩家存在。

档案王的正确之处是拒绝粗暴删除历史；错误之处是把“可回滚”变成“永不决定”。最终冲突不是善恶，
而是是否愿意承担一次可审计迁移的责任。

### 7.2 玩家弧

| 阶段 | 自我理解 |
|---|---|
| F1 | “我是不是一条被删掉的记录？” |
| F2 | “为什么有七份彼此相似的我？” |
| F3 | “即使名字消失，关系仍能证明我曾属于这里。” |
| F4 | “这些残片来自同一条未结束的命令。” |
| F5 | “谁被先看见、先处理，会改变人的命运。” |
| F6 | “能够写入世界，就必须会验证和撤销。” |
| F7 | “容易找到的不等于更真实；找不到的不等于不存在。” |
| F8 | “我不是单行真名，而是有来源、有关系、可审计的历史集合。” |

### 7.3 抄写员弧

| 层 | 她最初相信 | 玩家证明 | 她的变化 |
|---:|---|---|---|
| 1 | 当前登记册就是全部现实 | 0 行不能证明不存在 | 从引路人变成见证人 |
| 2 | 相同值可以合并成一份 | 相同内容仍有不同来源 | 开始保护出处 |
| 3 | 关系规则足以恢复真相 | 连接规则也会排除孤立记录 | 成为共同审计者 |
| 4 | 找到源命令即可停止灾难 | 直接终止会抹掉依赖历史 | 认出档案王留下的签名 |
| 5 | 证据越早公开越正确 | 排序与公开时机会伤害人 | 承认自己延迟过一份证据 |
| 6 | 全部回滚最安全 | 候选历史也包含必须保留的修复 | 接受沙箱、局部撤销和验证 |
| 7 | 最快路径最可靠 | 索引会让真实记录变得不可达 | 承认参与建立过“看不见”的路径 |
| 8 | 她应该替玩家解释最后答案 | 最终责任不能外包 | 只验证证据，把决定交还玩家 |

抄写员的温柔来自三个行为：她记得玩家已经证明的事；她不把失败称作愚蠢；她不会编造自己没有
证据知道的答案。她与篝火的区别是“篝火恢复状态，抄写员恢复上下文”。

## 8. 八层宏观因果

| 幕 | 层 | 主问题 | 错误结论 / Boss 信条 | 玩家证明的答案 | 离层留下的问题 |
|---|---:|---|---|---|---|
| I 存在 | 1 | 查不到是否等于不存在？ | 当前表之外没有人 | 0 行只说明当前查询无结果 | 为什么有七份恢复来源？ |
| I 复数 | 2 | 相似记录能否合并？ | 相同值只保留一份 | 必须保留来源和缺失关系 | 名字没了，关系还能否作证？ |
| II 关系 | 3 | 无名、无主是否等于无历史？ | 孤立行无价值 | 关系、孤立项与多份证词共同还原历史 | 谁制造了这些断裂？ |
| II 依赖 | 4 | 一条命令能否直接终止？ | 终止源即可净化一切 | 三相灾难属于同一未结束依赖链 | 谁决定证据的处理顺序？ |
| II 顺序 | 5 | 排序只是展示吗？ | 第一名最该被保留 | 顺序与窗口决定谁先被处理 | 谁有资格修改世界？ |
| II 责任 | 6 | 回滚是否永远最安全？ | 不提交就不会犯错 | 写入必须预演、约束、局部撤销、验证 | 访问路径会不会掩盖真相？ |
| III 判断 | 7 | 找得快是否等于更真实？ | 最优路径定义事实 | 索引只改变访问代价，不改变事实 | 已知全部历史后该不该迁移？ |
| III 迁移 | 8 | 保存历史是否意味着永不决定？ | 永远 OPEN 才不会失去任何人 | 快照、审计、隔离、验证、切换、保留回滚 | 由玩家承担新的现在 |

## 9. 单层统一九拍

每层使用同一可制作骨架，但以不同动词和空间结构完成，避免体验重复。

| 拍 | 目标 | 时长预算 | 强制输出 |
|---:|---|---:|---|
| 1 入层异象 | 提出本层问题，不给答案 | 20–40 秒 | 一幅可截图的异常 + 一句抄写员限制声明 |
| 2 第一次查询 | 教最小新动词并改变世界 | 2–4 分钟 | 持续环境变化，不只弹 Toast |
| 3 生态反例 | 普通怪或地标说明错误结论为何诱人 | 2–3 分钟 | 一个可操作反例 |
| 4 中段证据 | 把课程结果变成路线或场景变化 | 3–5 分钟 | 新路径、状态切换或可回访点 |
| 5 区域首领 | 用当前层已学语法做两阶段复合题 | 2–4 分钟 | 后区解锁 + 主题转折 |
| 6 隐藏证词 | 可错过，补人物或世界真相 | 2–4 分钟 | 证据 / 换装，不阻塞主线 |
| 7 第二次变化 | 把前半结论推翻或加上边界 | 3–5 分钟 | 抄写员态度改变 |
| 8 密文与层主 | 玩家用综合证据反驳错误信条 | 4–7 分钟 | Boss 多阶段 + 身份回收 |
| 9 离层回声 | 给出本层答案并提出下一层问题 | 20–45 秒 | 物理上升、主题乐句或场景回收 |

主线弹框首屏不超过 4 行，每行不超过约 22 个全角字符；更多背景进入可选证据页。重复调查只显示
“当前事实 + 下一目标”，不重播完整演出。

## 10. 第一层：地下余烬档案

### 10.1 层级意图

- 核心问题：`SELECT` 返回 0 行，是否说明玩家不存在？
- 核心动词：调查、排水、回返。
- 情绪：寒冷陌生 → 小小火光 → 不安的希望。
- 独有空间：双岸失名档案；水位变化把“查到”变成“看见道路”。
- 层结论：**没有结果不是不存在；它只限定了当前表、当前条件与当前时刻。**

### 10.2 九拍内容锁

| 拍 | 地点 / 稳定键 | 玩家行为 | 剧情与世界结果 |
|---:|---|---|---|
| 1 | `floor-1-entry` / `f1-spawn-ember` | 接近余烬与抄写员 | 火向玩家偏转，登记册却显示 0 行；抄写员只说“这两件事都是真的” |
| 2 | `f1-water-wheel` / ID #001 | 完成 `SELECT / FROM` | 水轮转动、栈桥落下；玩家第一次让查询改变空间 |
| 3 | 排水渠 / ID #002、#006–#008 | 用 `WHERE` 缩小范围 | 水位下降，墙上被水遮住的旧刻痕显形；随机生态只复习已学语法 |
| 4 | `f1-nameless-beds` / ID #003 | 区分缺行与 `NULL` | 床牌从 `???` 变为明确 `NULL`；“未知值”不等于“没有这一行” |
| 5 | 课程 ID #004；F1 无通用区域首领 | `GROUP BY` 整理恢复回执 | 七个来源分堆；中央路亮起，第一次铺垫第二层 |
| 6 | `f1-hidden-sealed-vault` / ID #009 | 开旧库或调查可疑宝箱 | 撕页证明有人主动移除登记；宝箱怪只在玩家选择调查时出现 |
| 7 | `shortcut:1:return` / `f1-scribe-desk` | 从深处打开身后的门 | 门回接入口，抄写员承认“我不能再把空白当判决” |
| 8 | `gate:floor-1-boss` / ID #005 | 用 `HAVING` 审计来源并击败层主 | 登记官的“无当前行即拒绝恢复”规则被改写；最后一击回收姓名 |
| 9 | `f1-lift` | 读取失名录第一页并上行 | 升降机显示七枚潮湿封签：同一段恢复从七处归来 |

### 10.3 身份与失败边界

- ID #001–#009 在存活时不得由字幕、无障碍文本、目标或 SQL 反馈泄露真名；
- 死亡回到篝火后，抄写员只复盘玩家已经提交的查询，不提前给出登记官结论；
- 读档后水位、床牌、回执和捷径必须由已提交事实恢复，不重复发放旧库证据；
- F1 允许没有区域首领，但不能用宝箱怪替代必修门控。

## 11. 第二层：月潮群岛

### 11.1 层级意图

- 核心问题：七份相似恢复记录，是一份重复数据，还是七段不同生命？
- 核心动词：航行、选岛、改潮。
- 情绪：短暂明亮 → 自由探索 → 发现被合并者的代价。
- 独有空间：三个物理区承载海岸、湖区、林沼与后区灯塔四个叙事子场景。
- 层结论：**相同值可以去重显示，不能因此删除来源。**

### 11.2 九拍内容锁

| 拍 | 地点 / 稳定键 | 玩家行为 | 剧情与世界结果 |
|---:|---|---|---|
| 1 | `floor-2-entry` / `f2-ranked-beacons` | 读取七枚熄灭航标 | 七张防水页拥有相同正文、不同潮痕；抄写员建议先保留顺序 |
| 2 | ID #010 / `ORDER BY, LIMIT` | 点亮航标 | 航标按风险排序，短船靠岸；顺序第一次成为路径 |
| 3 | ID #011、#015–#020；ID #021 可选 | 用 `DISTINCT` 识别重复水纹；挑战湖兽 | 重复显示被合并但来源封签仍保留；击败湖兽只改变前区潮位，不解锁后区 |
| 4 | `f2-root-bridge` / ID #012–#013 | `INNER JOIN` 连桥，再用 `LEFT JOIN` 保留未匹配住户 | 根桥形成，沉水村落中无装备记录的门显形 |
| 5 | `f2-frog-court` / ID #022 | 两阶段中区守卫战 | 蛙王无法再把未匹配住户封在沼泽；胜利后硬门解除并自动进入后区 |
| 6 | `f2-hidden-wreck-ledger` | 查沉船来源 | 隐藏记录说明七份来自不同事故；只补充出处与情绪，不独占主线答案 |
| 7 | `f2-drowned-village` | 回访已经退水或显形的村落 | 抄写员把“重复”改写为“同值、异源”，并明确保留未匹配者 |
| 8 | `gate:floor-2-boss` / ID #014 | 综合 JOIN 校准灯塔 | 灯塔同时照向七个方向，不再只选一条“标准来源” |
| 9 | `f2-north-ferry` | 登船 | 船底浮出被磨去姓名、仍保留关系编号的墓牌，指向第三层 |

### 11.3 叙事边界

- 灯塔岛是后区叙事子场景，不是第四个生成器 Region；
- #022 是当前中区通往后区的唯一硬门；#021 是前区可选湖兽，只改变潮位与探索路线；
- `DISTINCT` 的世界结果是“折叠显示”，绝不暗示安全删除原记录；
- 捷径短航线只减少已走过的折返，不跳过沉水村落证据。

## 12. 第三层：白霜墓原

### 12.1 层级意图

- 核心问题：姓名和所有者字段消失后，关系还能否证明一个人曾存在？
- 核心动词：侦查、对照、还原。
- 情绪：寂静哀悼 → 关系显形 → 对规则的第一次怀疑。
- 独有空间：骨桥、双墓园证词、幽火地宫；同地“白昼证词 / 幽灵证词”双状态。
- 层结论：**可连接项、孤立项和冲突证词必须共同审计。**

### 12.2 九拍内容锁

| 拍 | 地点 / 稳定键 | 玩家行为 | 剧情与世界结果 |
|---:|---|---|---|
| 1 | `floor-3-entry` | 观察没有姓名的墓碑 | 墓碑的关系槽仍结霜发亮；抄写员承认名字不是唯一证据 |
| 2 | ID #023 / `INNER JOIN` | 连接墓碑与遗物 | 骨桥只在成功匹配处成形，直观展示内连接的遗漏 |
| 3 | ID #024、#029–#032 | `LEFT JOIN` 保留全部墓碑 | 无遗物墓仍被保留；白昼证词显形 |
| 4 | ID #025–#027 | SELF / 三表链 / `UNION` | 亲缘、遗物与守墓记录组成多源链，幽灵证词覆盖同一空间 |
| 5 | 腐土墓园 / ID #033 | 两阶段区域战 | 墓主无法再把孤立记录封为“无主”；后区墓门开放 |
| 6 | `f3-hidden-reliquary` | 调查无主遗物室 | 获得不会阻塞主线的证据：无主不等于从未属于；本层不强制换装奖励 |
| 7 | 双名墓碑与篝火 | 对照两种证词 | 抄写员指出连接规则本身也可能制造沉默者 |
| 8 | `gate:floor-3-lesson-6` / ID #028 | 完成继承审计 | 死灵王的“无 owner 即无历史”被推翻，墓门从内部打开 |
| 9 | 葬火井 | 点火上升 | 火焰同时呈火、冰、雷三色，说明断裂来自同一上游命令 |

### 12.3 叙事边界

- 双状态必须改变光、Actor 透明度和证词内容，而不是只换地板颜色；
- `LEFT JOIN` 不是“自动更正确”，只是在本题选择保留墓碑侧全部记录；
- 无主遗物室保持证据奖励节奏，不为“每层都发甲”破坏稀有度；
- #033 存活时所有普通步行、区域门和捷径都不得绕过后区门控。

## 13. 第四层：三相升炉

### 13.1 层级意图

- 核心问题：找到灾难源头后，能否直接终止它？
- 核心动词：追踪、接线、断路。

## 21. 验收标准

### 21.1 每层

- 玩家能用一句话说出本层问题与答案；
- 至少 4 次课程结果产生持续世界变化；
- 至少 1 次非战斗解决、1 次区域转折、1 个可选隐藏证词；
- 抄写员至少有一次基于新证据改变立场的行动；
- Boss 信条是本层错误结论的最强版本，不是随机反派台词；
- 离层画面既收束本层，又提出下一层问题；
- 首演、重复、死亡、撤退和读档均有明确语义；
- 击杀前无任何姓名泄露。

### 21.2 八层整体

- 八层核心动词、空间结构、场景机制与情绪曲线均不重复；
- 六条跨层线索全部拥有铺垫、变义与回收；
- 抄写员的八步人物弧能从实际行为看见，不依赖人物小传；
- 最终五阶段分别调用前七层证据，不在结局突然发明答案；
- `MIGRATE` 明确保留历史、验证和回滚路径；
- 完整 Run 中连续两段不可交互叙事总时长不超过 45 秒；
- Reduced Motion、无音频和素材加载失败时仍能理解全部关键事实。

## 22. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 八层文本量失控 | 主线只保留行动所需信息，背景进入可选证据和失名录 |
| F1/F2 太细、F5/F8 太薄 | 统一事件合同，先补行为和状态，再做文辞润色 |
| 地图区名漂移 | 强制三物理区 + 多叙事子场景映射，不新增运行 Region |
| SQL 教学被剧情遮住 | 先给任务与字段，再给世界含义；Boss 不口述答案 |
| 身份谜题妨碍输入 | SQL 目标始终用现有 `id`；姓名只在胜利后进入图鉴 |
| 随机性破坏因果 | Seed 只改变非关键遭遇与装饰，剧情提交由稳定事实驱动 |
| 回燃等跨层场景破坏存档 | 使用本层记忆空间和返回锚点，不切换真实楼层状态 |
| 最终结局像技术清单 | 每个迁移步骤绑定具体人物代价和前层证据 |

## 23. 实施 Checkpoint

1. `N1 / Authority`：关闭内容真源漂移，补区域映射；
2. `N2 / F1–2`：用本稿验收现有长脚本，删重复解释；
3. `N3 / F3–4`：补双状态、炉路行为、回燃线索和中断恢复；
4. `N4 / F5–6`：补巡逻空档、原始/候选/回滚三态与抄写员过失；
5. `N5 / F7–8`：补双路径代价、七窗/四翼分层、五阶段终局；
6. `N6 / Full Run`：八层文字、身份泄露、节奏、音频降级与存档联合 QA。
