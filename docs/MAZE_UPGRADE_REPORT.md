# SQL 魔王城：种子迷宫探索实施与验收报表

状态：**核心 MVP 已实施；自动化通过，浏览器验收仍有明确未测项**
日期：2026-07-21
范围：迷宫地图、游荡怪物、触碰遭遇、物品拾取、反馈音效、打击感、新手引导与实时状态

## 0. 结论与证据边界

当前实现已经把旧的路线节点玩法替换为 64×48 连续迷宫，并完成同格遭遇、独立 SQL 对战、
触碰拾取、v2 Run 存档、发现式小地图、巡逻怪物与渐进引导。自动化覆盖迷宫确定性和 500 个
Seed 的课程可达/门锁/环路不变量、SQL 判题、巡逻纯函数、存档损坏回退、引导状态，以及两种
自由分支顺序下不使用传送/定位辅助的完整物理通关路径。

固定约 1280px 宽的桌面浏览器表面已实际完成：移动、同格遭遇、两次正确查询、战后拾取过滤弓、
穿过已开启知识门进入 WHERE 区；还实际观察了慢速巡逻、怪物主动撞静止玩家、错误查询反击与 HP
下降、终端焦点环绕，以及刷新后恢复同一 Seed。

以下项目没有被上述证据覆盖，因此本报表不把它们写成已完成：不使用测试传送辅助的完整手动
Run、390×844 触控闭环、200%/320px、Reduced Motion、音频主观试听与精确音画时序、持续移动
10 秒性能与存档写入频率。实现与原批准规格之间的差异也在下文逐项保留，不用构建通过替代。

## 1. 本次目标

把当前“十个路线节点 + 单房间模板”的第一层，升级为一张真正可行走、有回环、有探索迷雾的种子迷宫。玩家不再点击路线图传送或按怪物顺序推进，而是在连续世界中寻找区域、观察缓慢巡逻的怪物、与怪物发生实际触碰后进入独立 SQL 对战，并在战后走到掉落物上完成拾取。

所有移动、碰墙、遭遇、查询施法、命中、受伤、掉落、拾取、治疗、开门和胜负都要有语义一致的画面、声音与文字反馈。第一次进入的新手通过非模态、逐步推进的引导完成第一个探索闭环。

## 2. 用户 / 干系人

| 角色 | 需求 | 成功标准 |
|---|---|---|
| SQL 初学者 | 不看外部说明也知道下一步做什么 | 能完成移动 → 触碰遭遇 → 打开终端 → 正确查询 → 拾取 |
| 面试复习者 | 快速练习完整 SQL 并看懂错误 | 一回合内能核对目标、结果、伤害、剩余 HP 与下一问 |
| 博客访客 | 打开即玩，桌面和手机都可操作 | iframe、触控和本地存储受限时仍能完成当前页面游戏 |
| 内容维护者 | 可扩展后续 SQL 楼层 | 课程依赖与物理地图分离，新增装饰不会改变课程拓扑 |

## 3. 调研结论：借鉴 Minecraft 的生成架构，不复制实现

Minecraft 官方世界生成说明的核心不是“某一种噪声”，而是：Seed 驱动、分阶段生成、地形/生态/结构/Feature/实体分层，以及同一版本下的可复现性。Feature 还拥有独立的放置阶段与条件规则。适合本项目借用的，是这套架构，而不是 3D 密度场、无限世界或原版参数。

参考：

- [Minecraft World Generation Overview](https://learn.microsoft.com/en-us/minecraft/creator/documents/world-generation?view=minecraft-bedrock-stable)
- [Minecraft Feature Rules](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/featuresreference/examples/featuresintroduction?view=minecraft-bedrock-stable)
- [Minecraft Jigsaw Structures](https://learn.microsoft.com/en-us/minecraft/creator/documents/structures/introductiontojigsawstructures?view=minecraft-bedrock-stable)
- [Rooms and Mazes](https://journal.stuffwithstuff.com/2014/12/21/rooms-and-mazes/)

当前实现采用以下映射：

```text
世界 Seed + 生成器版本 v2
  → 课程依赖图（必修知识与关键奖励）
  → 64×48 物理迷宫（16×16 技术分区）
  → DFS 基础迷宫 + 十个抖动矩形 POI + 门连接修复 + 受控环路
  → 独立地面装饰
  → 从课程锚点确定性派生怪物与道具位置
  → 拓扑、课程可达性与门锁校验
```

生成器当前只使用两个独立子 Seed：`topology` 与 `decor`，并已有测试证明改变装饰密度不会改变
地砖、POI、知识门或拓扑 Hash。`theme`、`loot`、`spawn` 独立随机流和 `contentVersion` 尚未实现；
怪物与关键掉落目前由课程图、迷宫锚点和固定内容确定性派生。以后若内容变化会影响同 Seed 的
结果，必须提升生成器/存档版本，不能声称已有内容版本隔离。

## 4. MVP 范围

### 4.1 连续种子迷宫

- 一层生成 64×48 tile 的完整地图，视口保持 640×416，由相机跟随玩家。
- 保留现有十个逻辑房间作为课程 POI，但不再把它们当作传送节点。
- 使用 DFS 走廊、十个固定宏观槽位中的抖动矩形区域、单入口知识门、连接修复和额外环路。
  `src/content/runContent.ts` 中仍有旧房间模板数据，但当前迷宫生成器没有使用加权模板池。
- 在当前内容与生成器 v2 下，同 Seed 得到一致的拓扑、POI、初始怪物和关键掉落；当前数据模型
  没有单独的 `contentVersion`。
- 地图包含入口安全区、教学区、WHERE/IS NULL 自由分支、可选房、聚合门、精英区和 Boss 区。
- 原路线图改成发现式小地图：只显示已探索地面、当前位置、已发现目标与知识门，不再点击传送。

### 4.2 非线性探索与知识门

- 玩家实际走路进入区域，不按怪物编号推进。
- SELECT 作为首个教学闭环；完成后 WHERE 与 IS NULL 同时可探索，顺序自由。
- 可选篝火、宝藏和事件可自由绕行。
- GROUP BY 与 HAVING 仍保留必要知识门；GROUP BY 门除要求 WHERE/IS NULL 外，还要求玩家在固定
  祭坛按 `E` 真正领取聚合战锤。门锁显示缺少的概念或奖励，不允许直接传送、调试定位或物理
  踏入绕过。
- 随机性不得阻断必修课程、Boss 路径或关键武器。

### 4.3 游荡怪物与触碰遭遇

- 普通怪在所属房间内圈、出生点周围 3–5 格缓慢四向巡逻；当前每 1,100ms 最多判定移动一格，
  确定性的原地候选提供停顿概率。
- Boss 固定；新手安全区没有主动巡逻怪。
- 怪物不穿墙、不越锁定知识门、不站到道具或其他怪物上；巡逻位置严格排除房间边界、知识门
  与共享走廊，因此不需要依赖方向敏感的桥分析也不会占用迷宫窄口。恢复旧 v2 Run 时，落在
  非法巡逻位置的怪物会回到所属房间锚点。
- 玩家尝试进入怪物所在格，或怪物尝试进入玩家所在格时，立即锁定移动并只触发一次独立对战。
- 邻接不再由实际 UI 自动开战；战斗与场景切换时巡逻暂停。窗口失焦或页面隐藏时，Scene 会
  显式设置暂停状态、清空持续按键并停止接收移动和推进巡逻；恢复焦点后再按可见性恢复。
  这条应用层路径已有实现依据，但尚未留下真实浏览器切页/回切的单独验收记录。

### 4.4 地面物品与拾取

- 武器、遗物、治疗与钥匙统一为有稳定 `itemId` 的地面物品。
- 怪物死亡先产生“掉落”反馈；玩家走到松散掉落上自动拾取，形成类似 Minecraft 的接触拾取节奏。
- 祭坛、篝火和宝箱仍使用 `E` 调查，避免所有交互都变成误触。
- 掉落与拾取严格分成两个事件、两种音效；失败的 `E` 不播放奖励音。
- 触碰拾取的武器 Toast 展示伤害和热量减免前后值；祭坛按 `E` 领取聚合战锤时也使用同一套
  数值差异文案，明确显示伤害与热量减免的前后变化。

### 4.5 音效矩阵与打击感

新增原创 Web Audio cue：

| 事件 | 声音与画面 |
|---|---|
| 走路 / 碰墙 | 固定短脚步音加噪声；碰墙低频短音并做 150ms 节流 |
| 遭遇 | 多音警报、约 100ms 音乐交接、目标锁定通知 |
| 查询施法 | 独立的 query-cast 上升音，不提前播放命中声 |
| 怪物受伤 | 命中音、40–55ms 局部停姿、8–12 个像素碎片、伤害飘字、短震屏 |
| 玩家受伤 | 查询碎裂、怪物前冲、低频冲击与 HP 变化；尚无独立红色 HP 差值层 |
| 阶段完成 | 确定性的 `SQL CRITICAL` 提示，不增加随机伤害 |
| 掉落 / 武器 / 遗物 / 治疗 / 胜负 | 各自独立音色；拿到楼层钥匙后播放胜利 |
| 知识门 | 视觉状态更新；快照差异检测到门从锁定变为开放时派发一次 `gate-open` cue 与文字通知 |

命中帧到 HP 可见变化目标不超过 80ms。Reduced Motion 下移除震屏、轨迹、插值和装饰闪烁，但保留即时颜色、数值、文本和离散怪物逻辑。

### 4.6 新手引导与实时反馈

首次流程同时只显示一个非模态步骤：

1. 移动一格。
2. 跟随青色信标找到怪物；触碰会进入战斗。
3. 按住 `Q + S` 或点击 SQL 按钮。
4. 阅读任务、Schema 和当前知识锁。
5. 写出完整 SQL，并用 `Ctrl/Cmd + Enter` 执行。
6. 走到战利品上完成拾取；祭坛和宝箱使用 `E`。

每一步由真实游戏事件推进，不按计时器自动跳过；允许跳过和重播。当前引导把“阅读任务、Schema
和知识锁”合并到“写完整查询”步骤，因此是五个里程碑而不是六个独立步骤。HUD 提供数值 HP、
I/O 热量、拾取 Toast 和知识门原因；终端实现焦点环绕，关闭后归还来源。当前只保留统一反馈
Toast 作为 `aria-live` 状态区，多条语义提示排队显示，避免知识门通知被同一操作的拾取或查询
结果立即覆盖。窄屏 SQL 输入字号为 16px，主要按钮至少 44px；目标名、意图、
HP 等关键信息为 10–12px，交互提示为 11px 并允许换行，不再用省略号截断。VoiceOver 真实播报、
200%/320px 重排和 390×844 设备操作仍需浏览器验收，不能由 DOM/CSS 和单元测试代替。

## 5. 不做什么

- 不实现无限世界、动态远程区块、3D 体素、地下含水层或 Minecraft 存档格式。
- 不复制 Minecraft、宝可梦或其他游戏的源码、美术、音频、地图参数和关卡文本。
- 不新增第三方运行依赖、版权音频或外部素材。
- 不在本轮扩展 JOIN、子查询、窗口函数、事务与索引等新 SQL 课程。
- 不引入服务端、账号、排行榜、多人或 AI 出题。
- 不用随机暴击改变课程伤害，也不让随机掉落影响必修进度。

## 7. 数据与存档决策

- 新增 `MazeFloor`、`MazeZone`、`MazeGate`、`WorldActor` 与 `GroundItem`；探索状态实际保存为
  `discoveredCells`，引导状态实际由 `OnboardingController`/`OnboardingSnapshot` 管理，没有名为
  `DiscoveryMap` 或 `TutorialProgress` 的公开类型。
- Run 保存升级为 v2，并保存最终地图、演员位置、地面物品和探索迷雾。
- v1 Run 的局部房间坐标不能安全迁移，明确忽略并创建新 Run；永久 SQL Profile v1 无损保留。
- 引导完成状态使用独立 `select-from-dungeon:onboarding:v1`，不污染 SQL 熟练度档案。
- 正常巡逻由 Scene 局部更新且不发 Session 快照；Scene 只派发怪物位置差量给发现式小地图，
  因此不会每 tick 触发 AppShell 完整 DOM 重绘或同步存储。玩家移动仍会触发 AppShell 全量
  render。Run 写入采用 350ms debounce，模式、查询数、物品集合
  或拓扑变化立即 flush，`pagehide`/`beforeunload` 也会刷新。

## 9. 风险与取舍

| 风险 | 处理 |
|---|---|
| 课程图可解但物理地图不可解 | 对未解锁、分支解锁和全部解锁三个状态分别做 BFS 校验 |
| 随机地砖产生孤岛 | 当前不使用 Noise 切墙；主通路由 DFS、门连接修复和 BFS 校验保证 |
| 怪物与玩家 Tween 同时占格 | Session 原子裁决目标格，Scene 只播放结果 |
| 怪物堵住唯一窄路 | 巡逻严格限制在所属房间内圈，排除边界、知识门和共享走廊；代价是怪物不会跨房追逐，动态感服从课程路径安全 |
| 全局 RNG 导致改装饰换地图 | 已隔离 `topology` 与 `decor`；`theme`/`loot`/`spawn` 独立随机流尚未实现 |
| 大地图对象过多 | 静态地形与迷雾使用 Graphics；门、怪物、物品、装饰和标签使用独立对象，仍需性能实测 |
| 高频移动导致重绘与存档抖动 | 巡逻与小地图标记做差量更新，存档 debounce，关键事件立即 flush；玩家移动仍会全量刷新 AppShell，需性能实测 |
| 过度打击感干扰学习 | 必要玩法反馈 > SQL 结果与下一步 > 装饰；每次动作只保留一个主飘字和状态 |
| Web Audio 无法自动播放 | 首次手势解锁；不可用时完整视觉/文本降级 |
| 旧 Run 坐标不兼容 | 版本化丢弃旧 Run，永久学习档案不受影响 |

## 10. 实施 Checkpoint

1. **领域层**：生成器、校验器、巡逻纯函数和 500 Seed 测试。
2. **玩法层**：Session 连续移动、知识门、碰撞遭遇、地面物品和 v2 存档。
3. **呈现层**：完整迷宫、相机、迷雾、小地图、游荡怪和触碰过场。
4. **反馈层**：音效矩阵、命中时间线、Toast、HUD 与新手引导。
5. **验收层**：自动化、桌面、移动端、Reduced Motion、文档与完整 Diff 审计。

Checkpoint 1–4 已形成实现；Checkpoint 5 只完成自动化、固定桌面首闭环和文档审计，移动端、
缩放/Reduced Motion、完整手动 Run、音频与性能证据仍缺失。只有全部显式验收项有证据时才算
完整验收；构建通过不能替代玩法和浏览器证据。
