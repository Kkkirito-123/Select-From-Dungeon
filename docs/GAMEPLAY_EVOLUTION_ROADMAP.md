# SQL 魔王城玩法演进总路线图

> 状态：已确认的演进路线；`v0.2.0` 至 `v0.9.0` 已实现，后续版本仍按版本单独确认
> 当前稳定版本：`0.9.0`
> 发布原则：一个版本对应一个独立 PR；当前版本合并并记录后再开始下一版本

## 1. 总目标

把当前六层 SQL 迷宫逐步升级为八层像素肉鸽学习游戏，同时保持：

- SQL 学习是主线，地图探索不挤占主要时间。
- 地图、怪物和非关键掉落可以随机，课程和必需奖励不能随机卡死。
- 不使用 Agent、模型 API、账号或云端数据库。
- 浏览器本地运行、低性能消耗、刷新后能够恢复当前 Run。
- 每次改进范围可验收、可回滚、可通过单独 PR 记录。

## 2. 用户与干系人

- 主要玩家：SQL 初学者、面试八股复习者。
- 次级玩家：从博客 iframe 直接进入游戏的访客。
- 维护者：需要通过版本、测试、文档和 PR 管理长期迭代的项目作者。

## 3. 已确认的总体规则

### 3.1 学习与复盘

- 不接入 Agent，复盘由本地规则生成。
- 死亡复盘只展示导致死亡的本场战斗。
- 篝火复盘展示当前楼层的全部作答记录。
- 记录玩家 SQL、正确答案、错误类型、提示使用和战斗结果，不记录每一步移动。

### 3.2 篝火与复活

- 每层有 3 个篝火，按前、中、后三个区段分别随机。
- 篝火石圈围住的完整区域和出生区域都是安全区。
- 安全区内不生成怪物、不触发随机遭遇，巡逻怪物不能进入。
- 选择 `在此休息` 后恢复满生命并自动将当前篝火设为复活点。
- 死亡后返回最近休息的篝火；尚未休息时返回出生点。
- 导致玩家死亡的怪物保持剩余生命，不恢复满血。
- 死亡保留经验、武器、防具、道具、开门和课程进度。

### 3.3 受控种子与捷径

- 种子决定地图具体形态，但必修路径、课程依赖和关键奖励由规则保证。
- 同一地图种子、楼层和生成器版本得到稳定结果，刷新不能重抽。
- 地图按课程主路径、回环、篝火、捷径、生态、怪物和验证的顺序生成。
- 捷径只减少重复赶路，不能跳过必修 SQL。
- 捷径钥匙与楼层钥匙分离，不能依赖普通怪随机掉落。

### 3.4 怪物阶级

| 分类 | 题目 | XP | 作用 |
|---|---|---:|---|
| 普通怪 | 一道已解锁基础题 | 1 | 高频练习 |
| 小型精英 | 连续两道本层基础题 | 3 | 随机挑战 |
| 区域首领 | 二阶复合题起步 | 3 | 可选生态挑战与主题奖励 |
| 固定精英 | 二阶复合题起步 | 3 | 课程组合能力检查 |
| 层主 | 当前层综合题 | 5 | 楼层结业 |
| 最终魔王 | 跨层多阶段综合题 | 5 | 整轮结业 |

- 小型精英不设每层数量硬上限，由有限遭遇点和逐层概率控制。
- 湖泊、泥沼、森林等大型生态区域可以各有一个区域首领。
- 第一层使用史莱姆族，后续逐层升级到第八层魔王军团。
- 怪物名称保持简短直接，并与 SQL 表中的 `name` 完全一致。

### 3.5 地图生态

- 地图不通过增加面积延长时间。
- 两个有意义目标之间约为 10 至 18 个有效移动格。
- 湖泊、森林、泥沼、墓园、熔炉、要塞、龙巢、深渊和王座按楼层出现。
- 地形必须提供短路线选择、可选风险或奖励，不能只是背景。
- 空死路必须被移除，或放置明确可见的奖励和高难题。
- 环境使用静态像素图块与少量 2 至 4 帧动画，不使用高成本实时效果。

### 3.6 背包、防具与掉落

- 装备背包固定为 12 格；已装备武器和防具不占背包格。
- 玩家拥有一个武器位和一个防具位。
- 恢复品使用 3 个可堆叠快捷栏；钥匙和课程必需品不占格。
- 探索和篝火状态可以换装，战斗中禁止换装。
- 打开背包时暂停移动和怪物巡逻。
- 防具提供独立护甲生命，受到攻击时先扣护甲。
- 护甲生命最高为 3，篝火和复活恢复当前防具的全部护甲。
- 普通物品可以丢到脚下；离开楼层后才永久消失。
- 基础武器、钥匙和课程必需奖励不能丢弃。
- 一场战斗使用一个战利品包，最多显示 3 件不同物品。
- 每件候选物品独立计算概率，同场不重复；唯一装备在当前 Run 不重复掉落。

普通怪采用低掉落基线：

| 候选类型 | 单项独立概率建议 |
|---|---:|
| 当前生态恢复品 | 5% 至 6% |
| 修理片或磨刀石 | 2% |
| 当前层武器 | 0.5% 至 0.75% |
| 当前层防具 | 0.5% |
| 下一层武器 | 0.25% |

较高阶来源的非保证候选基线为：小型精英本层防具 `2.5%`；区域首领可选装备
`7.5%`、下一层武器 `1%`；层主可选装备 `7.5%`、下一层武器 `1.5%`。
普通怪大多数只获得 XP，没有物品掉落。小型精英至少一件，区域首领和层主至少两件；固定钥匙不计入三件上限。
以上低概率基线由 `v0.4.0` 建立，`v0.7.0` 已把候选拆成排水渠、软泥池、仓窖、湖泊、泥沼和
森林生态池。课程关键奖励、必需武器和钥匙的 `100%` 保证项不减半。

### 3.7 查询负载

- 第一至六层不显示当前的 `I/O 热量`，早期武器也不显示热量减免。
- 第七层学习索引、执行计划和查询优化时，才解锁名称更直接的 `查询负载`。
- 查询负载来自 SQLite `EXPLAIN QUERY PLAN`，必须明确标注为教学信号，不能宣称是真实 MySQL 性能。
- 查询负载优先影响优化评分或额外奖励，不直接惩罚 SQL 初学者。
- 第七层实现前重新确认负载阈值、奖励和晚期武器是否具有负载减免。

### 3.8 通关与死亡反馈

第一层及后续楼层通关：

```text
FLOOR 01 CLEARED
CONGRATULATIONS!!
```

- `CONGRATULATIONS!!` 使用金色像素字、短促金色扫光和原创通关提示音。
- 上方必须显示具体楼层，避免玩家不知道完成了哪一层。
- 约 1.5 秒后自动进入下一层，不要求再次移动或按键。
- 第八层改为 `DUNGEON CLEARED` 与最终通关文案。

玩家死亡：

```text
YOU DIED
正在返回最近篝火
```

- 正确拼写为 `YOU DIED`，不是 `YOU DEAED`。
- 使用暗红色像素字和短暂淡入，不照搬其他游戏的字体、构图或音效。
- 约 1.2 秒后返回最近篝火并自动打开本场死亡复盘。
- 无篝火记录时返回出生安全区。
- 文字和状态播报不能只依赖金色或红色，减少动态效果时取消扫光和缩放。

## 4. 八层内容骨架

精确 SQL 课程仍需在对应版本确认，但地图和怪物方向先固定：

| 层 | SQL 学习方向 | 地图生态 | 层主 |
|---:|---|---|---|
| 1 | `SELECT / FROM / WHERE` 基础 | 软泥地窖 | 史莱姆王 |
| 2 | 组合过滤、排序、限制与去重 | 森林、湖泊、泥沼 | 丛林之王 |
| 3 | 聚合函数、`GROUP BY / HAVING` | 亡者墓城 | 死灵王 |
| 4 | `INNER / LEFT JOIN` 与关系 | 元素熔炉 | 元素王 |
| 5 | 子查询、`EXISTS`、集合与 `CASE` | 黑铁要塞 | 城主 |
| 6 | CTE 与窗口函数 | 巨龙巢穴 | 龙王 |
| 7 | 索引、执行计划与查询优化 | 深渊回廊 | 魔龙 |
| 8 | 前七层综合与面试场景 | 魔王王座 | 魔王 |

边界：

- 当前 SQLite WASM 可以执行的语法使用真实结果判定。
- MySQL 特有执行计划、索引、事务和锁概念不能伪装成真实 MySQL 行为。
- 第七、八层在正式实现前必须单独确认是使用清楚标注的模拟题，还是引入隔离后端；没有确认前不扩展权限和数据库范围。
- `查询负载` 到第七层才解锁，第一至六层不显示该数值或武器减免。

## 5. 版本迭代顺序

每个版本都是一个可运行、可验证的垂直切片。小节会明确标出当前状态；未标记为已实现的版本仍是设计计划。

### `v0.2.0`：本地答题记录与复盘基础

状态：已实现。页面顶栏的 `答题复盘` 可随时打开最近一场战斗与当前楼层记录。

目标：

- 建立不依赖 AI 的作答记录。
- 支持本场死亡复盘和当前楼层复盘。

MVP：

- 记录 SQL、正确答案、错误类型、提示等级和战斗结果。
- 本场与本层两种只读复盘视图。
- 本地存档升级与异常恢复。

不做：

- 不加入篝火地图实体。
- 不改变死亡结算。
- 不接入 Agent 或后端。

验收：

- 刷新后当前层记录可恢复。
- 死亡复盘只包含本场，楼层复盘不混入上一层。
- 记录不会捕获无关按键和移动。

预计主要范围：

- `src/domain/`
- `src/storage/`
- `src/ui/`
- 对应测试和用户文档

### `v0.3.0`：三篝火、安全区与死亡复活

依赖：`v0.2.0`

状态：已实现。已完成 Run v7 迁移、133 项自动化测试、生产构建和桌面浏览器关键流程验证；
移动端篝火菜单与金色楼层结算仍列为专项视觉验收项。

目标：

- 用篝火替代整轮结束式死亡。
- 降低突发遭遇与战后卡片对探索节奏的打断。

MVP：

- 前、中、后三个稳定篝火。
- `在此休息 / 答案复盘` 两个选择。
- 最近篝火复活点、满生命恢复、安全区。
- 死亡回归和自动本场复盘。
- 敌人保留剩余生命。
- `YOU DIED / 正在返回最近篝火` 死亡反馈。
- `FLOOR NN CLEARED / CONGRATULATIONS!!` 金色通关反馈。
- 安全区外符合条件的成功移动按 2% 基础概率触发突发遭遇，连续 30 个符合条件的安静步数后保底。
- 战后 XP 结算卡与物品说明卡在之后完成 3 次成功移动后消失。

不做：

- 不加入捷径。
- 不加入背包和新掉落。

验收：

- 三个篝火均可到达且不堵路。
- 休息后复活点立即更新。
- 安全区内无生成、伏击和巡逻怪。
- 无篝火记录时回出生点。
- 通关和死亡反馈各只播放一次，结束后自动进入正确状态。
- 突发遭遇不会在安全区判定，刷新不会重抽，且不会超过 30 个符合条件的安静步数仍不出现。
- 卡片只计算成功移动；撞墙、菜单操作和按键不会让卡片提前消失。

### `v0.4.0`：装备背包、防具与低概率多掉落

依赖：`v0.3.0`

状态：已实现。已完成 Run v8 迁移、领域/存储自动化、生产构建，以及桌面与 390×844
窄屏背包关键流程验收；有物品战利品包仍列为专项浏览器视觉验收项。

目标：

- 建立可换装的肉鸽构筑基础。

MVP：

- 12 格装备背包、武器位、防具位和恢复品栏。
- 探索/篝火换装，战斗中禁止换装。
- 独立护甲生命。
- 每项独立低概率、最多三件、同场去重。
- 唯一装备不重复掉落。
- 战利品包、满包替换和可恢复丢弃。

不做：

- 不加入商店、金币、合成、耐久、品质和随机词条。

验收：

- 普通怪大多数无物品掉落。
- 背包已满时不会静默丢失物品。
- 刷新和死亡不会重抽掉落。
- 钥匙与课程奖励不能丢弃。

### `v0.5.0`：受控种子、地图引导与钥匙捷径（已实现）

依赖：`v0.4.0`

目标：

- 减少空走、回头路和不可解释的随机地图。

MVP：

- 从既有课程图、物理迷宫和篝火确定性派生主路线信标。
- 10 至 18 格兴趣点距离约束。
- 每层 1 道双向捷径及保证可得的中后段捷径钥匙。
- 篝火分段、关键物件和死路收益验证。
- 全部可修复死路被编织为回环，剩余走廊死路放置一次性补给。
- 不升级 `run:v8`：路线方案从存档迷宫派生，钥匙和打开状态复用既有字段。

不做：

- 不在本版本制作八层全部生态美术。

验收：

- 任意测试种子都能完成必修路线。
- 捷径不能绕过课程。
- 空死路为零，或具有明确可选奖励。
- 相同种子输出稳定。
- 400 个跨两层测试种子均满足零空死路、单一捷径、至少 17 格绕行价值和最大 18 格信标间隔。

### `v0.6.0`：八层课程契约与通用楼层框架（已实现）

依赖：`v0.2.0`、`v0.4.0`、`v0.5.0`

目标：

- 在继续制作内容前，固定八层课程、题目阶级和楼层数据边界。

MVP：

- 八层课程表和先修关系。
- 一阶、二阶、三阶题目契约。
- 普通怪、小型精英、区域首领、固定精英和层主配置结构。
- 楼层主题、装备池、怪物池和掉落池校验。
- 通用换层与八层存档结构。

实现结果：

- `FloorContracts` 固定 49 个有序课程节点、三种题阶、五类遭遇角色、八种主题拓扑，以及每层
  怪物/装备/掉落池和确定结业奖励。
- `CampaignDomain` 生成 8 个稳定楼层槽位，拒绝跳层、重复激活和 Seed 重抽；空壳可从第 1 层
  顺序推进至第 8 层并进入完成态。
- 截至 `v0.6.0`，可玩 `RunGraph` 仍只接受前两层，未实现楼层不会静默套用第二层内容。
- Run 存档升级为 `run:v9` 并携带 Campaign；有效 `run:v8` 至 `run:v4` 均可按原链路在内存中
  迁移，旧 Key 不删除。
- 顶栏显示当前 Campaign 槽位 `/ 08`，不把第三至八层契约误写成已经可玩的关卡。

不做：

- 不在本版本一次填满六个新楼层。
- 不接入真实 MySQL 后端。

验收：

- 内容校验能拒绝缺课程、缺层主、缺关键奖励和不可输入怪物名。
- 八层空壳能够顺序换层和存档恢复。
- 第七、八层的 MySQL 专属概念边界有明确标注。

### `v0.7.0`：第一、二层生态样板（已实现）

依赖：`v0.6.0`

MVP：

- 第一层史莱姆族与软泥地窖。
- 第二层湖泊、泥沼、森林。
- 水怪、水蛇、青蛙、毒蛙、猎犬、树妖。

### `v0.8.0`：第三、四层（已实现）

依赖：`v0.7.0`

MVP：

- 亡者墓城：骷髅、僵尸、幽灵、死灵王。
- 元素熔炉：火灵、冰灵、雷灵、元素王。

验收：

- 两层课程、生态、装备和层主均能完整通关。

## 6. 每个版本的统一交付方式

每个版本严格按以下顺序：

```text
确认本版本范围

→ 实现最小垂直切片
→ 运行聚焦测试

→ 检查完整 Diff

→ 提交并推送
→ 创建独立 PR
→ 用户审查并合并
→ 记录结果后开始下一版本
```

每个 PR 必须包含：

- 本次目标、MVP 和非目标。
- 改动文件与存档兼容策略。
- 自动化验证结果。
- 浏览器实际验证范围。
- 未验证内容和剩余风险。
- `GUIDE_*` 与 `README_*` 决定。

## 7. 总体验收标准

1. 八层课程从基础查询逐步进入复合查询与综合面试场景。
2. 每层具有独立地图、怪物、区域首领、层主、武器和防具。
3. 死亡回到篝火，不结束 Run，并提供本场复盘。
4. 篝火可以查看当前层复盘。
5. 地图具有湖泊、森林等主题生态，但不会增加无意义赶路。
6. 背包支持换装、满包处理和安全丢弃。
7. 普通怪大多数不掉物品，区域首领和层主提供可预期奖励。
8. 所有随机结果由种子稳定控制，刷新和死亡不能重抽。
9. 必修课程、关键武器和钥匙不依赖随机。
10. 浏览器本地运行，不需要 AI、账号或远程数据库。

## 8. 主要风险与取舍

- 八层内容量很大，必须先完成通用框架，再按两层一组扩展。
- 篝火、背包和八层都会改变 Run 存档，需要逐版本制定迁移或安全重开策略。
- 生态、区域首领和多掉落可能抢走 SQL 主线，因此先用前两层验证密度。
- 普通怪低掉落减少物品洪水，但可能降低即时惊喜；区域首领和宝箱承担稳定奖励。
- 敌人死亡后保持残血降低惩罚，需要通过复盘、返回路线和非刷怪规则维持挑战。
- 第七、八层涉及 MySQL 八股，而当前运行时是 SQLite；不能在技术边界未确认前伪造执行证据。
