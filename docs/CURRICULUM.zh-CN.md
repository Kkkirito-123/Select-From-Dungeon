## 1. 目标

把 SQL 魔王城从“题目依次变难”升级为“每层对应一个清晰知识簇”的学习游戏。玩家应当知道：

- 这一层正在学什么；
- 为什么当前题目属于这一层；
- 自己是依靠提示通关，还是已经能够独立解决变式题；
- 下一层建立在本层哪些能力之上；
- 哪些是可以真实执行的 SQL，哪些是索引、事务与数据库原理诊断。

完整路线覆盖常用 SQL 查询、写操作、事务、索引、执行计划和高频数据库面试知识，但不承诺覆盖
每一种数据库方言、DBA 运维命令或生产事故处理经验。

## 2. 用户与成功标准

| 用户 | 需要解决的问题 | 成功标准 |
|---|---|---|
| SQL 初学者 | 不知道从哪种语句开始学 | 每层只引入一个知识簇，Boss 不使用未教学语法 |
| 面试复习者 | 会写简单查询，但知识零散 | 可以按楼层定位薄弱主题，并进入变式复习 |
| 博客访客 | 只想快速玩几分钟 | 每个普通怪在 1–2 个有效查询阶段内结束 |
| 内容设计者 | 容易写出重复或无关题目 | 每个关卡都有统一的数据、提示、判定和验收契约 |
| 开发维护者 | 新增课程容易破坏旧进度 | 每层可以单独实现、测试、发布和迁移 |

## 3. 课程设计原则

1. **知识先于数值**：楼层难度主要来自概念组合，不靠重复攻击或单纯增加血量。
2. **先单表，后聚合，再连接**：不在基础过滤尚未掌握时引入分组和多表连接。
3. **完整输入但不过度抄写**：玩家自己填写 `SELECT ... FROM ...`；IDE 只补全关键词、表和完整字段名，
   不自动填入整条答案。
4. **判语义，也判知识点**：结果正确只是必要条件；当前关卡要求的语法能力也必须真实出现。
5. **答案不唯一**：允许别名、等价条件和合理的子句顺序，不要求逐字匹配标准答案。
6. **题目属于游戏世界**：任务围绕怪物、房间、装备、信号、宝箱和魔王城事件，不使用与场景无关的
   员工工资或学生成绩模板。
7. **字段必须完整可见**：终端、Schema 图鉴和补全菜单展示完整表名、字段名、类型及关系。
8. **短 ID 降低输入噪声**：新课程夹具在每层从可见短 ID `1` 开始；玩家不需要记忆 `101`、`1400`
   一类只增加抄写负担的编号。
9. **Boss 只综合本层**：Boss 可以组合本层和已掌握知识，但不能突然考察下一层语法。
10. **可选高难门只做预习**：越级挑战不授予正式课程掌握，不能跳过学习依赖。

## 4. 八层总览

| 层 | 主题与场景 | 必修能力 | 战斗主体 | Boss 验收 |
|---|---|---|---|---|
| 1 | 余烬青石城 | 单表选择、过滤、空值、排序与截取 | 查询战 | 一条完整单表综合查询 |
| 2 | 蒸汽聚合钟楼 | 聚合函数、分组、分组过滤与条件聚合 | 查询战 | 生成分组统计榜单 |
| 3 | 雷鸣关系桥城 | 内连接、左连接、自连接、多表连接与集合 | 查询战 | 连接房间、怪物和装备 |
| 4 | 镜影子查询地窟 | 标量子查询、`IN`、`EXISTS`、相关子查询与 CTE | 查询战 | 找出高于分组基准的目标 |
| 5 | 星轨窗口观测塔 | 分区、排名、前后行与累计窗口 | 查询战 | 每组 Top-N 与趋势判断 |
| 6 | 熔火回滚铸造厂 | 写操作、约束、事务、保存点与 ACID | 隔离沙箱战 | 修复副本数据并正确回滚 |
| 7 | 翠晶索引森林 | B+ 树、联合索引、覆盖索引、失效条件与执行计划 | 查询 + 计划战 | 降低综合查询计划成本 |
| 8 | 黑金数据王座 | MVCC、锁、隔离异常、建模、复制、分片与安全 | 事故诊断战 | 多阶段数据库面试终局 |

建议每层包含 5–6 个必修怪、1 个可选精英、1 个 Boss，以及复习前置知识的随机遭遇。单层目标
时长为 20–35 分钟；已经掌握的玩家可以通过独立答题缩短流程。

## 5. 各层课程定义

### 第一层：余烬青石城

**学习目标**：能够独立完成一条可靠的单表查询。
**前置知识**：无。
**执行边界**：真实只读 SQLite 查询。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 1-1 | 史莱姆 | `SELECT`、`FROM`、`AS` | 从指定表返回完整目标字段 |
| 1-2 | 蝙蝠 | `WHERE` 与比较运算 | 使用字段条件锁定单个目标 |
| 1-3 | 猎犬 | `AND`、`OR`、`NOT`、括号 | 正确表达组合逻辑，不依赖硬编码结果 |
| 1-4 | 宝箱怪 | `IN`、`BETWEEN`、`LIKE` | 在集合、范围和模式中筛选目标 |
| 1-5 | 幽灵 | `IS NULL`、`IS NOT NULL` | 不使用 `= NULL` |
| 1-6 | 排序守卫 | `DISTINCT`、`ORDER BY`、`LIMIT/OFFSET` | 去重、稳定排序并截取指定行 |

**Boss：查询监视者**

- 从单表中选择指定字段；
- 使用至少两个过滤条件；
- 正确处理空值或模式匹配；
- 按明确的第二排序键稳定排序；
- 截取所需结果；
- 禁止使用聚合、连接或子查询。

**确定奖励**：过滤弓、完整 Schema 图鉴。
**下一层预习门**：用 `COUNT` 和 `GROUP BY` 解除五道聚合锁。

### 第二层：蒸汽聚合钟楼

**学习目标**：能够把明细行转换成可信的统计结果。
**前置知识**：第一层独立通关，尤其是过滤和排序。
**执行边界**：真实只读 SQLite 查询。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 2-1 | 计数史莱姆 | `COUNT(*)`、`COUNT(column)` | 解释空值对计数的影响 |
| 2-2 | 统计魔像 | `SUM`、`AVG`、`MIN`、`MAX` | 选择与任务匹配的聚合函数 |
| 2-3 | 分组祭司 | `GROUP BY` | 每个非聚合输出字段都属于分组语义 |
| 2-4 | 门卫 | `WHERE` 与 `HAVING` | 分清分组前过滤与分组后过滤 |
| 2-5 | 条件女巫 | `CASE WHEN` | 创建条件字段或条件聚合 |
| 2-6 | 排名执行官 | 聚合 + 排序 + 截取 | 输出确定、可解释的统计榜单 |

**Boss：钟楼核心**

- 先过滤有效信号；
- 按频道或区域分组；
- 同时返回数量、总量和平均值；
- 只保留达到阈值的组；
- 按聚合结果和稳定第二键排序并取前 N 组。

**确定奖励**：聚合战锤、条件符文。
**下一层预习门**：用 `INNER JOIN` 连接怪物和房间，连续击破五道关系锁。

### 第三层：雷鸣关系桥城

**学习目标**：根据真实关系连接数据，并识别“右表不存在”的记录。
**前置知识**：第二层分组统计。
**执行边界**：真实只读 SQLite 查询；不支持的方言语法使用等价改写或概念演示。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 3-1 | 双表魔像 | `INNER JOIN ... ON` | 使用真实键关系，不允许 `ON 1=1` |
| 3-2 | 缺口史莱姆 | `LEFT JOIN` + `IS NULL` | 找出右表没有匹配的左表记录 |
| 3-3 | 镜像骑士 | 自连接 | 用清晰别名区分同一张表的不同角色 |
| 3-4 | 关系链兽 | 三表连接 | 控制连接基数，避免重复放大 |
| 3-5 | 集合双子 | `UNION`、`UNION ALL` | 对齐列数与类型，并解释去重差异 |
| 3-6 | 关系审计官 | 连接 + 聚合 | 在连接结果上正确分组和过滤 |

**Boss：雷鸣主核**

- 连接房间、怪物和装备；
- 保留没有装备的怪物；
- 统计每个区域的怪物数和装备强度；
- 使用 `HAVING`、排序和截取找出高风险区域；
- 结果不能因一对多连接而错误重复计数。

**确定奖励**：关系链刃、别名护符。
**下一层预习门**：用 `EXISTS` 找出至少拥有一种指定装备的怪物。

### 第四层：镜影子查询地窟

**学习目标**：能在一个查询中表达“依赖另一个查询结果”的问题。
**前置知识**：第三层连接和聚合。
**执行边界**：真实只读 SQLite 查询。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 4-1 | 标量宝箱怪 | 标量子查询 | 子查询只返回可用于比较的单值 |
| 4-2 | 空值陷阱 | `IN`、`NOT IN` | 识别 `NULL` 对 `NOT IN` 的影响 |
| 4-3 | 存在侦察兵 | `EXISTS`、`NOT EXISTS` | 用存在性表达半连接和反连接 |
| 4-4 | 回声法师 | 相关子查询 | 正确引用外层行，不制造无关重复计算 |
| 4-5 | 档案管理员 | `WITH` CTE | 把复杂查询拆成命名清晰的阶段 |
| 4-6 | 递归封印 | 递归 CTE 概念 | 只在可验证的小型层级数据上练习 |

**Boss：镜像议会**

- 计算每个房间的平均威胁值；
- 找出高于所属房间平均值的怪物；
- 使用 CTE 表达中间统计；
- 用 `EXISTS` 验证目标是否拥有指定信号或装备；
- 返回稳定、无重复的最终结果。

**确定奖励**：CTE 提灯、空值罗盘。
**下一层预习门**：使用 `ROW_NUMBER() OVER (...)` 找出每个区域第一名。

### 第五层：星轨窗口观测塔

**学习目标**：在不折叠明细行的情况下完成排名、比较和累计统计。
**前置知识**：第四层 CTE 与聚合。
**执行边界**：真实只读 SQLite 窗口查询。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 5-1 | 分区幽灵 | `OVER`、`PARTITION BY` | 理解窗口与 `GROUP BY` 的行数差异 |
| 5-2 | 序号守卫 | `ROW_NUMBER` | 每组产生确定、唯一的顺序 |
| 5-3 | 排名双子 | `RANK`、`DENSE_RANK` | 正确处理并列和排名空档 |
| 5-4 | 前后行猎手 | `LAG`、`LEAD` | 比较相邻事件而不做脆弱自连接 |
| 5-5 | 累计魔像 | 累计和、移动窗口 | 明确窗口排序与 frame |
| 5-6 | Top-N 执行官 | CTE + 窗口过滤 | 正确完成每组前 N 名 |

**Boss：时序观测者**

- 对每个区域内的怪物进行威胁排名；
- 保留每组前两名；
- 显示与前一名的差值；
- 计算区域累计威胁；
- 在并列数据下仍得到符合任务定义的结果。

**确定奖励**：窗口罗盘、时序披风。
**下一层预习门**：在隔离副本中完成五步写入，并通过 `ROLLBACK` 恢复原状态。

### 第六层：熔火回滚铸造厂

**学习目标**：安全修改数据，并理解事务边界和失败恢复。
**前置知识**：前五层查询能力。
**执行边界**：每场战斗使用一次性数据库副本；退出、失败或刷新都不能污染永久课程数据。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 6-1 | 写入工匠 | `INSERT` | 指定列写入，并满足类型、非空和唯一约束 |
| 6-2 | 修复守卫 | `UPDATE ... WHERE` | 预览影响范围，禁止无条件误更新 |
| 6-3 | 清理史莱姆 | `DELETE ... WHERE` | 先用等价 `SELECT` 验证待删除集合 |
| 6-4 | 约束魔像 | 主键、唯一、非空、检查、引用关系 | 根据失败信息定位数据问题 |
| 6-5 | 回滚骑士 | `BEGIN`、`COMMIT`、`ROLLBACK` | 明确事务成功和失败路径 |
| 6-6 | 保存点术士 | `SAVEPOINT`、`ROLLBACK TO` | 只撤销事务中的局部错误 |

**Boss：事务熔炉**

- 在一次隔离事务中写入修复记录；
- 更新明确目标，删除重复记录；
- 人为触发一个约束错误；
- 回滚到保存点后继续；
- 最终验证提交状态和原始永久数据均符合预期；
- 通过场景说明 ACID 四个属性，不以背缩写代替操作理解。

**确定奖励**：回滚盾、约束护甲。
**下一层预习门**：阅读 `EXPLAIN QUERY PLAN`，连续选出五个有效索引方案。

### 第七层：翠晶索引森林

**学习目标**：根据查询模式选择索引，并用执行计划验证，而不是死背“加索引”。
**前置知识**：连接、子查询和事务基础。
**执行边界**：查询在可重置性能夹具上执行；计划评分使用稳定教学指标，不把设备耗时当唯一标准。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 7-1 | B+ 树守卫 | B+ 树与索引定位 | 解释等值、范围与排序访问路径 |
| 7-2 | 联合索引兽 | 联合索引、最左前缀 | 根据过滤和排序顺序设计列顺序 |
| 7-3 | 覆盖幽灵 | 覆盖索引、回表 | 识别查询所需列是否都在索引中 |
| 7-4 | 失效巫师 | 函数、隐式转换、前导通配符、低选择性 | 解释为什么索引没有被有效使用 |
| 7-5 | 计划侦察兵 | `EXPLAIN QUERY PLAN` | 区分扫描、搜索、临时排序和连接顺序 |
| 7-6 | 优化执行官 | 查询改写与索引取舍 | 在写放大和查询收益之间做选择 |

**Boss：索引古树**

- 优化一个包含过滤、连接、排序和截取的查询；
- 先记录基线计划；
- 选择或设计联合索引；
- 必要时改写查询；
- 用稳定的扫描行数、临时结构和访问路径指标证明改善；
- 解释为什么不是索引越多越好。

**确定奖励**：索引之眼、计划透镜。
**下一层预习门**：诊断一个由 MVCC、锁等待和重试共同造成的事故。

### 第八层：黑金数据王座

**学习目标**：把 SQL 能力与高频数据库八股连接起来，完成事故级综合判断。
**前置知识**：前七层独立通关。
**执行边界**：查询可真实执行；MVCC、复制和分片题使用可重复的事务时间线、计划图或事故记录，
不伪装成 SQLite 能直接证明的生产行为。

| 节点 | 怪物 | 知识点 | 过关表现 |
|---|---|---|---|
| 8-1 | 版本幽灵 | MVCC、快照、可见性 | 根据事务时间线判断每次读取可见的版本 |
| 8-2 | 锁链骑士 | 行锁、间隙概念、死锁、等待 | 找出等待环并选择安全处理顺序 |
| 8-3 | 隔离巫妖 | 脏读、不可重复读、幻读 | 根据现象区分隔离问题，而非只背定义 |
| 8-4 | 建模魔像 | 范式、主键、唯一性、反范式 | 为明确读写目标设计可维护 Schema |
| 8-5 | 复制双子 | 主从延迟、一致性与可用性 | 识别读后写不一致和故障切换取舍 |
| 8-6 | 分片巨兽 | 分区、分库分表、路由、跨分片查询 | 判断何时不该分片以及拆分键风险 |
| 8-7 | 注入刺客 | 参数化、最小权限、输入边界 | 拒绝字符串拼接和越权查询 |

**最终 Boss：数据库魔王**

1. 写出一条包含连接、聚合和窗口函数的综合查询；
2. 用执行计划指出主要性能问题；
3. 选择索引并解释写入代价；
4. 根据并发时间线判断可见性、锁等待和隔离异常；
5. 提出安全、可回滚且可验证的修复顺序。

最终 Boss 允许分阶段保存进度，但每个阶段必须独立通过。通关代表完成高频 SQL 与数据库八股
路线，不代表已经具备生产 DBA 经验。

**确定奖励**：数据王冠、完整永久图鉴、变式挑战模式。

## 6. 战斗、提示与掌握度

### 6.1 战斗长度

| 遭遇 | 建议阶段 | 规则 |
|---|---:|---|
| 普通必修怪 | 1–2 | 第一阶段识别概念，第二阶段完成变式 |
| 精英怪 | 2–3 | 组合两个已经教学的概念 |
| 楼层 Boss | 3–5 | 综合本层，不重复完全相同的查询 |
| 随机遭遇 | 1 | 复习已学知识，不引入新语法 |
| 越级门守卫 | 5 | 明示“下一层难度”；失败会被一击击倒，胜利不授正式掌握 |

强制闯入越级门前必须二次显示风险。越级守卫的高血量来自五个不同知识锁，而不是让玩家把同一条
正确 SQL 重复执行五次。

### 6.2 从小到大的提示

| 等级 | 给玩家什么 | 不给什么 |
|---|---|---|
| 0 | 任务、怪物名、短 ID、完整 Schema | 不提示解法 |
| 1 | 应考虑的概念，例如“空值不能使用等号判断” | 不给表名和字段组合 |
| 2 | 需要使用的表、完整字段名和关系 | 不给子句顺序 |
| 3 | 语句骨架，例如 `SELECT ___ FROM ___ WHERE ___` | 不填关键表达式 |
| 4 | 对当前错误逐项诊断，并给出接近完整的结构 | 不自动执行、不直接结算胜利 |

提示必须累计展开，不能第一下就泄露答案。使用提示会影响掌握评价，但不会扣除永久学习进度。

### 6.3 掌握状态

每个知识点独立记录：

```text
未接触
  → 已教学
  → 提示通关
  → 独立通关
  → 变式掌握
```

- **进入下一层**：全部必修知识至少“提示通关”，并击败 Boss。
- **独立通关**：不使用 3–4 级提示完成正式关卡。
- **变式掌握**：在不同数据和不同目标下，连续完成两道无提示复习题。
- **楼层全掌握**：全部必修知识达到“变式掌握”；这是成就，不阻塞主线。

随机遭遇优先抽取最近失败、使用高级提示、或长时间未复习的旧知识点。题目数据应变化，不能只更换
怪物名字后继续使用完全相同的答案。

## 7. 题目与判定契约

每个课程节点在实现前至少定义：

```text
floorId
lessonId
prerequisites
conceptsIntroduced
battleType
schemaSnapshot
visibleTablesAndFields
gameObjective
stages
expectedResultSemantics
requiredQueryFeatures
forbiddenQueryFeatures
hintsFromSmallToLarge
reviewVariants
deterministicReward
bossContribution
```

实现必须满足：

- 怪物名字和当前目标在战斗前可见；
- ID 在题目和数据表中一致，并优先使用从 `1` 开始的短编号；
- 自动补全展示完整字段名，不用截断文本代替可访问的完整信息；
- 标准答案只用于测试，运行时判定基于结果语义和知识特征；
- 题目至少有一个与标准答案写法不同的等价解测试；
- 错误反馈区分语法错误、表/字段错误、结果错误、缺少当前知识点和危险语句；
- 普通关卡不要求输入无意义的重复 SQL 来消耗怪物血量；
- 每只必修怪掉落确定性奖励宝箱，随机遭遇只给经验；
- 写操作只发生在一次性沙箱，索引和事务测试不得修改永久档案。

## 8. 当前两层内容的迁移

当前实现仍保留双层 MVP：

- 第一层：`SELECT`、`WHERE`、`IS NULL`、`GROUP BY`、`HAVING`
- 第二层：`ORDER BY`、`DISTINCT`、`INNER JOIN`、`LEFT JOIN`、综合 `JOIN`

它可以继续作为可玩版本，但不是长期课程顺序。迁移时复用现有怪物、数据和判定，不一次重写全部内容：

| 新楼层 | 复用内容 | 需要补充 |
|---|---|---|
| 新第一层 | 当前 `SELECT`、`WHERE`、`IS NULL`，当前二层 `ORDER BY`、`DISTINCT` | `OR/NOT`、`IN/BETWEEN/LIKE`、新的单表 Boss |
| 新第二层 | 当前 `GROUP BY`、`HAVING` 与聚合战锤 | `SUM/AVG/MIN/MAX`、`CASE WHEN`、新的聚合 Boss |
| 新第三层 | 当前 `INNER JOIN`、`LEFT JOIN`、综合 JOIN Boss | 自连接、多表基数、`UNION/UNION ALL` |

迁移后的永久学习档案按 `lessonId` 映射，不按旧物理楼层编号判断是否掌握。旧 Run 可以明确开启新
Run，不尝试把玩家坐标跨课程地图迁移。

## 9. 分阶段交付

每一项单独提交 PR，避免“八层一起做”造成不可验收的大改：

1. **课程蓝图 PR**：只提交本文件、英文镜像和文档入口。
2. **课程数据契约 PR**：定义节点、掌握度和内容校验器，不改变地图。
3. **第一层重排 PR**：完成单表知识簇和单表 Boss。
4. **第二层聚合 PR**：迁移 `GROUP BY/HAVING`，补齐聚合函数与条件聚合。
5. **第三层关系 PR**：迁移现有 JOIN，补齐自连接、集合与基数验证。
6. **第四、五层 PR**：每层独立实现子查询/CTE 与窗口函数。
7. **沙箱引擎 PR**：先建立可丢弃写入环境，再实现第六层。
8. **计划评分 PR**：先建立稳定执行计划夹具，再实现第七层。
9. **事故模拟器 PR**：先定义事务时间线和诊断判定，再实现第八层。

任何一层开始编码前，都应先列出该层完整题目表、Schema 变化、存档迁移和浏览器验收路径。

## 10. 本文档不做什么

- 不在当前 PR 中实现新楼层、怪物、地图、美术或音频。
- 不修改现有 SQL 判定器、SQLite 安全边界、存档结构和经验数值。
- 不把 MySQL、PostgreSQL、SQLite 的差异混成一个“唯一正确语法”。
- 不用选择题完全替代写 SQL；理论题只用于无法由本地 SQLite 直接证明的内容。
- 不承诺玩家通关后自动具备生产数据库设计、调优或故障处理经验。

## 11. 文档验收标准与风险

### 验收标准

- 八层都有明确前置知识、必修节点、Boss、奖励和下一层预习门；
- 第一层到第五层语法依赖无倒序；
- 第六层写操作明确使用一次性沙箱；
- 第七层性能评价不依赖单台设备的绝对耗时；
- 第八层理论题使用可重复证据，不伪装成 SQLite 真实并发；
- 提示从概念逐渐增加到结构，不自动填答案；
- 掌握度区别“看提示过关”和“独立完成变式”；
- 当前双层内容有可执行、可回滚的迁移路线；
- 每个实现阶段都可以形成独立 PR 和独立验收。

### 风险与取舍

| 风险 | 取舍 |
|---|---|
| 八层内容量过大 | 按层交付，先重排前三层，再扩展后五层 |
| SQL 方言差异 | 运行题以项目当前 SQLite 为准，面试差异显式标注数据库类型 |
| 写操作破坏存档 | 第六层必须先有一次性数据库副本和重置验证 |
| 性能题受设备影响 | 使用计划结构和稳定计数，不以毫秒数作为唯一判定 |
| 理论题游戏感不足 | 使用事务时间线、事故日志和锁关系图，不退化成长篇背诵 |
| 提示导致照抄 | 高级提示降低掌握等级，复习题更换数据和目标 |
| 课程迁移破坏旧进度 | 以稳定 `lessonId` 迁移永久档案，旧 Run 明确重开 |
