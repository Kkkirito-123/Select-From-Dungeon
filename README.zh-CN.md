一个面向 SQL 初学者与面试复习者的浏览器肉鸽。SQL 就是战斗动作：探索由种子生成的像素魔王城，
实际走过连续迷宫，进入只显示编号的怪物所在格后切换到独立对战，写出一条完整 SQLite 查询，再把
正确结果变成攻击动画。

## 第一层学习路线

1. `SELECT / FROM`：先查询怪物 `#1` 的 `weakness`，最后用 `name` 查询完成击杀并恢复身份。
2. `WHERE / AND`：用房间和状态锁定 ID `#2`，再同时使用 `id` 与 `status` 查询弱点。
3. `IS NULL`：找出没有主人的怪物 ID，再找出“无主人且被诅咒”的怪物名字。
4. `COUNT / GROUP BY`：把 `monster_id = 4` 的信号按 `channel` 分组，并把数量命名为 `total`。
5. `HAVING`：先用 `COUNT(*) >= 2` 过滤魔王 `#5` 的信号组，再把阈值提高到 `>= 3`，只留下
   最强核心。

`WHERE` 与 `IS NULL` 是自由顺序分支；两者掌握并领取固定聚合战锤后，才会解锁 `GROUP BY`。
种子可以改变物理迷宫和非关键奖励，但不会改变必修查询数据，也不会让关键武器随机缺失。课程
依赖图只负责知识门锁，不负责传送；已经解锁的区域以玩家实际探索顺序为准。

每个阶段都有入局说明、可见 Schema、知识锁和渐进提示。第一层语法范围是一条平坦 `SELECT`，
暂不允许 `OR`、子查询或集合运算；在这个范围内，判定同时检查“结果语义 + 当前 SQL 知识点”。
表别名和 `HAVING total ...` 可以通过，不要求照抄唯一字符串。

## 第二层学习路线

1. `ORDER BY / LIMIT`：先找出最高 `charge` 的信号，再按降序返回前两名。
2. `DISTINCT`：从重复镜像信号中只保留不同的 `channel`，并按名称排序。
3. `INNER JOIN / ON`：用 `monsters.room_id = rooms.id` 连接怪物与房间，读取房间名和区域。
4. `LEFT JOIN / IS NULL`：保留左表怪物，用右表空值找出没有装备记录的目标。
5. `JOIN` 综合魔王：先连接房间后分组、`HAVING` 过滤并排序，再连接装备表找出最强核心。

第二层题目仍要求玩家自己写完整语句，并同时校验真实结果、当前知识锁与真实连接关系；`ON 1=1`
配合硬编码过滤不能绕过课程。第二层怪物血量按课程阶段数与确定武器伤害校准，不会要求无意义地
重复同一道题。

## 第三层学习路线

1. `INNER JOIN`：按已定义关系连接怪物和房间。
2. `LEFT JOIN`：保留全部目标，并找出缺少关联记录的数据。
3. 自连接：通过 `master_id` 连接怪物与主人记录。
4. 三表链路：依次连接怪物、房间和装备。
5. `UNION`：合并字段兼容的结果集，不能硬编码答案。
6. 连接审计魔王：连续完成两段连接与聚合综合题。

亡灵墓城会同时校验返回结果与连接形式，关系条件必须真实成立；本层确定性课程武器是骨刃。

## 第四层学习路线

1. 标量子查询。
2. `IN` 子查询。
3. `EXISTS`。
4. 相关子查询。
5. 使用 `WITH` 的公共表表达式。
6. 连续两阶段的递归 CTE 魔王。

元素熔炉只在对应阶段开放高级非平坦语法；每次答案仍必须是一条只读语句，本层确定性课程武器
是符文杖。

## 第五层学习路线

1. `OVER / PARTITION BY`：保留明细行，同时计算各军阵数量。
2. `ROW_NUMBER`：在要塞区域内生成稳定序号。
3. `RANK / DENSE_RANK`：处理相同装备 power 的并列排名。
4. `LAG / LEAD`：不做自连接也能读取前后装备值。
5. 显式 `ROWS` Frame：稳定计算累计装备 power。
6. CTE + 窗口 Top-N 城主：先分区排名，再由外层过滤。

黑铁要塞使用连续编号 `45–55`，拥有哥布林、兽人、骑士、巨魔和堡主生态遭遇，并确定提供黑铁斧。
窗口排序统一读取不会随战斗改变的 `monster_gear.power`，因此前一只怪物死亡变成 `hp = 0` 后，
不会污染后续题目的标准结果。

## 第六层学习路线

1. 指定列的 `INSERT`。
2. 带精确 `WHERE` 的 `UPDATE`。
3. 带精确 `WHERE` 的 `DELETE`。
4. `CHECK` 失败与 `INSERT OR IGNORE`。
5. `BEGIN / ROLLBACK`。
6. `SAVEPOINT / ROLLBACK TO / RELEASE / COMMIT`。

巨龙熔巢只允许操作 `repair_queue(id, item, quantity, status)`。策略层会拦截 DDL、永久课程表、
无条件更新/删除和超过八条语句的脚本；每次攻击都新建并销毁数据库副本。龙枪是本层确定课程武器。

```text
    │
GameSession ── 物理世界、篝火、安全区、演员、迷雾、战斗、掉落与档案的事实权威
  ├─ FloorContracts ── 可校验的八层课程与内容 Schema
  ├─ CampaignDomain ── 有序八层槽位与换层不变量
  ├─ RunGraph ── 课程依赖与兴趣点门锁
  ├─ FloorMapBlueprints ── 八层手工宏观轮廓与交通身份
  ├─ FloorLabyrinthContent/Domain ── F1–F8 入场边界、安全范围、视野与陷阱
  ├─ MazeGenerator/MazeFloor ── 48×36 / generator v5 种子物理地图
  ├─ MazeValidation ── 拓扑、可达性与存档不变量
  ├─ CampfireDomain ── 两座种子篝火、出生复活锚点与可见安全格掩码
  ├─ GuidedMap ── 路线信标、死路补给、保证钥匙与双向捷径
  ├─ BiomeDomain ── 派生生态区域、静态地貌与区域首领锚点
  ├─ EncounterDirector ── 确定性安全期与按步数伏击
  ├─ MonsterRoaming ── 确定性的缓慢巡逻决策
  ├─ LootDirector ── 独立恢复品候选与同场去重
  ├─ gateChallenges ── 可选 Boss 门查询特征与结果约束
  ├─ lessonEvaluator ── 结果语义 + 知识锁
  ├─ SqlSchemaCatalog ── 四表权威元数据与生成 DDL
  ├─ SqlAutocomplete ── 完整 Schema 补全与无障碍 Listbox 状态
  ├─ SqlEngine ── 只读查询与一次性写操作/事务沙箱
  ├─ NarrativeContent/Domain ── 每层五拍、证据、上升路线与 MIGRATE
  ├─ ActorVisuals/PixelActorFactory ── 地图/战斗同源程序化角色
  ├─ DungeonScene ── 连续探索、迷雾、碰撞、巡逻与抄写员
  ├─ BattleScene ── 独立对战与同源角色动画
  ├─ FeedbackDirector ── 探索通知与事件音频路由
  ├─ RecordedScorePlayer/ArcadeAudio ── F1/F2 连续母带 + 程序化降级/SFX
  ├─ NarrativeCodexView ── 本地《失名录》与迁移进度
  └─ OnboardingController ── 独立持久化的渐进引导
```

`FloorContracts` 定义八层课程与内容边界，`CampaignDomain` 序列化确定性的有序槽位并拒绝
跳层、重复激活与 Seed 重抽。`RunGraph` 是当前可执行八层的课程依赖图，不负责移动玩家；
`MazeFloor` 才是物理世界。发现式小地图只是只读的
探索视图，移动、同格遭遇、拾取与知识门都由 `GameSession` 对照迷宫进行判定。

新 Run 使用 generator v5 和八张 `48×36` 手工宏观蓝图；generator v4 的 `64×48` 地图只为
旧 Run 兼容继续读取。迷宫生成器隔离 `topology` 与 `decor` 两条随机流；`GuidedMap` 再从固定迷宫、课程图和篝火
确定性派生路线信标、死路补给与钥匙捷径。因此调整装饰密度不会改变课程、钥匙或捷径。Actor 与
固定课程宝箱从课程锚点确定性派生，可选掉落由生态与独立稳定 Hash 判定；生态计划从迷宫、
篝火、引导地图和 Seed 重建，不重复写进存档。当前仍未加入单独的内容版本字段。
八层迷宫内容同样只保存稳定意图；安全格、当前视野与陷阱坐标都从现有迷宫和 Seed 解析。
已触发陷阱复用 `openedGateIds`，入场确认由玩家位置、已探索格与已访问房间恢复，因此本功能
不增加存档字段，Run 格式继续保持 `v11`。

第一至五层及第七、八层终端每次只接受一条只读 `SELECT` 或 `WITH`，最多显示 50 行结果；第六层允许在
一次性 `repair_queue` 中执行 1–8 条受控语句。DDL、`PRAGMA`、`ATTACH`、永久课程表和无条件
更新/删除都会被拒绝。查询计划与查询负载是 SQLite 教学信号，不能当作 MySQL 优化器的真实证据。
第八层并发与分布式练习只读取确定性事故夹具，不声称是 SQLite 原生行为。

浏览器本地存储拆成：

  未处理战利品包、装备背包、防具/护甲、恢复品、唯一物品记录、关键物品、已发现迷雾格、
  两个篝火、出生锚点、当前复活点、生命、等级/经验、遭遇计量、遗物和战斗进度，还包括已打开的挑战门、
  捷径/死路补给状态、当前机关题和最多 200 次本地 SQL 作答记录。引导地图本身由 Seed 重建，
