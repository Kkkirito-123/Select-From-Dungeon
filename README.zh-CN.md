一个面向 SQL 初学者与面试复习者的浏览器肉鸽。SQL 就是战斗动作：探索由种子生成的像素魔王城，
实际走过连续迷宫，进入有名字怪物所在格后切换到独立对战，写出一条完整 SQLite 查询，再把
正确结果变成攻击动画。

## MVP 现在能玩什么

- 完成一个由四张 64×48 连续迷宫组成的 Run。每层在技术上分成十二块 16×16 区域，并用额外
  环路减少死路折返。第一层分成青石排水渠、软泥水池和余烬仓窖；第二层分成月影湖泊、
  毒雾泥沼和古树森林；第三层进入亡灵墓城；第四层进入由火、冰、雷构成的元素熔炉。每个区域
  都有独立色板、静态像素地貌与怪物池。
- 顶栏现在显示当前楼层槽位 `/ 08`。可校验的 Campaign 骨架已经定义八个稳定 Seed、课程先修、
  题阶、遭遇角色、主题和内容池；`v0.8` 真正可玩第一至四层，第五至八层仍是后续版本的数据
  契约，不用伪关卡冒充已经完成。
- 击败第一至三层魔王并拾取钥匙后，会显示金色
  `FLOOR NN CLEARED / CONGRATULATIONS!!` 约 1.5 秒并自动进入下一层，不需要再次寻路、
  按 `E` 或选择菜单。等级、XP、装备、背包、遗物和查询数跨层保留。
- 实际行走会揭开战争迷雾并让发现式小地图显形。小地图只记录已探索区域与课程门锁，不能点击，
  也不会传送玩家。
- 同一 Seed 会确定性生成课程路线信标、前中后三段篝火、死路补给和一条双向捷径。路线信标把
  主课程路上的可见兴趣点间隔控制在 18 格内；默认编织全部可修复死路，剩余死路都会放置一次性
  补给，不再只有空墙。捷径钥匙保证出现在中后段，不占背包，也不依赖怪物随机掉落；靠近钥匙、
  捷径门或补给按 `E` 交互。捷径只有在玩家先亲自走到钥匙处后才能永久开启，因此只能减少本 Run
  的重复折返，不能跳过必修 SQL。
- 移动进入存活必修怪物所在格，或触发按步数判定的伏击后，自动进入类似宝可梦的单体战斗。
  安全期结束后，安全区外每次符合条件的成功移动以 2% 基础概率判定；连续 30 个符合条件的
  安静步数后保底遭遇，刷新页面不能重抽。地图普通怪约每
  1,100 毫秒巡逻一步，魔王固定不动。每次查询前都能看到对手完整名字、ID、血量和下一次反击。
- 突发遭遇只从玩家脚下生态区的怪物池抽取。第一至四层小型精英权重依次为 5%、7%、9%、
  11%，怪物池从史莱姆、湖泊/泥沼/森林生物，逐步过渡到亡灵和火/冰/雷元素。已编写的地图可见
  区域首领使用符合本层的多阶段练习，奖励 3 XP 和至少两件生态战利品，但不阻塞课程与换层。
- 按 `Q + S` 或触控按钮打开游戏内终端。每个阶段都从空编辑器开始，玩家需要完整写出
  `SELECT ... FROM ...` 或 `WITH ... SELECT ...`，不是补最后一个空。
- 无需离开游戏即可使用内置 `PLAN ASSIST` 补全栈。输入前缀会排序提示 SQL 关键词、函数、
  四张权威表与全部 22 个字段，`m.` 等别名会把范围缩到对应表；支持方向键配合
  `Enter`/`Tab`、点击、触控，以及 `Ctrl/Command + Space` 主动唤起。接受建议不会执行查询，
  也不会填完整答案。
- 永久 `SCHEMA CODEX / 字段图鉴` 会展示字段名、类型、可空性、主键与逻辑 JOIN 关系，四个表
  标签均支持键盘操作；战斗与机关终端另有默认折叠的完整字段速查。`REF` 是教学关系，并不表示
  SQLite 已声明外键约束。
- 真实执行浏览器内 SQLite WASM，可查看结果表与 `EXPLAIN QUERY PLAN`。正确结果发动攻击；错误
  结果或语法错误触发已预告的怪物反击；空输入不消耗回合。
- 顶栏 `答题复盘` 会本地记录每次 SQL、对应参考答案、错误类型、提示等级和战斗结果，可分别
  查看最近一场战斗与当前楼层。记录最多保留 200 次 SQL 回合，不记录移动或按键，也不会上传。
- 每层会在前、中、后学习阶段生成三个稳定的实体篝火。篝火周围可见区域与本层出生区都是
  安全区，不会触发突发遭遇，巡逻怪也不能进入。站在火堆相邻格按 `E`，可以选择
  `在此休息` 或 `答案复盘`；休息恢复满生命，并把该篝火设为复活点。
- 死亡不再重置 Run。短暂显示 `YOU DIED` 后，玩家会满血返回最近休息的篝火；尚未休息时返回
  本层出生安全区，并自动打开导致死亡的本场复盘。课程、XP、装备、门、已击败怪物和存活敌人
  的剩余生命都会保留。
- 按 `B` 可在探索或篝火状态打开本轮构筑：12 格装备背包、一个武器位、一个防具位，以及
  三种恢复品堆叠（每种最多 5 个）。打开背包会暂停移动和怪物巡逻，战斗中不能换装。防具提供
  独立护甲生命，优先承受错误反击；篝火休息和复活都会修复当前防具。
- 站在任意一层的锁定 Boss 门旁按 `E`，可尝试可选高难 `QUERY BREACH` 机关。完成固定组合查询
  可以提前打开当前物理门，但不增加课程掌握、XP 或战利品；错误结果或语法错误造成 1 点伤害，
  并由护甲优先承受；空输入和安全退出没有代价。
- 每局以两颗心开始。击败普通、精英、魔王分别获得 1、3、5 经验；累计经验达到 2、4、6、8，
  此后每 4 XP 一档直到 24 时升级，每升一级增加一颗生命上限并恢复一颗心。战后结算卡会明确
  显示击败对象、XP 前后变化、等级进度和升级结果。
- 每次胜利都按“Run 种子 + 楼层 + 怪物 + 物品”逐项独立判定低概率候选，并在非空时留下一个
  可按 `E` 打开的战利品包；一个包最多三件非钥匙物品，同场不重复，刷新、休息和死亡不会重抽。
  普通怪大多数没有物品，精英至少一件，Boss 至少两件；钥匙另计。课程关键奖励仍是 `100%`
  确定项：`SELECT` 后可得过滤弓，`IS NULL` 后可得空值提灯，进入 `GROUP BY` 前必得聚合战锤；
  第二层继续提供雷序军刀与关系链刃，第三层提供骨刃，第四层提供符文杖；生态池还可能出现
  低概率武器、防具和恢复品。
  唯一装备再次命中会转换为恢复品；满背包必须显式替换，
  未处理物留在原包。普通装备和恢复品可丢在脚下并在换层前重新拾取，基础/课程保护物品和钥匙
  不能丢弃。物品说明卡和 XP 结算卡会在之后完成三次成功移动后消失。
- 运行时用 Web Audio 播放电子古典音乐：第一层随机轮换四首原创抒情曲式，第二层随机轮换三首
  由代码重新编排与合成的公版贝多芬芯片曲。战斗切换为原创激昂太空街机曲；不打包第三方录音，
  也不复制其他游戏旋律。移动、撞墙、遭遇、查询施法、命中、受伤、
  阶段完成、掉落、拾取、知识门开启、胜利与失败都有不同提示。项目不打包第三方音乐或音效素材。
- 可选的逐步新手引导会依次教移动、寻找怪物、打开终端、执行第一次查询和打开第一个战利品包；可
  跳过或重新教学，不会改变 SQL 熟练度。
- 当前迷宫、演员、地面物品、迷雾、三个篝火、复活点与战斗状态和永久学习档案分开保存。
  开始新 Run 会重置局内状态，但保留已掌握知识、练习次数、通关数和最佳查询数。
- 桌面支持 WASD/方向键，窄屏提供可见方向键和全屏 SQL 终端，可直接嵌入博客页面操作。

## 第一层学习路线

1. `SELECT / FROM`：先查询怪物 `#101` 的 `name`，再查询它的 `weakness`。
2. `WHERE / AND`：用房间和状态锁定水胶怪，再用屏幕上显示的怪物名字查询弱点。
3. `IS NULL`：找出没有主人的怪物 ID，再找出“无主人且被诅咒”的怪物名字。
4. `COUNT / GROUP BY`：把 `monster_id = 800` 的信号按 `channel` 分组，并把数量命名为 `total`。
5. `HAVING`：先用 `COUNT(*) >= 2` 过滤魔王 `#900` 的信号组，再把阈值提高到 `>= 3`，只留下
   最强核心。

`WHERE` 与 `IS NULL` 是自由顺序分支；两者掌握并领取固定聚合战锤后，才会解锁 `GROUP BY`。
种子可以改变物理迷宫和非关键奖励，但不会改变必修查询数据，也不会让关键武器随机缺失。课程
依赖图只负责知识门锁，不负责传送；已经解锁的区域以玩家实际探索顺序为准。

每个阶段都有入局说明、可见 Schema、知识锁和渐进提示。第一层语法范围是一条平坦 `SELECT`，
暂不允许 `OR`、子查询或集合运算；在这个范围内，判定同时检查“结果语义 + 当前 SQL 知识点”。
表别名和 `HAVING total ...` 可以通过，不要求照抄唯一字符串。

## 第二层学习路线

1. `ORDER BY / LIMIT`：先找出最高 `charge` 的信号，再按降序返回前两名。
2. `DISTINCT`：从重复镜像信号中只保留不同的 `channel`，并按名称排序。
3. `INNER JOIN / ON`：用 `monsters.room_id = rooms.id` 连接怪物与房间，读取房间名和区域。
4. `LEFT JOIN / IS NULL`：保留左表怪物，用右表空值找出没有装备记录的目标。
5. `JOIN` 综合魔王：先连接房间后分组、`HAVING` 过滤并排序，再连接装备表找出最强核心。

第二层题目仍要求玩家自己写完整语句，并同时校验真实结果、当前知识锁与真实连接关系；`ON 1=1`
配合硬编码过滤不能绕过课程。第二层怪物血量按课程阶段数与确定武器伤害校准，不会要求无意义地
重复同一道题。

## 第三层学习路线

1. `INNER JOIN`：按已定义关系连接怪物和房间。
2. `LEFT JOIN`：保留全部目标，并找出缺少关联记录的数据。
3. 自连接：通过 `master_id` 连接怪物与主人记录。
4. 三表链路：依次连接怪物、房间和装备。
5. `UNION`：合并字段兼容的结果集，不能硬编码答案。
6. 连接审计魔王：连续完成两段连接与聚合综合题。

亡灵墓城会同时校验返回结果与连接形式，关系条件必须真实成立；本层确定性课程武器是骨刃。

## 第四层学习路线

1. 标量子查询。
2. `IN` 子查询。
3. `EXISTS`。
4. 相关子查询。
5. 使用 `WITH` 的公共表表达式。
6. 连续两阶段的递归 CTE 魔王。

元素熔炉只在对应阶段开放高级非平坦语法；每次答案仍必须是一条只读语句，本层确定性课程武器
是符文杖。

## 本地运行

要求 Node.js `>=20.19` 与 pnpm `11.9.0`。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 Vite 输出的地址，通常是 `http://localhost:5173/`。不要通过 `file://` 直接打开
`index.html`，SQLite WASM 必须通过 HTTP 加载。

第一只怪物的两次攻击是：

```sql
SELECT name
FROM monsters
WHERE id = 101;

SELECT weakness
FROM monsters
WHERE id = 101;
```

从魔王城入口出发，跟随新手引导卡或青色信标实际走过迷宫。小地图只显示已经探索的位置，不能
点击移动。进入史莱姆所在格 → 按 `Q + S` → 完整输入查询 → `Ctrl/Cmd + Enter` 执行
攻击。怪物倒下后先查看 XP 结算，再靠近怪物原位置留下的战利品包并按 `E` 处理奖励。

## 架构与存档

```text
AppShell ── HUD、发现式小地图、新手引导、终端与查询证据
    │
GameSession ── 物理世界、篝火、安全区、演员、迷雾、战斗、掉落与档案的事实权威
  ├─ FloorContracts ── 可校验的八层课程与内容 Schema
  ├─ CampaignDomain ── 有序八层槽位与换层不变量
  ├─ RunGraph ── 课程依赖与兴趣点门锁
  ├─ MazeGenerator/MazeFloor ── 64×48 种子物理迷宫
  ├─ MazeValidation ── 拓扑、可达性与存档不变量
  ├─ CampfireDomain ── 三个稳定复活点与共享安全格掩码
  ├─ GuidedMap ── 路线信标、死路补给、保证钥匙与双向捷径
  ├─ BiomeDomain ── 派生生态区域、静态地貌与区域首领锚点
  ├─ EncounterDirector ── 确定性安全期与按步数伏击
  ├─ MonsterRoaming ── 确定性的缓慢巡逻决策
  ├─ LootDirector ── 独立候选、阶级保底、去重与三件上限
  ├─ gateChallenges ── 可选 Boss 门查询特征与结果约束
  ├─ lessonEvaluator ── 结果语义 + 知识锁
  ├─ SqlSchemaCatalog ── 四表权威元数据与生成 DDL
  ├─ SqlAutocomplete ── 完整 Schema 补全与无障碍 Listbox 状态
  ├─ SqlEngine ── 只读 SQLite WASM 执行与运行时同步
  ├─ DungeonScene ── 连续探索、迷雾、碰撞与巡逻
  ├─ BattleScene ── 独立对战呈现和攻击动画
  ├─ FeedbackDirector ── 探索通知与事件音频路由
  ├─ ArcadeAudio ── 随机探索音乐与原创战斗 Web Audio
  └─ OnboardingController ── 独立持久化的渐进引导
```

`FloorContracts` 定义未来八层课程与内容边界，`CampaignDomain` 序列化确定性的有序槽位并拒绝
跳层、重复激活与 Seed 重抽。`RunGraph` 仍是当前可执行四层的课程依赖图，不负责移动玩家；
`MazeFloor` 才是物理世界。发现式小地图只是只读的
探索视图，移动、同格遭遇、拾取与知识门都由 `GameSession` 对照迷宫进行判定。

迷宫生成器隔离 `topology` 与 `decor` 两条随机流；`GuidedMap` 再从固定迷宫、课程图和篝火
确定性派生路线信标、死路补给与钥匙捷径。因此调整装饰密度不会改变课程、钥匙或捷径。Actor 与
固定课程掉落从课程锚点确定性派生，可选掉落由生态与独立稳定 Hash 判定；生态计划从迷宫、
篝火、引导地图和 Seed 重建，不重复写进存档。当前仍未加入单独的内容版本字段。

终端只接受一条只读 `SELECT` 或 `WITH`，最多显示 50 行；拒绝 DML、DDL、`PRAGMA`、`ATTACH` 和多语句。
查询计划与 I/O 热量是 SQLite 教学信号，不能当作 MySQL 优化器的真实证据。

浏览器本地存储拆成：

- `select-from-dungeon:run:v9`：可丢弃的当前 Run，包括确定性的八层 Campaign 骨架、当前可执行
  楼层、生成迷宫、世界演员、地面物品、
  未处理战利品包、装备背包、防具/护甲、恢复品、唯一物品记录、关键物品、已发现迷雾格、
  三个篝火、当前复活点、生命、等级/经验、遭遇计量、遗物和战斗进度，还包括已打开的挑战门、
  捷径/死路补给状态、当前机关题和最多 200 次本地 SQL 作答记录。引导地图本身由 Seed 重建，
  不重复保存一份派生数据。
- `select-from-dungeon:profile:v2`：22 项已掌握课程、练习次数、通关数和最佳查询数。
- `select-from-dungeon:onboarding:v1`：可选引导是否已完成或跳过。

有效的 `run:v8` 会在内存中迁移为 v9 并补上确定性的八层槽位；有效的 `run:v7` 再补上空背包/
战利品状态并登记当前已装备物品；有效的 `run:v6`、`run:v5` 与 `run:v4` 会继续经过原有迁移
进入 v9。旧 Key 不会被删除。更早的
Run Key 不读取也不删除。
有效的 `profile:v1` 会自动迁移到 v2；升级前只含前十项课程的 v2 档案会补齐第三、四层计数。
`src/main.ts` 对快照持久化进行防抖，避免每次移动或巡逻状态变化都同步写入一次本地存储。

## 验证、构建与博客嵌入

```bash
pnpm test
pnpm build
python3 scripts/test_validate_rules.py
python3 scripts/validate-rules.py
```

`pnpm build` 会先执行 TypeScript 检查，再把静态网站输出到 `dist/`，并把根目录权威
`LICENSE` 与 `ATTRIBUTIONS.md` 自动复制进去；不要另外手工维护副本。把该目录部署到能正确
