一个面向 SQL 初学者与面试复习者的浏览器肉鸽。SQL 就是战斗动作：探索唯一固定的像素魔王城，
实际走过连续迷宫，进入只显示编号的怪物所在格后切换到独立对战，写出一条完整 SQLite 查询，再把
正确结果变成攻击动画。

## 第一层学习路线

1. `SELECT / FROM`：先查询怪物 `#1` 的 `weakness`，最后用 `name` 查询完成击杀并恢复身份。
2. `WHERE / AND`：用房间和状态锁定 ID `#2`，再同时使用 `id` 与 `status` 查询弱点。
3. `IS NULL`：找出没有主人的怪物 ID，再找出“无主人且被诅咒”的怪物名字。
4. `COUNT / GROUP BY`：把 `monster_id = 4` 的信号按 `channel` 分组，并把数量命名为 `total`。
5. `HAVING`：先用 `COUNT(*) >= 2` 过滤魔王 `#5` 的信号组，再把阈值提高到 `>= 3`，只留下
   最强核心。

`WHERE` 与 `IS NULL` 是自由顺序分支；两者掌握并领取固定聚合战锤后，才会解锁 `GROUP BY`。
种子可以改变物理迷宫和非关键奖励，但不会改变必修查询数据，也不会让关键武器随机缺失。课程
依赖图只负责知识门锁，不负责传送；已经解锁的区域以玩家实际探索顺序为准。

每个阶段都有入局说明、可见 Schema、知识锁和渐进提示。第一层语法范围是一条平坦 `SELECT`，
暂不允许 `OR`、子查询或集合运算；在这个范围内，判定同时检查“结果语义 + 当前 SQL 知识点”。
表别名和 `HAVING total ...` 可以通过，不要求照抄唯一字符串。

## 第二层学习路线

1. `ORDER BY / LIMIT`：先找出最高 `charge` 的信号，再按降序返回前两名。
2. `DISTINCT`：从重复镜像信号中只保留不同的 `channel`，并按名称排序。
3. `INNER JOIN / ON`：用 `monsters.room_id = rooms.id` 连接怪物与房间，读取房间名和区域。
4. `LEFT JOIN / IS NULL`：保留左表怪物，用右表空值找出没有装备记录的目标。
5. `JOIN` 综合魔王：先连接房间后分组、`HAVING` 过滤并排序，再连接装备表找出最强核心。

第二层题目仍要求玩家自己写完整语句，并同时校验真实结果、当前知识锁与真实连接关系；`ON 1=1`
配合硬编码过滤不能绕过课程。第二层怪物血量按课程阶段数与确定武器伤害校准，不会要求无意义地
重复同一道题。

## 第三层学习路线

1. `INNER JOIN`：按已定义关系连接怪物和房间。
2. `LEFT JOIN`：保留全部目标，并找出缺少关联记录的数据。
3. 自连接：通过 `master_id` 连接怪物与主人记录。
4. 三表链路：依次连接怪物、房间和装备。
5. `UNION`：合并字段兼容的结果集，不能硬编码答案。
6. 连接审计魔王：连续完成两段连接与聚合综合题。

亡灵墓城会同时校验返回结果与连接形式，关系条件必须真实成立；本层确定性课程武器是骨刃。

## 第四层学习路线

1. 标量子查询。
2. `IN` 子查询。
3. `EXISTS`。
4. 相关子查询。
5. 使用 `WITH` 的公共表表达式。
6. 连续两阶段的递归 CTE 魔王。

元素熔炉只在对应阶段开放高级非平坦语法；每次答案仍必须是一条只读语句，本层确定性课程武器
是符文杖。

## 第五层学习路线

1. `OVER / PARTITION BY`：保留明细行，同时计算各军阵数量。
2. `ROW_NUMBER`：在要塞区域内生成稳定序号。
3. `RANK / DENSE_RANK`：处理相同装备 power 的并列排名。
4. `LAG / LEAD`：不做自连接也能读取前后装备值。
5. 显式 `ROWS` Frame：稳定计算累计装备 power。
6. CTE + 窗口 Top-N 城主：先分区排名，再由外层过滤。

黑铁要塞使用连续编号 `45–55`，拥有哥布林、兽人、骑士、巨魔和堡主生态遭遇，并确定提供黑铁斧。
窗口排序统一读取不会随战斗改变的 `monster_gear.power`，因此前一只怪物死亡变成 `hp = 0` 后，
不会污染后续题目的标准结果。

## 第六层学习路线

1. 指定列的 `INSERT`。
2. 带精确 `WHERE` 的 `UPDATE`。
3. 带精确 `WHERE` 的 `DELETE`。
4. `CHECK` 失败与 `INSERT OR IGNORE`。
5. `BEGIN / ROLLBACK`。
6. `SAVEPOINT / ROLLBACK TO / RELEASE / COMMIT`。

巨龙熔巢只允许操作 `repair_queue(id, item, quantity, status)`。策略层会拦截 DDL、永久课程表、
无条件更新/删除和超过八条语句的脚本；每次攻击都新建并销毁数据库副本。龙枪是本层确定课程武器。

## 本地运行

要求 Node.js `>=20.19` 与 pnpm `11.9.0`。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 Vite 输出的地址，通常是 `http://localhost:5173/`。不要通过 `file://` 直接打开
`index.html`，SQLite WASM 必须通过 HTTP 加载。

需要按生产方式本地验收时，构建并通过 HTTP 预览 `dist/`：

```bash
pnpm build
pnpm preview
```

游戏默认使用确定性的本地 SQL 复盘和作者编写的抄写员文本。配置
  `VITE_CAMPFIRE_AGENT_URL` 后，可选 Python 3.11+ 篝火 Agent 通过无状态
`POST /v1/campfire/review` 只改善当前层复盘文案。配置 `VITE_SCRIBE_AGENT_URL` 后，抄写员端点可用于调查、
死亡复盘和导航指引，只接收作者文案和受限的场景证据。没有任一服务时游戏仍可完整运行，Agent 输出不会持久化。

顶栏 `⌘ 管理员` 只提供下一层初始位置入口，包含剧透的预览只存在内存中，不覆盖正式 Run
或永久怪物档案；战斗时自动填写当前题目的正确 SQL，刷新页面即退出预览并回到最后一次正式存档。

第一只怪物的两次攻击是：

```sql
SELECT weakness
FROM monsters
WHERE id = 1;

SELECT name
FROM monsters
WHERE id = 1;
```

从魔王城入口出发，跟随新手引导卡或青色信标实际走过迷宫。小地图只显示已经探索的位置，不能
点击移动。进入 `ID #001` 所在格 → 按 `Q + S` → 完整输入查询 → `Ctrl/Cmd + Enter` 执行
攻击。最后一击前只显示 ID；胜利时才恢复名字并写入永久图鉴。随后查看 XP 结算，再靠近怪物
原位置可能留下的战利品包并按 `E` 处理奖励。

`src/domain/learning/campfireReview.ts` 把当前楼层答案记录转换为篝火面板使用的确定性事实。
它不访问外部服务、不写入存档，也不修改游戏状态。`ScribeHook` 将当前场景投影为受限的学习、死亡或导航
证据；作者文案始终是本地回退，展示前仍执行现有的怪物身份脱敏。

`src/application/triggers/` 将快照变化转换为作答、靠近篝火、换层、死亡和导航等级提升事件，
`src/application/hooks/` 维护 `dirty / requesting / ready / fallback` 状态。新作答标记当前层脏数据，
玩家进入篝火两格圆形范围后才允许为这份证据发起一次请求；`ScribeHook` 在调查实体抄写员、死亡和导航指引
等级提升时响应。`src/infrastructure/agent/CampfireAgentClient.ts` 与 `ScribeAgentClient.ts` 只发送各自的
受限投影，按证据 Hash 在内存中缓存，并且只接受请求 ID 与 Hash 都匹配的回复。`agent/` 目录负责 Python
契约、篝火复盘与抄写员流程和 HTTP 服务；默认无状态，可显式启用只保存触发元数据与合法输出的 Agent 专用
SQLite，不保存游戏数据库、原始 SQL 或完整快照。

`FloorContracts` 定义八层课程与内容边界，`CampaignDomain` 序列化确定性的有序槽位并拒绝
跳层与重复激活。`RunGraph` 是当前可执行八层的课程依赖图，不负责移动玩家；
`MazeFloor` 才是物理世界。发现式小地图只是只读的
探索视图，移动、同格遭遇、拾取与知识门都由 `GameSession` 对照迷宫进行判定。

新 Run 使用唯一一套 generator v7，把八张手工宏观蓝图分散到 `56×42` 紧凑迷宫；玩家不能输入
Seed 或重抽地图。generator v6 `96×72`、
generator v5 `48×36` 与 generator v4 `64×48` 地图只为旧 Run 兼容继续读取。迷宫生成器隔离 `topology` 与 `decor` 两条随机流；`GuidedMap` 再从固定迷宫、课程图和篝火
确定性派生路线信标、死路补给与钥匙捷径。因此调整装饰密度不会改变课程、钥匙或捷径。Actor 与
固定课程宝箱从课程锚点确定性派生，可选掉落由生态与独立稳定 Hash 判定；生态计划从迷宫、
篝火、引导地图和 Seed 重建，不重复写进存档。
八层迷宫内容同样只保存稳定意图；安全格、当前视野与陷阱坐标都从唯一地图解析。
已触发陷阱复用 `openedGateIds`；直接穿过开放房间边界不增加独立存档字段。Run v12 记录题库版本、
确定性牌组、随机练习首次奖励和导航计数。

只读 `public/data/question-bank-v2.sqlite` 由课程源生成，共 960 题：每层 L1 64 道、L2 40 道、
L3 16 道；第二至八层 L1 包含 40 道本层题与 24 道复习题，L2/L3 都是本层题。固定课程怪和
层主继续使用作者题；每层 15 个题族各有 8 道基于真实数据参数、可执行且保存精确结果证据的变体，
普通怪、小精英、区域首领分别抽 1 道 L1、2 道 L2、3 道 L3。加载前通过 Manifest 校验版本、字节数、总数与 SHA-256；新题库
版本只在新 Run 生效。

第一至五层及第七、八层终端每次只接受一条只读 `SELECT` 或 `WITH`，最多显示 50 行结果；第六层允许在
一次性 `repair_queue` 中执行 1–8 条受控语句。DDL、`PRAGMA`、`ATTACH`、永久课程表和无条件
更新/删除都会被拒绝。查询计划与查询负载是 SQLite 教学信号，不能当作 MySQL 优化器的真实证据。
第八层并发与分布式练习只读取确定性事故夹具，不声称是 SQLite 原生行为。

浏览器本地存储拆成：

- `select-from-dungeon:run:v12`：可丢弃的当前 Run，包括确定性的八层 Campaign、当前可执行
  楼层、生成迷宫、世界演员、地面物品、
  未处理战利品包、装备背包、防具/护甲、恢复品、唯一物品记录、关键物品、已发现迷雾格、
  两个篝火、出生锚点、当前复活点、生命、等级/经验、遭遇计量、遗物和战斗进度，还包括已打开的挑战门、
  捷径/死路补给状态、当前机关题、最多 200 次本地 SQL 作答、题库牌组、随机练习首次奖励与
  导航计数。引导地图本身由 Seed 重建，
  不重复保存一份派生数据。
- `select-from-dungeon:profile:v3`：47 项已掌握课程、已回收怪物编号、练习次数、通关数和最佳查询数。
- `select-from-dungeon:onboarding:v1`：可选引导是否已完成或跳过。
- 篝火与抄写员 Agent 输出在浏览器中只存在当前页面内存，不写入 Run、Profile 或 IndexedDB；Python 服务默认无状态，
  显式启用时只保存 Agent 专用触发元数据与合法输出，不保存游戏数据库或原始 SQL。
- IndexedDB `select-from-dungeon-learning`：最多 5000 条完整作答与永久题目/课程聚合，支持 JSON
  导出和显式清除。
- IndexedDB `select-from-dungeon-content`：已校验的版本化题库字节，保证进行中的 Run 固定题库版本。

有效的 `run:v11` 会在内存中无损迁移为 v12；有效的 `run:v10` 到 `run:v4` 会继续经过原有迁移
链进入 v12。旧 Key 不会被删除。更早的
Run Key 不读取也不删除。
有效的 `profile:v1` 与 `profile:v2` 会自动迁移到 v3；原学习计数保持，缺失身份记录从空集合开始。
`src/infrastructure/storage/progressPersistence.ts` 会合并非关键移动与巡逻快照；查询、战利品、背包、模式和
拓扑变化仍立即落盘。

SQL 执行和复盘证据继续留在浏览器本地 SQLite、Run/Profile 与 IndexedDB 边界内。明确配置后，
可选 Agent 只接收当前层投影，不是游戏状态来源。
